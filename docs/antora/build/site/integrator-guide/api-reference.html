Organization & Access Control

Organizational model endpoints for group hierarchy, project catalog, membership management, visibility, and access policies. The canonical REST contract is defined in ADR-DES.API.organization-rest-endpoints — see that ADR for the full endpoint list, RBAC rules, and audit semantics.

Projects

Projects follow the 1:1 Project ↔ Ontology model: creating a Project atomically creates its paired Ontology (response includes ontology_id); deleting a Project cascades to the paired Ontology. Members, visibility, and policies live on the Project.

Method Path Description

GET

/api/v1/projects

List projects (paginated, searchable)

POST

/api/v1/projects

Create a project (Owner, idempotent; atomically creates paired Ontology)

GET

/api/v1/projects/{id}

Get project details (includes ontology_id for the 1:1 paired Ontology)

PUT

/api/v1/projects/{id}

Update project (Owner, idempotent)

DELETE

/api/v1/projects/{id}

Delete project (Owner, idempotent; cascades to paired Ontology)

PUT

/api/v1/projects/{id}/move

Move project to another group (Owner, idempotent)

Access Policies

ABAC policies live on Project.

Method Path Description

GET

/api/v1/projects/{id}/policies

List ABAC policies

POST

/api/v1/projects/{id}/policies

Create policy (Owner, idempotent)

DELETE

/api/v1/projects/{id}/policies/{policyId}

Delete policy (Owner, idempotent)

Role values: Guest, Reporter, Developer, Maintainer, Owner. Legacy Viewer/Editor aliases accepted for backward compatibility.

Visibility values: private, internal, public. Private requires explicit membership; internal allows any authenticated org member; public allows anonymous read access.

Write endpoints support Idempotency-Key header (UUID). Membership endpoints require it (400 if missing).

GraphQL

The frontend uses Apollo Client to query the API Gateway’s GraphQL endpoint for complex data operations:

query GetOntology($id: ID!) {
  ontology(id: $id) {
    id
    name
    description
    classes {
      id
      label
      properties { name type }
    }
    relationships {
      from
      to
      type
    }
  }
}

Security

  • BOLA/BFLA enforcement at the API Gateway level — object-level and function-level authorization checks prevent unauthorized access.

  • Negative authorization tests are part of the test suite (tests/security/).

  • SAST/DAST security gates run in CI alongside dependency scanning.

See Authentication for token flow and identity providers.
