Quick Start

cd <project-root> && make docker-up
# Builds all images and starts containers — one command

Open http://localhost:3000 — the frontend is ready. The API Gateway is at http://localhost:8080.

The first make docker-up builds all images from source — can take 20–40 minutes.

Build Images Only

Use make docker-build when you want images without starting containers (CI, registry push, pre-building):

make docker-build                 # All service images
make docker-build-rust            # Rust: ontology, versioning, publisher, public-browse
make docker-build-go              # Go: api-gateway, auth, commenting, tickets, AI
make docker-build-python          # Python: metrics, classifier, document-extractor
make docker-build-typescript      # TypeScript: frontend, publish-browse-ui
make docker-build-api-gateway     # Single service via compose

Images are tagged vedo-core/<service>:latest.

Go services require a vendor/ directory. Run make vendor-go to populate it. Services without vendor/ are skipped.

Docker Compose Selection

Scenario Compose File Key Difference

Development

deploy/docker-compose.yml

Uses Keycloak JWKS for auth validation

E2E Testing

deploy/docker-compose.test.yml

Uses JWT_DEV_PUBLIC_KEY_PEM for self-signed test tokens

CI Pipeline

deploy/docker-compose.test.yml

Same as E2E — self-signed tokens match CI test JWTs

The test compose file extends the main compose via include and sets JWT_DEV_PUBLIC_KEY_PEM on the API Gateway, which takes highest priority in the auth resolution chain. The webServer.url in Playwright configs uses port 3000 (frontend nginx proxy), not port 8080 (API Gateway direct).

Raw Docker Compose

# Dev
docker compose --env-file config/.env.dev -f deploy/docker-compose.yml up -d

# Test
docker compose --env-file config/.env.test -f deploy/docker-compose.yml up -d

# Staging
docker compose --env-file config/.env.staging -f deploy/docker-compose.yml up -d

Each env file defines separate host ports while keeping container ports identical — inter-service communication always works through the Docker network.

Infrastructure Only

Start only the backing services without the application stack — useful for local native development:

make infra-up     # Neo4j, Postgres, Redis, RabbitMQ, Keycloak, MinIO
make infra-down   # Stop infrastructure

Container Management

make docker-status        # Health table (Name, Health, Ports)
make docker-status-full   # Full machine-readable JSON
make docker-logs          # Tail logs from all services
make docker-shell SVC=<name>  # Open shell in a service container
make docker-config        # Validate compose configuration
