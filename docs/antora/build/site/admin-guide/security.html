BOLA / BFLA Enforcement

The API Gateway enforces two layers of authorization:

  • BOLA (Broken Object-Level Authorization) — every request is checked to ensure the authenticated user has access to the specific resource (ontology, group, merge request) they are requesting.

  • BFLA (Broken Function-Level Authorization) — every endpoint is checked to ensure the user’s role permits the requested operation.

Negative authorization tests in tests/security/ verify that unauthorized access is properly rejected.

OWASP Top 10 Compliance

VEDO Core follows OWASP Top 10 mitigation practices:

Risk Mitigation

Injection

Parameterized queries (Neo4j Cypher, PostgreSQL), input validation at gateway

Broken Authentication

Keycloak OIDC/OAuth2 with JWT validation

Sensitive Data Exposure

TLS in production, secrets via environment variables

XXE

No XML external entity processing

Broken Access Control

BOLA/BFLA enforcement at API Gateway

Security Misconfiguration

Docker multi-stage builds, minimal base images

XSS

Vue 3 auto-escaping, CSP headers

Insecure Deserialization

Type-safe parsers, no untrusted deserialization

Known Vulnerabilities

Dependency scanning in CI

Insufficient Logging

Structured JSON logs with trace_id on all services
