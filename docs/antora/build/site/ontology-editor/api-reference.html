The VEDO Core REST API provides programmatic access to all ontology operations, query endpoints, and versioning functionality. The full OpenAPI 3.1 specification is available at GET /api/v1/openapi.json.

Base URL

All API endpoints are prefixed with /api/v1:

https://your-vedo-instance.com/api/v1

Authentication

Most endpoints require authentication via JWT bearer token:

GET /api/v1/ontologies
Authorization: Bearer <your-jwt-token>

Public endpoints (health, public ontology views) do not require authentication.

Getting a Token

Obtain a JWT token through the login endpoint:

POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "your-username",
  "password": "your-password"
}

Response:

{
  "access_token": "eyJhbGciOiJSUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 3600
}

Standard Response Format

Success

{
  "data": { ... },
  "meta": {
    "page": 0,
    "per_page": 20,
    "total": 42,
    "total_pages": 3
  }
}

Error

{
  "error": {
    "code": "ONT-CLASS-NOT-FOUND",
    "message": "Class not found: UnknownClass"
  }
}

Error codes are domain-prefixed: * ONT- — Ontology service errors * VER- — Versioning service errors * GATEWAY- — API Gateway errors * AUTH- — Authentication errors

Content-Type: application/json

{
  "id": "hasEmployee",

Query Endpoints

SPARQL

POST /api/v1/sparql
Content-Type: application/json

{
  "query": "SELECT ?s ?p ?o WHERE { ?s ?p ?o } LIMIT 10"
}

Read-only only — mutation queries (INSERT/DELETE) are rejected.

CYPHER

POST /api/v1/cypher
Content-Type: application/json

{
  "query": "MATCH (n) RETURN n LIMIT 10"
}

Read-only only — mutation queries (CREATE/DELETE) are rejected.

Rate Limiting

Query endpoints (SPARQL/CYPHER) have per-tier rate limits:

Tier

Limit

Anonymous

10 requests/minute

Free

100 requests/minute

Pro

500 requests/minute

Enterprise

1000 requests/minute

When rate limit is exceeded, the API returns 429 Too Many Requests with a Retry-After header.
