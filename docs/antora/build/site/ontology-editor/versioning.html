VEDO Core includes a Git-like versioning engine that tracks all changes to ontologies. Every modification is recorded as a delta, enabling full history, branches, and rollback.

Concepts

Commits

A commit captures the state of an ontology at a point in time. Each commit contains: * A message describing the change * The author (user who made the change) * A delta — the difference from the previous state * A timestamp

Deltas are stored in JSONB format in PostgreSQL:

{
  "added_triples": [
    {"s": "Person", "p": "rdfs:subClassOf", "o": "owl:Thing"}
  ],
  "removed_triples": [],
  "modified_triples": []
}

Branches

Branches allow parallel development: * Each ontology has a default branch (main) * Create branches for experimental changes * Switch between branches to work on different features * Merge branches when work is complete

Materialized State

The current state of each branch is materialized in Neo4j for fast queries. When you switch branches, the versioning service replays deltas to compute the new materialized state.

Making Commits

  1. Make changes to the ontology (add classes, properties, individuals).

  2. Click the Commit button in the toolbar.

  3. Enter a descriptive commit message.

  4. Click Commit.

The commit is created and the workspace shows as clean.

Viewing Commit History

  1. Navigate to the Versioning tab.

  2. Select Commits to see the history.

  3. Each commit shows: message, author, timestamp, branch.

  4. Click a commit to see its full details.

Creating Branches

  1. In the Versioning tab, select Branches.

  2. Click New Branch.

  3. Enter a branch name (e.g., feature/new-property).

  4. Select the source branch.

  5. Click Create.

You are now on the new branch. Changes made here won’t affect other branches.

Switching Branches

  1. In the Versioning tab, select Branches.

  2. Find the branch you want to switch to.

  3. Click Switch.

  4. The workspace loads the materialized state of that branch.

Merging Branches

  1. Switch to the target branch (e.g., main).

  2. Click Merge.

  3. Select the source branch to merge from.

  4. If there are conflicts:

    • Conflicts are resolved automatically with source preference

    • A merge commit is created with two parent commits

  5. The merged state is available immediately.

Rolling Back

To revert to a previous state:

  1. View the commit history.

  2. Find the commit you want to roll back to.

  3. Click Rollback.

  4. Confirm the rollback.

  5. An inverse delta commit is created, restoring the state.
