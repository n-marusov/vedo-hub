== Инфраструктура

=== Kubernetes (K8s)
[#k8s]
Платформа оркестрации контейнеров. VEDO Core развёртывается в Kubernetes для production-сред. Используются Deployment, StatefulSet, Service, Ingress, ConfigMap, Secret.

=== Docker
[#docker]
Система контейнеризации. Используется для локальной разработки и тестирования через Docker Compose.

=== Helm Chart
[#helmChart]
Пакетный менеджер Kubernetes. VEDO Core поставляется в виде Helm-чарта для настройки и развёртывания в K8s. Чарт включает все сервисы, БД, network policies, ingress.

=== Docker Compose
[#dockerCompose]
Инструмент для запуска многоконтейнерных приложений. Используется для локального развёртывания VEDO Core на одной машине.

=== Air-gapped Deployment
[#airgapped]
Изолированное развёртывание без доступа к внешним реестрам образов и Internet. Все артефакты доставляются через `vedo-cli airgap prepare`.

== Хранилища данных

=== Neo4j
[#neo4j]
Графовая СУБД, используемая как primary Triple Store для рабочей онтологии (TBox + ABox). В production: 3 core + 2 read replica.

=== PostgreSQL
[#postgresql]
Реляционная СУБД. Используется как Version Store (коммиты, ветки, дельты в JSONB). Отдельные инстансы для Support DB, Commenting DB, Ticket DB.

=== Redis
[#redis]
In-memory data store. Используется для кэширования запросов, блокировок, Pub/Sub для WebSocket и сессий.

=== MinIO
[#minio]
S3-совместимое объектное хранилище. Используется как хранилище реплик (WAL, снапшоты) и для immutable backup с WORM (Object Lock).

=== Object Storage / S3
[#s3]
Стандарт объектного хранения. VEDO Core использует S3-совместимые хранилища (MinIO, AWS S3, Yandex Object Storage) для backup и реплик.

=== WORM (Write Once Read Many)
[#worm]
Режим неизменяемого хранения данных. Реализуется через Object Lock в S3/MinIO. Используется для compliance-копий backup, исключающих перезапись и удаление до истечения срока.

== Резервное копирование и восстановление

=== 3-2-1 Backup Strategy
[#threeTwoOne]
Стратегия резервного копирования: 3 копии данных, 2 разных носителя, 1 копия off-site. VEDO Core реализует эту стратегию через комбинацию локального S3, WORM-хранилища и off-site реплики.

=== RTO (Recovery Time Objective)
[#rto]
Целевое время восстановления после сбоя. Для VEDO Core: standard restore — 4 часа, fast rollback — 60 минут.

=== RPO (Recovery Point Objective)
[#rpo]
Допустимая потеря данных с момента последней резервной копии. Для VEDO Core: 15 минут для активных данных (WAL), 24 часа для cold archive.

=== Immutable Backup
[#immutableBackup]
Резервная копия, защищённая от изменений и удаления до истечения срока хранения. Реализуется через WORM/Object Lock.

=== PITR (Point-in-Time Recovery)
[#pitr]
Восстановление на момент времени. Доступно через комбинацию полного backup + WAL для PostgreSQL и Neo4j.

=== Backup Retention
[#backupRetention]
Политика хранения резервных копий. SaaS: 90 дней active + 1 год archive. On-Premise: по контракту.

=== Secure Erase
[#secureErase]
Безвозвратное удаление данных с гарантией невозможности восстановления. Используется при decommission тенанта.

=== Audit Cold Archive
[#auditColdArchive]
Долговременное хранение аудитных логов в WORM-хранилище. Срок хранения определяется юрисдикцией.

== Мониторинг и наблюдаемость

=== Prometheus
[#prometheus]
Система сбора метрик. VEDO Core экспортирует метрики RED-метода для всех сервисов.

=== Grafana
[#grafana]
Платформа визуализации метрик. Используются дашборды для мониторинга состояния каждого сервиса.

=== OpenTelemetry
[#opentelemetry]
Стандарт сбора телеметрии (трейсы, метрики, логи). VEDO Core использует OTel SDK для инструментации всех сервисов.

=== Tempo
[#tempo]
Распределённая трассировочная система. Используется для поиска трейсов по trace_id при диагностике инцидентов.

=== Loki
[#loki]
Система агрегации логов. Используется для централизованного сбора и поиска логов всех сервисов.

=== RED Method
[#redMethod]
Метод мониторинга: Rate (частота запросов), Errors (ошибки), Duration (длительность). Применяется для всех сервисов VEDO Core.

=== SLI / SLO / SLA
[#sliSloSla]
* **SLI** — измеримые индикаторы качества (p95 latency, availability)
* **SLO** — целевые значения SLI
* **SLA** — юридические обязательства перед клиентом

=== Error Budget
[#errorBudget]
Допустимое отклонение от SLO. Определяет скорость внедрения изменений: при исчерпании бюджета изменения замораживаются.

=== P0/P1/P2/P3
[#incidentPriorities]
Уровни критичности инцидентов:
* **P0** — полная недоступность сервиса
* **P1** — деградация производительности, частичная недоступность
* **P2** — некритичные сбои
* **P3** — косметические проблемы

=== Alert Fatigue
[#alertFatigue]
Усталость от алертов — состояние, при котором операторы перестают реагировать на предупреждения из-за их избыточности.

== Безопасность и управление доступом

=== Keycloak
[#keycloak]
Identity Provider VEDO Core. Обеспечивает аутентификацию, SSO, управление пользователями, MFA (TOTP), service accounts.

=== RBAC (Role-Based Access Control)
[#rbac]
Модель управления доступом на основе ролей. В VEDO Core: Owner, Maintainer, Admin, Support Engineer, Viewer.

=== JWT (JSON Web Token)
[#jwt]
Токен доступа. VEDO Core использует JWT (RS256, TTL 15 минут) для аутентификации запросов.

=== OAuth2 / OIDC
[#oauth2Oidc]
Протоколы авторизации и аутентификации. VEDO Core использует OAuth2 + OpenID Connect через Keycloak.

=== BYOL (Bring Your Own License)
[#byol]
Модель, при которой клиент предоставляет собственные лицензии на стороннее ПО (ОС, БД).

=== Emergency Access / Break-glass
[#breakGlass]
Процедура экстренного доступа при недоступности Keycloak. Использует L1 Emergency Admin с Shamir Secret Sharing (M из N).

=== TOTP (Time-based One-Time Password)
[#totp]
Одноразовый пароль на основе времени. Используется как второй фактор MFA для операций категорий A/B/C.

=== Service Account
[#serviceAccount]
Учётная запись для автоматизации (CI/CD). Использует client_credentials grant, MFA не требуется.

=== Shamir Secret Sharing
[#shamir]
Схема разделения секрета: пароль L1 Emergency Admin разделяется на M частей; доступ возможен только при сборе N из M частей.

=== Compliance Evidence
[#complianceEvidence]
Документы, подтверждающие соответствие требованиям: DPA, SOC2, ISO 27001. Загружаются и хранятся в WORM-хранилище.

=== BOLA / BFLA / IDOR
[#bolaBflaIdor]
Уязвимости авторизации:
* **BOLA** — Broken Object Level Authorization
* **BFLA** — Broken Function Level Authorization
* **IDOR** — Insecure Direct Object Reference

=== SAST / DAST
[#sastDast]
* **SAST** — статический анализ кода на уязвимости
* **DAST** — динамический анализ запущенного приложения

=== SCA (Software Composition Analysis)
[#sca]
Анализ состава зависимостей на уязвимости. VEDO Core использует `vedo-cli sca scan` для автоматического SCA-сканирования.

=== SBOM (Software Bill of Materials)
[#sbom]
Спецификация состава ПО (SPDX 2.3 / CycloneDX 1.5). Генерируется через `vedo-cli sca sbom generate`.

=== CVE (Common Vulnerabilities and Exposures)
[#cve]
Идентификаторы известных уязвимостей. Проверяются через SCA-сканирование и advisory databases.

=== Advisory Database
[#advisoryDatabase]
База данных уязвимостей (RustSec, Go VulnDB, PyPA, npm, NVD, Trivy). Используется для offline-сканирования в air-gapped среде.

=== ROPG (Resource Owner Password Grant)
[#ropg]
OAuth2 grant type для аутентификации с логином/паролем. Используется vedo-cli для интерактивного входа.

== Модели развёртывания

=== SaaS (Software as a Service)
[#saas]
Облачное развёртывание VEDO Core на инфраструктуре провайдера.

=== On-premise
[#onPremise]
Развёртывание VEDO Core на инфраструктуре клиента.

=== Multi-tenant
[#multiTenant]
Архитектура, при которой один экземпляр VEDO Core обслуживает несколько тенантов с изоляцией данных.

=== Multi-AZ
[#multiAz]
Развёртывание в нескольких зонах доступности для отказоустойчивости.

=== Rolling Update
[#rollingUpdate]
Стратегия обновления Kubernetes без downtime: поды заменяются постепенно.

=== Blue-Green Deployment
[#blueGreen]
Методика развёртывания с двумя идентичными средами (blue и green) для минимизации downtime при переключении трафика.

=== Canary Release
[#canaryRelease]
Постепенное обновление: новая версия сначала получает малый % трафика.

=== CAPEX / OPEX
[#capexOpex]
* **CAPEX** — капитальные затраты (оборудование, лицензии)
* **OPEX** — операционные затраты (подписки, поддержка)

== Платформа VEDO Core

=== VEDO Core
[#vedoCore]
Веб-платформа для многопользовательского редактирования онтологий с Git-подобным версионированием. Включает микросервисы: Ontology Service, Versioning Service, Auth Service, API Gateway, Metrics Service, Publisher Service, Ticket Management и CLI-утилиту.

=== vedo-cli
[#vedoCli]
Единая административная утилита командной строки. Выполняет backup/restore, диагностику, emergency-операции, управление тикетами, Merge Request'ами и многое другое.

=== Ontology Service
[#ontologyService]
Микросервис на Rust для CRUD-операций над графом онтологии (TBox + ABox), импорта/экспорта, валидации OWL 2 DL.

=== Versioning Service
[#versioningService]
Микросервис на Rust с Git-подобным версионированием: коммиты, ветки, слияния (3-way merge), Merge Requests.

=== Auth Service
[#authService]
Микросервис на Go для аутентификации (JWT, OAuth2) через Keycloak.

=== API Gateway
[#apiGateway]
Единая точка входа на Go: маршрутизация, JWT-валидация, rate limiting, кэширование.

=== Metrics Service
[#metricsService]
Микросервис на Python для сбора метрик по RED-методу.

=== Support DB
[#supportDb]
Отдельный кластер PostgreSQL для support metadata, tenant info, break-glass audit, escalation matrix.

=== GPDR / 152-ФЗ
[#gdpr152fz]
Регуляторные требования к обработке персональных данных. VEDO Core поддерживает compliance через audit-логи, право на забвение, purge тенантов.

=== Feature Flags
[#featureFlags]
Механизм включения/отключения функций без переразвёртывания.

=== Graceful Degradation
[#gracefulDegradation]
Способность системы сохранять частичную функциональность при отказе отдельных компонентов.

=== Circuit Breaker
[#circuitBreaker]
Паттерн предотвращения каскадных сбоев: при превышении порога ошибок вызовы блокируются, системе даётся время на восстановление.

=== Kill Switch
[#killSwitch]
Аварийный перевод системы в режим «только чтение» через `vedo-cli emergency readonly`.

=== Helm Chart
[#helmChart1]
Пакет Kubernetes для развёртывания VEDO Core. Включает чарты для всех сервисов и зависимостей.

=== Feature Matrix
[#featureMatrix]
Сравнение возможностей локального и production-развёртывания (Neo4j cluster, PostgreSQL replication, Redis cluster и т.д.).

=== Job Functions / Roles in Vedocli
[#guardrailsG1G4]
Система guardrails для разрушительных операций:
* **G1** — typed confirmation
* **G2** — env guard + confirmation
* **G3** — MFA + env guard + confirmation
* **G4** — cool-down delay + full backup verification + всё из G3

== SLA и Recovery

=== Maintenance Window
[#maintenanceWindow]
Согласованное время проведения плановых работ, в течение которого возможно недоступность сервиса.

=== GitOps
[#gitops]
Методология управления инфраструктурой через Git-репозиторий как источник истины.

=== CI/CD
[#cicd]
Continuous Integration / Continuous Deployment. VEDO Core использует CI/CD для тестирования и развёртывания.

=== WAL (Write-Ahead Logging)
[#wal]
Журнал предзаписи. Используется PostgreSQL и Neo4j для обеспечения надёжности и PITR.

=== Rollback
[#rollback]
Откат изменений до предыдущего стабильного состояния.

=== Environment Guard
[#environmentGuard]
Защита от случайного выполнения разрушительных операций на production-среде.

=== Runbook
[#runbook]
Эксплуатационная инструкция — документированная процедура выполнения операций.

=== Incident Commander
[#incidentCommander]
Роль руководителя инцидента — лицо, координирующее работы по восстановлению сервиса.

=== Escalation Matrix
[#escalationMatrix]
Матрица эскалации — описание цепочек оповещения для разных уровней инцидентов.

=== Cooling-off Period
[#coolingOffPeriod]
Период «охлаждения» перед выполнением разрушительной операции (G4). Используется для tenant purge и decommission.

=== Drill
[#drill]
Учебная тренировка — проверка процедур восстановления без воздействия на production.

=== Geo-репликация
[#geoReplication]
Репликация данных между географически распределёнными центрами обработки данных.

=== Failover
[#failover]
Переключение на резервный компонент при отказе основного.
