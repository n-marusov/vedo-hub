== Введение

Политики безопасности VEDO Core охватывают аутентификацию, авторизацию, управление привилегированным доступом и безопасность цепочки поставок.

== Предварительные требования

* Доступ к Keycloak для настройки Identity Provider
* Права администратора безопасности

== Аутентификация

* JWT (RS256, 15m TTL) через Auth Service
* Refresh tokens (7d TTL)
* OAuth2/OIDC через Keycloak
* MFA (TOTP) для критических операций

Поддерживаемые OAuth-провайдеры: Keycloak, ЕСИА/Госуслуги, Яндекс, VK, Google.

== Авторизация (RBAC)

GitLab-подобная модель организации:

* Group — контейнер для команд и вложенных групп
* Ontology — базовая единица доступа и версионирования
* Membership наследуется по иерархии

Роли:

| Роль | Разрешения |
|------|-----------|
| Viewer | Чтение онтологии, комментариев |
| Editor | CRUD классов, свойств, индивидов, коммиты |
| Maintainer | Merge Request, protected branches, approval |
| Owner | Управление членством, назначение ролей, передача владения |

== MFA для критических операций

MFA (TOTP) требуется для:

* Создание/восстановление backup
* Применение миграций
* Kill/readonly emergency режим
* Decommission tenant
* Управление MFA-статусом других пользователей

== Break-glass доступ

Процедура экстренного доступа для ситуаций, когда штатная аутентификация недоступна:

. Запрос через поддержку с подтверждением инцидента.
. Выдача временного emergency-токена (TTL ≤ 60 минут).
. Аудит всех действий с уведомлением security-команды.
. Автоматическая ротация скомпрометированных секретов после инцидента.

== Supply chain безопасность

* Проверка уязвимостей зависимостей в CI
* Подпись Docker-образов
* SBoM (Software Bill of Materials) для каждой сборки
* Fuzz-тесты для парсеров и SPARQL-запросов
