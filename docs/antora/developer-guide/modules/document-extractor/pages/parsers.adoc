= Parser Design and Extension Guide
:description: How the Document Extractor parsers work and how to add new ones.

== Parser Architecture

Each file format is handled by a dedicated parser module in the `parsers/` directory. All parsers implement a common interface:

....
class BaseParser:
    def parse(self, content: bytes, filename: str) -> ParsedDocument:
        ...
....

The `ParsedDocument` type contains:

* `title` — document title extracted from filename or metadata
* `content` — plain text content extracted from the document
* `metadata` — format-specific metadata (e.g., author, page count)
* `sections` — optional hierarchy of sections with headings

== Available Parsers

=== Text Parsers (MD, TXT)

* `text_parser.py` — Handles Markdown and plain text files
* Markdown headings (`#`, `##`, etc.) are converted to section hierarchy
* Code blocks, tables, and lists are preserved in the extracted content

=== PDF Parser

* `pdf_parser.py` — Uses PyPDF2 and pdfplumber for text extraction
* Detects scanned (image-only) PDFs and returns an error
* Extracts text page by page with page number metadata

=== DOCX Parser

* `docx_parser.py` — Uses python-docx for Word document parsing
* Extracts paragraphs, tables, and headings
* Preserves document structure with heading levels

=== JSON Parser

* `json_parser.py` — Parses JSON files into ontology structures
* Top-level keys become candidate classes
* Nested objects suggest class hierarchies
* Arrays of primitives suggest data properties

=== XML Parser

* `xml_parser.py` — Parses XML files
* Element tags suggest class names
* Attributes suggest data properties
* Nested elements suggest object properties

=== CSV Parser

* `csv_parser.py` — Parses CSV files
* Header row → property names
* Each row → an individual
* File name → class name

=== XLSX Parser

* `xlsx_parser.py` — Uses openpyxl for Excel files
* Sheet names → class name candidates
* First row → property names
* Subsequent rows → individuals

== Adding a New Parser

. Create a new file in the `parsers/` directory (e.g., `yaml_parser.py`)
. Implement the parsing logic following the established pattern
. Register the new parser in `api/routes.py` by adding the format to the supported types dictionary
. Add the corresponding Python package to `pyproject.toml` dependencies if needed
. Add tests for the new parser in `tests/`
