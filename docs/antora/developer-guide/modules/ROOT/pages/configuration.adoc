= Configuration
:description: Environment variables, config files, and Docker Compose profiles for development.

== Environment Variables

All services are configured via environment variables. Defaults are set in `deploy/docker-compose.yml`.

=== API Gateway

|===
|Variable |Default |Description

|`SERVICE_PORT` |`8080` |Listen port
|`ONTOLOGY_SERVICE_URL` |`http://ontology-service:8081` |Ontology service backend URL
|`VERSIONING_SERVICE_URL` |`http://versioning-service:8082` |Versioning service backend URL
|`AUTH_SERVICE_URL` |`http://auth-service:8084` |Auth service backend URL
|===

=== Ontology Service (Rust)

|===
|Variable |Default |Description

|`HOST` |`0.0.0.0` |Bind address
|`PORT` |`8080` |Listen port
|`NEO4J_URI` |`bolt://neo4j:7687` |Neo4j Bolt connection URI
|`NEO4J_USER` |`neo4j` |Neo4j username
|`NEO4J_PASSWORD` |`password` |Neo4j password
|===

=== Versioning Service (Rust)

|===
|Variable |Default |Description

|`HOST` |`0.0.0.0` |Bind address
|`PORT` |`8080` |Listen port
|`DATABASE_URL` |`postgres://postgres:password@postgres:5432/vedo_versioning` |PostgreSQL connection string
|===

=== Auth Service (Go)

|===
|Variable |Default |Description

|`HOST` |`0.0.0.0` |Bind address
|`PORT` |`8080` |Listen port
|`KEYCLOAK_URL` |`http://keycloak:8080` |Keycloak server URL
|===

=== Metrics Service (Python)

|===
|Variable |Default |Description

|`HOST` |`0.0.0.0` |Bind address
|`PORT` |`8080` |Listen port
|`RABBITMQ_URL` |`amqp://guest:guest@rabbitmq:5672/` |RabbitMQ connection URL
|`REDIS_URL` |`redis://redis:6379` |Redis connection URL
|===

=== Frontend

|===
|Variable |Default |Description

|`VITE_API_URL` |`http://localhost:8080` |API Gateway URL (Vite env)
|`VITE_WS_URL` |`ws://localhost:8080` |WebSocket URL (Vite env)
|===

== Data Stores

=== Neo4j

|===
|Variable |Default |Description

|`NEO4J_AUTH` |`neo4j/password` |Neo4j authentication credentials
|===

Ports: `7474` (Browser), `7687` (Bolt).

=== PostgreSQL

|===
|Variable |Default |Description

|`POSTGRES_USER` |`postgres` |Database user
|`POSTGRES_PASSWORD` |`password` |Database password
|`POSTGRES_DB` |`vedo_versioning` |Default database name
|===

Port: `5432`.

=== Redis

Port: `6379`. No authentication in the default development setup.

=== RabbitMQ

|===
|Variable |Default |Description

|`RABBITMQ_DEFAULT_USER` |`guest` |AMQP user
|`RABBITMQ_DEFAULT_PASS` |`guest` |AMQP password
|===

Ports: `5672` (AMQP), `15672` (Management UI).

=== Keycloak

|===
|Variable |Default |Description

|`KEYCLOAK_ADMIN` |`admin` |Admin username
|`KEYCLOAK_ADMIN_PASSWORD` |`admin` |Admin password
|`KC_HEALTH_ENABLED` |`true` |Enable health endpoints
|===

Port: `8180` (mapped from internal `8080`).

Realm configuration is imported from `deploy/keycloak/vedo-core-realm.json`.

== Docker Compose

The main orchestration file is at `deploy/docker-compose.yml`.

[source,yaml]
----
include:
  - path: ./docker-compose.docs.yaml
----

Compose profiles:

|===
|Profile |Services

|(default) |All services + databases + Keycloak
|`local` |Includes `vedo-cli-build` (compile-only)
|`ci` |Includes `vedo-cli-build` (compile-only)
|===

== Multi-Environment Setup

The project ships three pre-configured env files with non-overlapping ports:

|===
|Environment |Env file |Port offset |Project name

|dev |`config/.env.dev` |none |`vedo-core-dev`
|test |`config/.env.test` |+10000 |`vedo-core-test`
|staging |`config/.env.staging` |+20000 |`vedo-core-staging`
|===

[source,bash]
----
make docker-up-dev      # Dev
make docker-up-test     # Test (includes JWT dev keys for Playwright)
make docker-up-staging  # Staging
----

=== Ways to Configure

|===
|Method |Example |Best for

|Shell env |`export API_GATEWAY_PORT=9090 && make docker-up` |One-off overrides
|`.env` file |Create `.env` with `API_GATEWAY_PORT=9090` |Persistent project config
|Inline |`API_GATEWAY_PORT=9090 make docker-up` |Temporary overrides
|===

=== Dev Environment Variables

The `config/.env.example` file contains placeholder values for reference. For development:

|===
|Variable |Default |Description

|`KC_HOSTNAME` |`localhost` |Keycloak hostname (must resolve in your environment)
|`KEYCLOAK_JWKS_URL` |`http://localhost:8180/realms/vedo-core/protocol/openid-connect/certs` |JWKS endpoint for token validation
|===

Override `KC_HOSTNAME` only if your Keycloak setup uses a different domain. Any override must be resolvable from the Docker network.

== Essential Overrides

|===
|Variable |Default |Description

|`LLM_PROVIDER` |*(empty — disabled)* |LLM backend: `openai`, `anthropic`, `ollama`
|`LLM_API_KEY` |*(empty)* |API key for the chosen provider
|`LLM_MODEL` |*(empty)* |Model name (e.g. `gpt-4o`, `claude-3-opus`, `llama3`)
|`LLM_BASE_URL` |*(empty)* |Custom OpenAI-compatible endpoint
|`LLM_PROVIDERS_OLLAMA_BASE_URL` |`http://localhost:11434/v1` |Ollama API endpoint
|`LLM_PROVIDERS_OLLAMA_MODEL` |`llama3` |Ollama model name
|`GRPC_TLS_ENABLED` |`false` |Enable mTLS for all gRPC services
|`GRPC_CA_CERT_FILE` |*(empty)* |CA certificate path (api-gateway)
|`GRPC_TLS_CERT_FILE` |*(empty)* |TLS certificate path (Rust services)
|`GRPC_TLS_KEY_FILE` |*(empty)* |TLS key path (Rust services)
|===

== AI Features (LLM)

Document extraction and AI orchestration require an LLM provider. Use the bundled Ollama profile for local development:

[source,bash]
----
# Start VEDO + local Ollama (~4 GB)
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.llm.yaml --profile llm up -d

# Pull a model into the running Ollama container
docker compose -f deploy/docker-compose.llm.yaml exec ollama ollama pull llama3

# Tell services to use Ollama
export LLM_PROVIDER=ollama
export LLM_PROVIDERS_OLLAMA_BASE_URL=http://ollama:11434/v1
export LLM_PROVIDERS_OLLAMA_MODEL=llama3
----

Or use a cloud provider:

[source,bash]
----
export LLM_PROVIDER=openai
export LLM_API_KEY=sk-...
export LLM_MODEL=gpt-4o
make docker-up
----
