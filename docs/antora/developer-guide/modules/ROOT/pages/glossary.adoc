== 1. Базовые концепты и теория моделирования

=== Данные (Data)
`data`
Совокупность конкретных xref:glossary.adoc#individual[индивидуальных объектов] и значений их свойств в рамках модели данных.

=== Значение свойства (Value)
`value`
Значение литерального свойства, выраженное определённым типом данных. «Значением» ссылочного свойства может считаться другой xref:glossary.adoc#individual[индивидуальный объект].

=== Индивидуальный объект (Individual)
`individual`
Конкретный объект, элемент модели, представляющий собой отдельную сущность реального мира. В отличие от xref:glossary.adoc#class[класса], индивид не может содержать другие экземпляры.

=== Интенсионал (Intension)
`intension`
Содержание понятия, совокупность существенных признаков, свойств и внутренней идеи, которая определяет класс.

=== Класс (Class)
`class`
Символ или понятие, используемое для обозначения совокупности объектов, обладающих общими свойствами (xref:glossary.adoc#extension[экстенсионала]) и объединённых общей идеей (xref:glossary.adoc#intension[интенсионалом]).

=== Концептуализация (Conceptualization)
`conceptualization`
Абстрактное, упрощённое представление фрагмента реальности, выраженное через набор понятий.

=== Модель (Model)
`model`
Информационное представление совокупности объектов и явлений, упрощённое, концептуализированное, с прогностическим потенциалом.

=== Модель данных, схема данных (Data model)
`dataModel`
Модель, задаваемая совокупностью xref:glossary.adoc#class[классов] и xref:glossary.adoc#property[свойств].

=== Онтология (Ontology)
`ontology`
Формальная, явная спецификация разделяемой концептуализации. Содержит xref:glossary.adoc#class[классы], xref:glossary.adoc#individual[индивиды], свойства, отношения и аксиомы на основе RDF/OWL.

=== Ссылочное свойство (Property)
`property`
Характеристика объекта, выражаемая либо значением-литералом, либо связью с другим объектом.

=== Свойство-литерал (Datatype Property)
`datatypeProperty`
Тип свойства, значением которого является конкретное данное (число, строка, дата, логическое значение).

=== Таксономия (Taxonomy)
`taxonomy`
Иерархическая структура организации классов на основе отношения обобщения/специализации (is-a).

=== Триплет (Triple)
`triple`
Фундаментальная структурная единица RDF: {Субъект, Предикат, Объект}.

=== Экстенсионал (Extension)
`extension`
Объём понятия — множество всех объектов, подпадающих под данный класс.

== 2. Цели и стратегии моделирования

=== Декомпозиция (Decomposition)
`decomposition`
Разделение моделируемого фрагмента реальности на отдельные элементы.

=== Идентификация (Identification)
`identification`
Присвоение объекту модели уникального идентификатора. Ключевой принцип — нейтральность идентификатора.

=== Имитационное моделирование (Simulation Modeling)
`simulationModeling`
Метод, при котором модель воспроизводит поведение сложной системы во времени.

=== Классификация (Classification)
`classification`
Логическая операция отнесения объекта к одному или нескольким классам.

=== Поддержка принятия решений (Decision Support)
`decisionSupport`
Применение онтологий и логического вывода для предоставления обоснованных вариантов действий.

=== Реификация (Reification)
`reification`
Технический приём «разворачивания» связи в отдельный узел для хранения метаинформации об отношении.

=== Фасетная классификация (Faceted Classification)
`facetedClassification`
Принцип классификации, при котором объект может быть отнесён к нескольким независимым фасетам.

=== Цифровой двойник (Digital Twin)
`digitalTwin`
Интегрированная модель подконтрольной системы, описывающая её структуру, состояние, поведение и взаимодействие с внешней средой.

== 3. Структура и архитектура онтологий

=== ABox (Assertion Box)
`abox`
Часть xref:glossary.adoc#ontology[онтологии] с утверждениями о конкретных xref:glossary.adoc#individual[индивидах].

=== TBox (Terminology Box)
`tbox`
Часть xref:glossary.adoc#ontology[онтологии] с определениями xref:glossary.adoc#class[классов], свойств и аксиом.

=== RBox (Role Box)
`rbox`
Компонент с аксиомами, относящимися к ролям (объектным свойствам): иерархия, транзитивность, симметричность.

=== Дескрипционная логика (Description Logic)
`descriptionLogic`
Семейство формальных языков представления знаний, лежащих в основе OWL.

=== Парадигма открытого мира (Open World Assumption)
`openWorldAssumption`
Допущение, что отсутствие факта не означает его ложности.

== 4. Технологический стек Semantic Web

=== RDF (Resource Description Framework)
`rdf`
Стандарт W3C для описания ресурсов в виде графа на основе xref:glossary.adoc#triple[триплетов].

=== RDFS (RDF Schema)
`rdfs`
Стандартный словарь для RDF: классы, свойства, иерархия, домен/диапазон.

=== OWL (Web Ontology Language)
`owl`
Язык описания онтологий на основе дескрипционных логик. Расширяет RDF/RDFS.

=== SPARQL (SPARQL Protocol and RDF Query Language)
`sparql`
Язык запросов к RDF-графам. В VEDO Core используется как основной язык семантического поиска.

=== SPARQL-инъекция
`sparqlInjection`
Атака внедрения кода в параметры SPARQL-запроса. Предотвращается xref:glossary.adoc#parameterizedQuery[параметризованными запросами].

=== Параметризованный запрос
`parameterizedQuery`
Техника передачи значений параметров отдельно от структуры запроса для исключения инъекций.

=== SWRL (Semantic Web Rule Language)
`swrl`
Язык правил логического вывода для OWL онтологий.

=== SHACL (Shapes Constraint Language)
`shacl`
Язык W3C для валидации RDF-графов через описание «форм» и ограничений.

=== URI / IRI (Uniform Resource Identifier)
`uri`
Унифицированный идентификатор ресурса. В Semantic Web — для глобальной идентификации сущностей.

=== Triple Store (RDF Store)
`tripleStore`
Специализированная графовая СУБД для хранения RDF-графов.

=== Машина логического вывода (Reasoner)
`reasoner`
Компонент для вычисления логических следствий из аксиом и фактов онтологии.

=== Пустой узел (Blank Node)
`blankNode`
Узел в RDF-графе без глобального URI-идентификатора.

=== SPARQL Endpoint
`sparqlEndpoint`
Сетевой интерфейс доступа к RDF-хранилищу. В VEDO Core: `/api/v1/sparql`, только чтение, с ограничениями.

=== Introspection
`introspection`
Возможность клиента получить метаданные текущей онтологии.

=== Turtle (Terse RDF Triple Language)
`turtle`
Текстовый формат сериализации RDF-графов. В VEDO Core — для импорта, экспорта и канонической сериализации.

=== RDF/XML
`rdfXml`
XML-сериализация RDF-графа для совместимости со старыми инструментами.

=== N-Triples
`nTriples`
Построчный формат сериализации RDF для потоковой обработки.

=== XSD (XML Schema Definition)
`xsd`
Набор стандартных типов данных XML Schema для значений DatatypeProperty.

=== Курсорная пагинация
`cursorPagination`
Механизм пагинации с непрозрачным курсором, исключающий пропуск и дублирование.

=== Глубина запроса (Depth limit)
`depthLimit`
Максимальная вложенность полей в навигационном запросе (предотвращение рекурсивных атак).

=== Сложность запроса (Query complexity)
`graphqlQueryComplexity`
Численная оценка ресурсоёмкости GraphQL-запроса.

== 6. Общетехнические термины

=== MVC (Model-View-Controller)
`mvc`
Архитектурный паттерн, разделяющий данные, интерфейс и логику управления.

=== noSQL (Not Only SQL)
`nosql`
Класс баз данных, не использующих реляционную модель: графовые, документные, ключ-значение.

=== XML (eXtensible Markup Language)
`xml`
Расширяемый язык разметки для сериализации данных.

=== XPath / XSLT
`xpath`
Стандарты W3C для навигации и трансформации XML-документов.

=== JSON-LD (JSON for Linked Data)
`jsonLd`
Формат сериализации связанных данных на основе JSON.

=== GraphQL
`graphql`
Язык запросов к API с явным указанием структуры данных. Основной API фронтенда VEDO Core.

=== OpenAPI
`openApi`
Машиночитаемая спецификация REST API.

=== Swagger UI
`swaggerUi`
Веб-интерфейс для просмотра и вызова REST API на основе OpenAPI.

=== Protocol Buffers / Protobuf
`protobuf`
Бинарный формат описания сообщений и сервисных контрактов для gRPC.

=== WebSocket
`webSocket`
Двунаправленный протокол связи поверх HTTP для realtime-уведомлений.

=== UUID (Universally Unique Identifier)
`uuid`
Универсальный уникальный идентификатор для адресации сущностей API.

=== JSONB
`jsonb`
Бинарный формат хранения JSON в PostgreSQL для дельт коммитов и метаданных.

== 7. Термины платформы VEDO Core

=== Платформа VEDO Core

==== VEDO
`vedo`
**V**irtual **E**nvironment for **D**eveloping **O**ntologies. Акроним платформы. Дескриптор: *Build, connect, and share knowledge at scale.*

==== VEDO Core
`vedoCore`
Центральный серверный компонент платформы VEDO, предоставляющий API, версионирование и управление онтологиями.

==== VEDO Editor
`vedoEditor`
Веб-интерфейс VEDO для визуального редактирования онтологий.

==== Точка доступа (Point of Access)
`pointOfAccess`
Изолированная рабочая область, объединяющая онтологию, хранилища и настройки доступа.

=== Архитектурные компоненты

==== Ontology Service
`ontologyService`
Микросервис на Rust для CRUD-операций над графом онтологии, валидации OWL-аксиом и обхода графа.

==== Versioning Service
`versioningService`
Микросервис на Rust для Git-подобного версионирования: коммиты, ветки, слияние, semantic diff.

==== API Gateway
`apiGateway`
Единая точка входа для внешних запросов. Маршрутизация, аутентификация, rate limiting.

==== Auth Service
`authService`
Микросервис на Go для аутентификации и авторизации через Keycloak (OAuth2 / OIDC).

==== Metrics Service
`metricsService`
Микросервис на Python для сбора и агрегации метрик онтологии.

==== vedo-cli
`vedoCli`
Единая CLI-утилита для администрирования: backup/restore, миграции, air-gap, диагностика.

=== Функции и возможности

==== Каноническая сериализация (Canonical Serialization)
`canonicalSerialization`
Нормализованный Turtle для стабильного diff между версиями.

==== Коммит онтологии (Ontology Commit)
`ontologyCommit`
Фиксация изменений онтологии с SHA-256 хэшем и дельтой триплетов.

==== Ветка онтологии (Ontology Branch)
`ontologyBranch`
Независимая линия разработки онтологии для параллельной работы.

==== Слияние онтологий (Ontology Merge)
`ontologyMerge`
Объединение изменений из одной ветки в другую с семантическим разрешением конфликтов.

==== Merge Request
`ontologyMergeRequest`
Запрос на слияние ветки с ревью и обсуждением.

==== Canonical Workload Profile
`canonicalWorkloadProfile`
Единица масштаба для SLA, QA benchmarks и capacity planning.

==== API Coverage Gate
`apiCoverageGate`
Gate, проверяющий, что все endpoint'ы из Operation Inventory существуют в OpenAPI-спецификации.

==== Обратная совместимость API (API Backward Compatibility)
`apiBackwardCompatibility`
Гарантия, что изменения API не ломают существующих клиентов.

==== Deprecation Period
`deprecationPeriod`
Период поддержки устаревших API-эндпоинтов (N + 1 minor version).

==== Долгосрочная поддержка (LTS)
`lts`
Версии с длительным сроком поддержки для Enterprise-клиентов.

==== Аварийный выключатель (Kill Switch)
`killSwitch`
Механизм безопасной остановки подозрительных операций.

==== Доказательство развёртывания (Deployment Evidence)
`deploymentEvidence`
Верифицируемое подтверждение успешного развёртывания (Helm + CI + мониторинг).

== 8. SLA, метрики и восстановление

=== RTO (Recovery Time Objective)
`rto`
Целевое время восстановления после сбоя.

=== RPO (Recovery Point Objective)
`rpo`
Целевая точка восстановления — максимально допустимая потеря данных.

=== SLA (Service Level Agreement)
`sla`
Соглашение об уровне обслуживания.

=== SLO (Service Level Objective)
`slo`
Целевой показатель уровня обслуживания.

=== SLI (Service Level Indicator)
`sli`
Индикатор уровня обслуживания (измеряемая метрика).

=== Error Budget
`errorBudget`
Бюджет ошибок — допустимый уровень отказов для SLO.

`alertSeverity`
Уровни критичности алертов: P0 (критичный), P1 (высокий), P2 (средний), P3 (низкий).

=== GitOps
`gitOps`
Подход к управлению инфраструктурой через Git как единый источник истины.

=== CI/CD (Continuous Integration / Continuous Deployment)
`cicd`
Непрерывная интеграция и непрерывная поставка.

=== WAL (Write-Ahead Logging)
`wal`
Журнал упреждающей записи для обеспечения целостности данных.

=== Откат (Rollback)
`rollback`
Восстановление предыдущего стабильного состояния.

=== Защита окружения (Environment Guard)
`environmentGuard`
Автоматическая защита окружения от разрушительных изменений.

=== Эксплуатационная инструкция (Runbook)
`runbook`
Инструкция по действиям при инцидентах и штатных операциях.

=== PITR (Point-in-Time Recovery)
`pitr`
Восстановление на момент времени.

=== 3-2-1 Backup Strategy
`backup321`
Стратегия бэкапов: 3 копии, 2 носителя, 1 вне площадки.

=== Неизменяемая резервная копия (Immutable Backup)
`immutableBackup`
Резервная копия, которую нельзя изменить или удалить до истечения срока хранения.

=== Предохранитель (Circuit Breaker)
`circuitBreaker`
Паттерн защиты от каскадных отказов.

=== Плавная деградация (Graceful Degradation)
`gracefulDegradation`
Сохранение частичной функциональности при отказе компонентов.

== 9. Модели развёртывания

=== SaaS (Software as a Service)
`saas`
Облачная модель поставки программного обеспечения.

=== On-premise
`onPremise`
Развёртывание на инфраструктуре заказчика.

=== Приватное облако (Private Cloud)
`privateCloud`
Выделенная облачная инфраструктура для одного заказчика.

=== Мультитенантность (Multi-tenant)
`multiTenant`
Режим, при котором один экземпляр обслуживает несколько организаций.

=== Kubernetes / K8s
`kubernetes`
Платформа оркестрации контейнеров для развёртывания VEDO Core.

=== Docker
`docker`
Контейнеризация микросервисов VEDO Core.

=== Изолированное развёртывание (Air-gapped Deployment)
`airGapped`
Развёртывание в сети, изолированной от интернета.

=== Сине-зелёное развёртывание (Blue-Green Deployment)
`blueGreen`
Стратегия деплоя с двумя идентичными окружениями.

=== Канареечный выпуск (Canary Release)
`canaryRelease`
Постепенное развёртывание новой версии для части пользователей.

=== HA (High Availability)
`ha`
Высокая доступность — способность системы сохранять работоспособность при отказах.

=== Feature Flags (Feature Toggles)
`featureFlags`
Механизм включения/отключения функций без развёртывания.

== 10. Методология, архитектура и качество

=== ADR (Architecture Decision Record)
`adr`
Запись архитектурного решения: контекст, решение, альтернативы, последствия.

=== C4 Model
`c4Model`
Модель описания архитектуры ПО на четырёх уровнях: контекст, контейнеры, компоненты, код.

=== NFR (Non-Functional Requirement)
`nfr`
Нефункциональное требование: производительность, безопасность, надёжность.

=== PBT (Property-Based Testing)
`pbt`
Свойство-ориентированное тестирование на основе формальных инвариантов.

=== Gate
`gate`
Контрольная точка качества, блокирующая релиз при нарушении.

=== Фаззинг-тестирование (Fuzz Testing)
`fuzzTesting`
Тестирование генерацией случайных входных данных.

=== Базовая линия производительности (Performance Baseline)
`performanceBaseline`
Эталонные показатели производительности для сравнения.

=== Traceability
`traceability`
Прослеживаемость: связь требований → контрактов → тестов → gates.

=== HLV (Human-Led Validation)
`hlv`
Методология Human-Led Validation для обеспечения качества через формальные контракты.

=== Saga Pattern
`sagaPattern`
Паттерн управления распределёнными транзакциями.

=== Пробный прогон (Dry-run)
`dryRun`
Тестовый запуск операции без фактического изменения состояния.
