= Testing
:description: Test suites, how to run them, and what they cover.

== Quick Reference

|===
|Test suite |Make target |Requirements

|Unit tests |`make test` |Language toolchains only
|Integration tests |`make test-integration` |Live infra (Neo4j, Postgres)
|E2E — API |`make test-e2e-api` |Docker test stack
|E2E — GUI |`make test-e2e-gui` |Docker test stack + frontend
|E2E — all |`make test-e2e` |Docker test stack
|Contract / gate tests |`make test-gates` |Go toolchain + Docker stack
|Full CI |`make ci` |Language toolchains only
|Full CI + e2e |`make ci-full` |Docker test stack + infra
|===

== Test Suites

Cross-service test suites are in `tests/`:

|===
|Suite |Path |Description

|E2E — API |`tests/e2e/specs/api/` |REST, GraphQL, SPARQL integration tests
|E2E — GUI |`tests/e2e/specs/gui/` |Pages, user stories, a11y tests
|Security |`tests/security/` |BOLA/BFLA authorization tests
|CLI |`tests/cli/` |vedo-cli integration tests
|Integration |`tests/integration/` |Go integration tests (ticket-api, org-api)
|Gates |`tests/gates/` |Gate-level test scripts
|===

== Running Tests

=== Unit Tests (Fast)

No test environment required — tests run natively with language toolchains.

[source,bash]
----
make test              # All unit tests
make test-rust         # cargo test --lib
make test-go           # go test ./...
make test-python       # pytest
make test-typescript   # pnpm test
----

=== Integration Tests

Requires live database infrastructure (Neo4j, Postgres).

[source,bash]
----
make test-integration        # All integration tests
make test-integration-rust   # Rust only (NEO4J_URI, DATABASE_URL required)
----

Integration tests gracefully skip with a clear message to stderr when the relevant environment variable is unset.

=== Coverage

[source,bash]
----
make coverage    # Go tests with coverage profiles (cover.out per service)
----

=== E2E Tests (Playwright)

Requires the Docker test stack. Two-phase execution — API runs first (fast feedback), GUI runs second.

Playwright configs automatically start the backend using `deploy/docker-compose.test.yml`, which overrides the API Gateway to accept self-signed test JWT tokens instead of requiring Keycloak.

[source,bash]
----
# Start the test stack first (or let Playwright auto-start it)
make docker-up-test

# Phase 1: API tests (REST, GraphQL, SPARQL)
make test-e2e-api

# Phase 2: GUI tests (pages, user stories, a11y)
make test-e2e-gui

# Or run both phases together
make test-e2e
----

GUI tests use `maxFailures: 1` — stops on first failure for fast feedback. API tests use `retries: 2`.

==== Running a Single GUI Test

[source,bash]
----
cd tests/e2e
pnpm exec playwright test --config=config/playwright.gui.config.ts -g "Dashboard Navigation"
pnpm exec playwright test --config=config/playwright.gui.config.ts specs/gui/pages/dashboard-navigation.spec.ts

# Override maxFailures for a subset
pnpm exec playwright test --config=config/playwright.gui.config.ts specs/gui/user-stories/ --max-failures=0
----

=== Security Tests (BOLA/BFLA)

Security tests in `tests/security/` verify:

* *BOLA* (Broken Object-Level Authorization) — users cannot access other users' ontologies, groups, or merge requests.
* *BFLA* (Broken Function-Level Authorization) — users cannot invoke admin-level operations without proper roles.

[source,bash]
----
bash tests/gates/test_bola_bfla_gate.sh
----

== CI Pipeline

[source,bash]
----
make ci        # proto-all → build → lint → test → typecheck
make ci-full   # ci + test-integration + test-e2e + test-gates
----

`ci` runs everything that doesn't require Docker. `ci-full` adds integration, E2E, and gate tests.

== Test Structure

----
tests/
├── e2e/
│   ├── config/playwright.api.config.ts   # API test config
│   ├── config/playwright.gui.config.ts   # GUI test config
│   ├── specs/api/                        # REST, GraphQL, SPARQL tests
│   ├── specs/gui/                        # Pages, user stories, a11y
│   ├── scripts/run-ci.sh                 # CI gate runner
│   └── package.json
├── integration/                          # Go integration tests
│   ├── ticket-api/
│   └── org-api/
├── gates/                                # Gate-level test scripts
└── security/                             # BOLA/BFLA authorization tests
----
