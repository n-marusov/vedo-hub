= Протоколы API
:description: Протоколы взаимодействия VEDO Core: gRPC, REST, WebSocket, GraphQL, SPARQL
:keywords: API, gRPC, REST, WebSocket, GraphQL, SPARQL

== Введение

VEDO Core использует пять протоколов для разных сценариев взаимодействия. Граница протоколов обязательна к соблюдению.

== gRPC (внутренние вызовы)

* Внутренние вызовы между микросервисами
* Контракты через protobuf
* Потоковая передача

Используется для: вызовов API Gateway → Ontology Service, Versioning Service, Auth Service.

== REST (внешний API)

* Внешний API для отраслевых приложений
* Формат JSON
* Документация через OpenAPI

Базовый URL: `/api/v1/`

Эндпоинты: классы, свойства, индивиды, импорт, экспорт, коммиты, ветки, SPARQL.

== WebSocket

* Realtime коллаборация
* Двунаправленная связь, низкая задержка

Используется для: комментарии (Commenting Service), уведомления.

Подключение: `wss://api.vedo.example/ws/comments` (JWT auth on connect).

== GraphQL

* Основной API фронтенда для навигации по графу
* Порционная загрузка подграфов
* Cursor pagination
* Apollo Client cache

== SPARQL 1.1

* Семантические запросы к RDF-графу
* Только SELECT и ASK (модифицирующие запросы запрещены)
* Query complexity ограничения
* Read-only режим

== Аутентификация

API Gateway валидирует JWT-токены через Auth Service:

* JWT (RS256, 15m TTL)
* Refresh tokens (7d TTL)
* OAuth2/OIDC через Keycloak
* Bearer-токен в заголовке Authorization

== Обработка ошибок

Единый формат ошибок с stable error_code и message_key:

[source,json]
----
{
  "error_code": "CYCLE_DETECTED",
  "message": "Cycle detected in class hierarchy",
  "details": {
    "class_id": "http://example.com#Cat",
    "parent_id": "http://example.com#Animal"
  }
}
----

Подробнее: xref:integrator-guide::rest-api.adoc[REST API] и xref:integrator-guide::authentication.adoc[Аутентификация] в руководстве интегратора.
