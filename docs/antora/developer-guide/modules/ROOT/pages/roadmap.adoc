== Этапы развития

=== Этап 1: Базовый редактор (MVP)

*Цель:* Работающий редактор онтологий для одного пользователя.

*Функции:*
* F1: Просмотр и навигация по графу (2D)
* F2: Редактор онтологий (TBox) — классы, ObjectProperty, DatatypeProperty
* F4: Управление индивидами (ABox)
* F6: REST API (базовый CRUD)
* F8: Импорт/экспорт (Turtle, RDF/XML)
* F10: SPARQL endpoint (read-only)

*Срок:* Кв. 1

=== Этап 2: Версионирование и коллаборация

*Цель:* Командная работа через Git-подобное версионирование.

*Функции:*
* F3: Git-подобное управление версиями (коммиты, ветки, слияние)
* F5: Комментарии и обсуждения
* F3.5: Semantic Diff
* F12: Базовая поддержка и сбор обратной связи

*Срок:* Кв. 2

=== Этап 3: Качество данных и аналитика

*Цель:* Инструменты для обеспечения качества онтологий.

*Функции:*
* F7: Метрики и аналитика
* SHACL-валидация
* Визуальный конструктор правил качества
* Поиск дубликатов

*Срок:* Кв. 3

=== Этап 4: Публикация и интеграция

*Цель:* Обмен онтологиями с внешними системами.

*Функции:*
* F11: Публикация онтологий (снапшоты)
* Webhooks
* GraphQL API
* Интеграция с Git-репозиториями (экспорт)

*Срок:* Кв. 3

=== Этап 5: Администрирование и CLI

*Цель:* Инструменты для эксплуатации.

*Функции:*
* F9: `vedo-cli` (backup, restore, миграции)
* Air-gapped deployment
* Диагностика по trace_id
* RBAC и управление доступом

*Срок:* Кв. 4

=== Этап 6: Enterprise и масштабирование

*Цель:* Корпоративные функции.

*Функции:*
* Multi-AZ и geo-репликация
* On-premise установка
* 24/7 поддержка с SLA
* White-label (брендирование)
* Audit log

*Срок:* Кв. 4

=== Этап 7: Сообщество и экосистема

*Цель:* Построение сообщества вокруг платформы.

*Функции:*
* Публичный roadmap с голосованием
* Форум сообщества
* База знаний и FAQ
* Плагины и SDK

*Срок:* Кв. 4+

== Технический долг

* LOP (Large Object Promisor) — отложено до зрелой поддержки
* Kafka — опционально для event sourcing
* 3D-визуализация графа — post-MVP
* Полнотекстовый поиск по опубликованным онтологиям — post-MVP
