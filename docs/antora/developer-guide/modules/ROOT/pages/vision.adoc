== Бизнес-проблема

Современные инструменты разработки онтологий (прежде всего десктопный Protégé) создают серьёзные препятствия для промышленного использования:

|===
| ID | Проблема | Влияние

| P1
| Зависания при работе с крупными онтологиями (45 сек на открытие класса с 500 потомками) и нестабильная сериализация RDF/XML
| 15 минут простоя в день на инженера + ложные изменения в Git

| P2
| Невозможность параллельной работы — файловый обмен по email, ручная склейка изменений
| 6 человеко-часов в день на команду из 3 человек

| P3
| Потеря контекста ревью — комментарии в Protégé неудобны, не видны при интеграции
| Ошибки в проектировании API стоимостью от 500 000 ₽

| P4
| Высокий порог входа: нужно изучать OWL и дескрипционные логики
| Месяцы на обучение, сопротивление внедрению

| P5
| Интеграция онтологий требует написания кода на Java/Python
| 40–80 часов на одну интеграцию

| P6
| Сложность развёртывания и администрирования
| 1–2 недели на запуск проекта
|===

== Формулировка концепции

**Короткая версия:**

> Мы превращаем хаос из десктопных файлов и нечитаемых Git-диффов в веб-платформу для разработки онтологий с Git-подобным управлением версиями.

**Полная версия:**

> **Для** инженеров знаний, ИТ-архитекторов и проектных команд,
> **которые** сегодня сталкиваются с низкой производительностью десктопных инструментов, сложностью параллельной работы и отсутствием контроля версий при разработке онтологий,
> **VEDO Core** является центральной веб-платформой для управления жизненным циклом онтологий,
> **которая** обеспечивает молниеносную работу с графами знаний, Git-подобное управление версиями и REST API для бесшовной интеграции,
> **в отличие от** Protégé с файлами .owl, ручным мержем в Git и отсутствием веб-интерфейса.

== Критерии успеха

* **Функциональный** — все операции редактора стабильны и покрыты автотестами
* **Производительностный** — CRUD-операции ≤ 1 сек при 500 000 триплетов
* **Интеграционный** — полное управление онтологией через HTTP API
* **Коллаборативный** — параллельная работа 5 инженеров в разных ветках
* **Аудиторский** — каждое изменение фиксируется в журнале аудита
* **Эксплуатационный** — `vedo-cli` как единая административная утилита
* **Диагностический** — P0 локализуется через `vedo-cli diagnose` за ≤ 10 мин
* **Поддержка** — P0 ≤ 15 мин, NPS ≥ 30
