:toc: left

== Версионирование

API VEDO Core использует **URL-based версионирование**: версия указывается в пути endpoint'а:

[source]
----
https://api.vedo.local/api/v1/...
----

Текущая версия: **v1**.

== Обратная совместимость

VEDO Core гарантирует обратную совместимость (xref:glossary.adoc#api-backward-compatibility[API Backward Compatibility]) в пределах одной мажорной версии:

* Новые поля в ответах добавляются без нарушения существующих клиентов
* Новые endpoint'ы добавляются без изменения существующих
* Существующие поля и endpoint'ы не удаляются без предупреждения

Нарушением обратной совместимости считается:

* Удаление или переименование endpoint'а
* Удаление или переименование поля в ответе
* Изменение типа поля
* Добавление обязательного поля в запрос
* Изменение формата ошибок
* Изменение статус-кодов

== Деприкация (Deprecation)

Процесс устаревания функциональности API:

. **Объявление деприкации**: endpoint или поле помечается как deprecated в OpenAPI-спецификации и документации
. **Deprecation Period**: от 6 месяцев для SaaS, от 12 месяцев для LTS (xref:glossary.adoc#lts[Long Term Support])
. **Удаление**: после завершения deprecation period

Заголовки ответа для deprecated endpoint'ов:

[source]
----
Sunset: Sat, 20 May 2027 00:00:00 GMT
Deprecation: true
----

=== Пример

[source,http]
----
HTTP/1.1 200 OK
Deprecation: true
Sunset: Sat, 20 May 2027 00:00:00 GMT

{
  "data": [...],
  "deprecation": {
    "message": "This endpoint will be removed after May 2027",
    "migration": "Use GET /api/v1/ontologies/{id}/classes instead",
    "removalDate": "2027-05-20"
  }
}
----

== Политика совместимости по типам клиентов

|===
| Тип клиента | Гарантия совместимости

| SaaS (текущая версия)
| Обратная совместимость в пределах v1.x

| Enterprise on-premise (LTS)
| Обратная совместимость на весь срок LTS (12 мес после анонса)

| Sandbox
| Может изменяться быстрее, без предупреждения
|===

== Миграция между версиями

=== v1 → v2 (дата TBD)

При выпуске v2 будет опубликован миграционный гайд со следующими разделами:

* Изменения в endpoint'ах и форматах
* Сроки: deprecation v1, поддержка v1, удаление v1
* Инструменты для миграции (скрипты, чек-листы)
* Примеры перехода

=== Миграция конфигурации

Для on-premise клиентов миграция на новую мажорную версию выполняется через Helm-чарты:

[source,bash]
----
helm upgrade vedo-core ./charts/vedo-core \
  --set api.version=v2 \
  --reuse-values
----

== Breaking changes

Внеплановые breaking changes выпускаются только в исключительных случаях (security-уязвимости, критические ошибки) с обязательным уведомлением клиентов за 30 дней.

Уведомления отправляются через:

* Email администраторам онтологий
* Статус-страницу сервиса
* Webhook-уведомления (для подписанных клиентов)

== Версионирование SDK

* Версионирование SDK следует за версиями API
* Мажорная версия SDK = мажорная версия API
* SDK v1.x совместим с API v1.x

== Рекомендации для разработчиков

. **Обрабатывайте неизвестные поля в JSON-ответах** — будущие версии могут добавлять новые поля
. **Используйте заголовки `Deprecation` и `Sunset`** для отслеживания устаревших endpoint'ов
. **Подписывайтесь на уведомления об изменениях** через webhook `api.deprecation`
. **Тестируйте интеграцию в xref:sandbox.adoc[sandbox]** перед обновлением production
. **Фиксируйте версию API в конфигурации клиента**
