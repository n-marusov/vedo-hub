= Устранение неполадок
:description: Решение типовых проблем при интеграции с VEDO Core.
:toc: left
:toclevels: 2

== HTTP-ошибки

=== 400 Bad Request

Причины:

* Некорректный JSON в теле запроса
* Отсутствие обязательных полей
* Ошибка валидации (например, неверный формат IRI)

Решение: проверьте тело запроса на соответствие схеме. В ответе содержится поле `details` с описанием ошибки:

[source,json]
----
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Validation failed",
    "details": [
      {"field": "label", "message": "Label is required"}
    ]
  }
}
----

=== 401 Unauthorized

Причины:

* Отсутствует заголовок `Authorization`
* Истёк JWT-токен (срок жизни — 1 час)
* Неверный формат токена

Решение:

[source,bash]
----
# Проверьте наличие заголовка
curl -I -H "Authorization: Bearer <token>" https://api.vedo.local/api/v1/health

# Получите новый токен (см. Начало работы)
curl -X POST https://keycloak.vedo.local/realms/vedo-core/protocol/openid-connect/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "client_id=vedo-api-client" \
  -d "client_secret=<secret>" \
  -d "grant_type=client_credentials"
----

=== 403 Forbidden

Причины:

* Недостаточно прав для выполнения операции
* Попытка доступа к чужой онтологии
* BOLA/BFLA защита сработала

Решение:

* Проверьте роль пользователя (xref:glossary.adoc#rbac[RBAC])
* Убедитесь, что у вас есть доступ к данной онтологии
* Обратитесь к владельцу онтологии для изменения прав

[NOTE]
====
API всегда возвращает `403` (никогда `404`) при отсутствии доступа к ресурсу, чтобы не раскрывать существование ресурса (защита от IDOR).
====

=== 404 Not Found

Причины:

* Неверный `ontologyId`, `classId`, `propertyId`
* Ресурс был удалён
* ID не URL-encoded (для IRI с символами `:`, `/`, `#`)

Решение:

* Проверьте ID в URL
* URL-encode IRI-идентификаторы: `http://example.org/onto#Person` → `http%3A%2F%2Fexample.org%2Fonto%23Person`

=== 409 Conflict

Причины:

* Попытка создать дубликат класса/свойства
* Попытка удалить класс, имеющий индивиды
* Попытка удалить свойство, используемое классом

Решение: получите список зависимостей из тела ответа и устраните конфликт.

=== 429 Too Many Requests

Причины:

* Превышен rate limit (xref:limits.adoc[Лимиты и квоты])
* SPARQL-запрос слишком сложный

Решение:

* Дождитесь окончания окна rate limit
* Уменьшите частоту запросов
* Для SPARQL: упростите запрос, уменьшите LIMIT

Заголовки ответа:

[source]
----
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1621500000
Retry-After: 60
----

=== 503 Service Unavailable

Причины:

* Плановое обслуживание (maintenance window)
* Активирован xref:glossary.adoc#kill-switch[Kill Switch] (режим read-only)

Решение:

* Проверьте статус-страницу сервиса
* Дождитесь окончания обслуживания

== Аутентификация

=== Токен истёк

JWT-токен действителен 1 час. Используйте refresh token для получения нового.

=== Refresh token недоступен

Если refresh token также истёк, выполните полную аутентификацию заново.

=== Service account не работает

Убедитесь, что:

* Client ID и Client Secret корректны
* Service account активирован в Keycloak
* У service account есть необходимые роли

== Rate Limiting

См. xref:limits.adoc[Лимиты и квоты] для полной информации.

== Query complexity

=== GraphQL

При ошибке превышения сложности запроса:

* Уменьшите вложенность полей
* Уменьшите размер страницы (параметр `first`)
* Увеличьте depth limit или подождите снятия ограничения

=== SPARQL

При ошибке превышения сложности SPARQL-запроса:

* Уменьшите количество triple patterns
* Избегайте вложенных `OPTIONAL` и `UNION`
* Добавьте `LIMIT`
* Упростите FILTER-выражения

== SPARQL-ошибки

|===
| Ошибка | Причина | Решение

| `SPARQL_SYNTAX_ERROR`
| Ошибка синтаксиса
| Проверьте валидность SPARQL-запроса

| `SPARQL_WRITE_NOT_ALLOWED`
| Попытка INSERT/DELETE
| Endpoint только для чтения

| `SPARQL_MISSING_LIMIT`
| Отсутствует LIMIT
| Добавьте LIMIT в SELECT-запрос

| `SPARQL_QUERY_TOO_COMPLEX`
| Превышен лимит сложности
| Упростите запрос

| `SPARQL_TIMEOUT`
| Превышено время выполнения
| Уменьшите объём данных или упростите запрос
|===

== Webhook delivery failures

|===
| Симптом | Причина | Решение

| Подписка деактивирована
| >10% ошибок за последний час
| Проверьте endpoint, активируйте подписку

| Signature mismatch
| Неверный секрет
| Проверьте `secret` при создании подписки

| Delivery timeout
| Endpoint не отвечает за 10 сек
| Убедитесь, что endpoint доступен и отвечает 2xx

| Все попытки исчерпаны
| Endpoint недоступен
| Проверьте URL, firewall, SSL-сертификат
|===

== Отладка

=== Заголовки отладки

Включает ли запрос заголовок `X-Request-Id`? Всегда добавляйте его для трассировки:

[source,bash]
----
curl -X GET ... -H "X-Request-Id: my-custom-id"
----

=== Получение деталей ошибки

Тело ответа на ошибку содержит `requestId`, который можно использовать при обращении в поддержку для поиска trace:

[source,json]
----
{
  "error": {
    "code": "VALIDATION_ERROR",
    "requestId": "req_abcdef123456",
    "message": "..."
  }
}
----

=== Использование vedo-cli diagnose

Для диагностики инцидентов используйте `vedo-cli diagnose trace --id <trace_id>` с полученным `requestId`.

=== Swagger UI

Используйте Swagger UI по адресу `https://api.vedo.local/api/docs` для тестирования endpoint'ов в интерактивном режиме.
