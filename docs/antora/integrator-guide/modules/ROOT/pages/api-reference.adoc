== Базовый URL

[source]
----
https://api.vedo.local/api/v1
----

[NOTE]
====
Базовый URL зависит от окружения:

* Sandbox: `https://api-sandbox.vedo.local/api/v1`
* Production: `https://api.vedo.local/api/v1`
* On-premise: определяется при развёртывании
====

== Аутентификация и авторизация

Все запросы к API требуют JWT-токен, передаваемый в заголовке `Authorization`:

[source]
----
Authorization: Bearer <jwt-token>
----

Токен выдаётся через Keycloak (см. xref:gettingstarted.adoc[Начало работы]).

=== Стандартные заголовки

|===
| Заголовок | Обязательный | Описание

| `Authorization: Bearer <token>`
| Да
| JWT-токен

| `Accept: application/json`
| Да
| Формат ответа

| `Content-Type: application/json`
| Для POST/PATCH
| Формат тела запроса

| `X-Request-Id`
| Нет
| Идентификатор запроса для трассировки

| `X-Idempotency-Key`
| Для мутирующих запросов
| Ключ идемпотентности
|===

== Пагинация

API использует cursor-based пагинацию. Параметры запроса:

|===
| Параметр | Тип | По умолчанию | Описание

| `first`
| integer
| 20
| Количество элементов на странице (max 100)

| `after`
| string
| —
| Курсор для получения следующей страницы
|===

Формат ответа:

[source,json]
----
{
  "data": [...],
  "pagination": {
    "endCursor": "cursor_string",
    "hasNextPage": true
  }
}
----

[NOTE]
====
Offset-пагинация не поддерживается. Все endpoint'ы со списками используют cursor-based пагинацию для обеспечения консистентности при параллельных изменениях.
====

== Обработка ошибок

API использует стандартные HTTP-статусы и единый формат ошибок:

[source,json]
----
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Human-readable description",
    "details": [
      {
        "field": "label",
        "message": "Label is required"
      }
    ],
    "requestId": "req_abcdef123456"
  }
}
----

=== HTTP-статусы

|===
| Код | Описание

| `200 OK`
| Успешный запрос

| `201 Created`
| Ресурс создан

| `204 No Content`
| Ресурс удалён

| `400 Bad Request`
| Некорректный запрос (validation error)

| `401 Unauthorized`
| Отсутствует или истёк JWT-токен

| `403 Forbidden`
| Недостаточно прав

| `404 Not Found`
| Ресурс не найден

| `409 Conflict`
| Конфликт (например, duplicate)

| `422 Unprocessable Entity`
| Семантическая ошибка (OWL validation)

| `429 Too Many Requests`
| Превышен rate limit

| `500 Internal Server Error`
| Внутренняя ошибка сервера

| `503 Service Unavailable`
| Сервис временно недоступен (maintenance / kill-switch)
|===

== Эндпоинты

=== Навигация по графу

==== Дерево классов

[source,bash]
----
GET /api/v1/ontologies/{ontologyId}/classes/tree
----

Возвращает иерархическое дерево классов.

|===
| Параметр | Тип | Описание

| `ontologyId`
| string (path)
| UUID онтологии

| `depth`
| integer (query)
| Глубина дерева (max 10, default 3)

| `parentId`
| string (query)
| ID родительского узла для поддерева
|===

Пример ответа:

[source,json]
----
{
  "data": [
    {
      "id": "http://example.org/onto#Thing",
      "label": "Thing",
      "children": [
        {
          "id": "http://example.org/onto#Agent",
          "label": "Agent",
          "children": [...]
        }
      ]
    }
  ]
}
----

==== Поиск сущностей

[source,bash]
----
GET /api/v1/ontologies/{ontologyId}/search?query={query}&type={type}
----

|===
| Параметр | Тип | Описание

| `ontologyId`
| string (path)
| UUID онтологии

| `query`
| string (query)
| Поисковый запрос

| `type`
| string (query)
| Фильтр по типу: `class`, `property`, `individual`, `all` (default)
|===

Пример:

[source,bash]
----
curl -X GET "https://api.vedo.local/api/v1/ontologies/abc-123/search?query=Person&type=class" \
  -H "Authorization: Bearer <token>" \
  -H "Accept: application/json"
----

=== Фильтрация классов

[source,bash]
----
GET /api/v1/ontologies/{ontologyId}/classes?showAbstract={bool}&showDeprecated={bool}
----

|===
| Параметр | Тип | Описание

| `ontologyId`
| string (path)
| UUID онтологии

| `showAbstract`
| boolean (query)
| Показывать абстрактные классы (default: true)

| `showDeprecated`
| boolean (query)
| Показывать устаревшие классы (default: false)
|===

=== Детали класса

[source,bash]
----
GET /api/v1/ontologies/{ontologyId}/classes/{classId}
----

[source,bash]
----
curl -X GET "https://api.vedo.local/api/v1/ontologies/abc-123/classes/http%3A%2F%2Fexample.org%2Fonto%23Person" \
  -H "Authorization: Bearer <token>" \
  -H "Accept: application/json"
----

[NOTE]
====
ID классов и свойств передаются в URL как URL-encoded IRI. Используйте `%2F` вместо `/` и `%3A` вместо `:`.
====

=== Управление классами

==== Список классов

[source,bash]
----
GET /api/v1/ontologies/{ontologyId}/classes
----

==== Создание класса

[source,bash]
----
POST /api/v1/ontologies/{ontologyId}/classes
----

Тело запроса:

[source,json]
----
{
  "label": "Person",
  "comment": "A person entity",
  "parents": ["http://example.org/onto#Agent"],
  "abstract": false
}
----

==== Обновление класса

[source,bash]
----
PATCH /api/v1/ontologies/{ontologyId}/classes/{classId}
----

[source,json]
----
{
  "label": "Updated Person",
  "comment": "Updated description",
  "abstract": true
}
----

==== Удаление класса

[source,bash]
----
DELETE /api/v1/ontologies/{ontologyId}/classes/{classId}
----

[NOTE]
====
Удаление класса может быть отклонено при наличии индивидов или зависимых свойств. В этом случае API возвращает `409 Conflict` с описанием зависимостей.
====

----

[source,json]

  "comment": "Parent relationship",

    "symmetric": false,
    "functional": false

[source,json]
----

  "label": "fullName",
  "comment": "Full name of person",
  "type": "datatypeProperty",
  "domain": ["http://example.org/onto#Person"],
  "range": "xsd:string"
}
----

[source,bash]
----
PATCH /api/v1/ontologies/{ontologyId}/properties/{propertyId}
----

==== Удаление свойства

[source,bash]

=== Версионирование

==== Список коммитов

[source,bash]
----
GET /api/v1/ontologies/{ontologyId}/commits
----

==== Получение коммита

[source,bash]
----
GET /api/v1/ontologies/{ontologyId}/commits/{sha}
----

[source,bash]
----
curl -X GET "https://api.vedo.local/api/v1/ontologies/abc-123/commits/a1b2c3d4" \
  -H "Authorization: Bearer <token>" \
  -H "Accept: application/json"
----

Ответ включает diff и статистику:

[source,json]
----
{
  "sha": "a1b2c3d4e5f6...",
  "message": "Added Person class",
  "author": {
    "id": "user_123",
    "name": "John Doe"
  },
  "timestamp": "2026-05-20T10:30:00Z",
  "stats": {
    "additions": 5,
    "deletions": 0,
    "modified": 0
  },
  "diff": [...]
}
----

==== Создание коммита

[source,bash]
----
POST /api/v1/ontologies/{ontologyId}/commits
----

[source,json]
----
{
  "message": "Added Person class with properties",
  "branch": "main"
}
----

[source,bash]

GET /api/v1/ontologies/{ontologyId}/branches

=== Импорт/Экспорт

==== Экспорт онтологии

[source,bash]
----
GET /api/v1/ontologies/{ontologyId}/export?format={format}
----

Параметр `format`:

* `turtle` (default) — Turtle (.ttl)
* `rdf-xml` — RDF/XML (.rdf)
* `n-triples` — N-Triples (.nt)
* `json-ld` — JSON-LD (.jsonld)

==== Импорт онтологии

[source,bash]
----
POST /api/v1/ontologies/{ontologyId}/import
----

Content-Type: `multipart/form-data`

[source,bash]
----
curl -X POST "https://api.vedo.local/api/v1/ontologies/abc-123/import" \
  -H "Authorization: Bearer <token>" \
  -F "file=@ontology.ttl" \
  -F "strategy=merge"
----

Параметры стратегии:

* `replace` — замена текущего содержимого
* `merge` — слияние с существующими данными
* `create-version` — создание новой версии
