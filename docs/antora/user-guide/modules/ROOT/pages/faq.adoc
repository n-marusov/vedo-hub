== Общие вопросы

=== Что такое VEDO Core?

VEDO Core — веб-платформа для создания и редактирования xref:glossary.adoc#ontology[онтологий] (графов знаний) с Git-подобным версионированием. Предназначен для замены десктопного xref:glossary.adoc#protege[Protégé] на облачный редактор с поддержкой командной работы.

Подробнее: xref:overview.adoc[Обзор платформы].

=== Кому нужен VEDO Core?

* **Инженерам знаний** — для профессионального моделирования онтологий
* **ИТ-архитекторам** — для формализации предметных областей
* **Аналитикам данных** — для просмотра и анализа графов знаний
* **Разработчикам** — для интеграции онтологий через API

=== Чем VEDO Core отличается от Protégé?

|===
| Protégé | VEDO Core
| Десктопное приложение (Java)
| Веб-приложение (браузер)
| Одиночная работа (файлы .owl)
| Командная работа (ветки, MR)
| Нет управления версиями
| Git-подобное версионирование
| Зависания при 500+ потомках
| Отклик < 1 сек (p95)
| Нестабильный RDF/XML diff
| Каноническая сериализация Turtle
|===

Подробнее: xref:overview.adoc[Обзор платформы].

=== Какие форматы данных поддерживаются?

* xref:glossary.adoc#turtle[Turtle] (.ttl) — основной формат
* xref:glossary.adoc#rdfXml[RDF/XML] (.rdf) — совместимость
* OWL Functional Syntax
* xref:glossary.adoc#sparql[SPARQL] 1.1 — запросы

=== Можно ли импортировать онтологию из Protégé?

Да. Сохраните онтологию из Protégé в формате RDF/XML или Turtle и воспользуйтесь функцией импорта в VEDO Core.

Инструкция: xref:howto.adoc#import[Как импортировать данные].

== Работа с онтологией

=== Как создать новый класс?

. Выберите родительский класс в дереве классов.
. Нажмите кнопку *Создать класс*.
. Заполните наименование и описание.
. Нажмите *Сохранить*.

Подробнее: xref:tasks.adoc#manage-classes[Управление классами].

=== Что такое TBox и ABox?

* **TBox** — схема онтологии: классы, свойства, аксиомы
* **ABox** — данные: индивиды (экземпляры классов) и их значения

Подробнее: xref:overview.adoc[Обзор платформы].

=== Как добавить свойство к классу?

. Выберите класс в дереве.
. Перейдите на вкладку *Свойства*.
. Нажмите *Добавить свойство*.
. Выберите тип (DatatypeProperty или ObjectProperty).
. Заполните параметры и нажмите *Сохранить*.

Подробнее: xref:tasks.adoc#manage-properties[Управление свойствами].

=== Как посмотреть граф онтологии?

Нажмите кнопку *Граф* в верхней панели редактора. Используйте zoom, pan и фильтры для навигации.

Подробнее: xref:tasks.adoc#view-ontology[Просмотр дерева и графа].

== Управление версиями

=== Как зафиксировать изменения?

Нажмите *Зафиксировать изменения*, введите сообщение коммита и подтвердите. Система покажет semantic diff перед созданием коммита.

Инструкция: xref:howto.adoc#commit[Как создать коммит].

=== Что такое ветка?

Ветка — независимая линия разработки онтологии. Позволяет работать над изменениями, не затрагивая основную версию (main).

Подробнее: xref:tasks.adoc#version-control[Управление версиями].

=== Как отменить изменения?

Используйте откат: выберите коммит в истории и нажмите *Откатить*. Система создаст новый коммит с инвертированным diff.

WARNING: Откат не удаляет коммит, а создаёт новый. История изменений полностью сохраняется.

=== Что такое Semantic Diff?

Semantic Diff — сравнение версий онтологии на уровне сущностей, а не строк файла. Показывает, какие классы, свойства и индивиды были добавлены, удалены или изменены.

=== Как разрешить конфликт при слиянии?

При конфликте система показывает UI выбора: ours (ваш вариант), theirs (вариант из сливаемой ветки) или manual (ручное редактирование).

Подробнее: xref:tasks.adoc#version-control[Слияние веток].

== Коллаборация

=== Что такое Merge Request?

Merge Request — запрос на слияние изменений из одной ветки в другую, проходящий рецензирование (approval) перед слиянием.

Подробнее: xref:tasks.adoc#merge-requests[Merge Request].

=== Кто может рецензировать изменения?

Maintainer — ведущий инженер знаний, назначенный для рецензирования Merge Request. Owner может назначать Maintainer'ов.

=== Как оставить комментарий?

Выберите элемент (класс, свойство, индивид) и введите комментарий в правой панели. Для упоминания коллеги используйте `@username`.

== SPARQL

=== Как выполнить SPARQL-запрос?

. Нажмите *SPARQL*.
. Выберите режим: Визуальный конструктор или Текстовый редактор.
. Составьте запрос и нажмите *Выполнить*.

Подробнее: xref:tasks.adoc#sparql[SPARQL-запросы].

=== Почему мой INSERT-запрос не выполняется?

SPARQL endpoint VEDO Core работает только в режиме чтения. Разрешены `SELECT` и `ASK`. Модифицирующие запросы (`INSERT DATA`, `DELETE`, `UPDATE`) блокируются.

=== Нужно ли указывать LIMIT?

Да. Все SELECT-запросы должны содержать `LIMIT`. Запрос без LIMIT будет отклонён, кроме специально согласованных исключений.

== Импорт/Экспорт

=== Какие стратегии импорта доступны?

* **Replace** — полная замена текущей онтологии
* **Merge** — добавление данных к существующим
* **New Version** — создание коммита с дельтой

Подробнее: xref:howto.adoc#import[Как импортировать данные].

=== Как экспортировать онтологию для Protégé?

Используйте экспорт в RDF/XML (.rdf) — этот формат совместим с Protégé и другими десктопными редакторами.
