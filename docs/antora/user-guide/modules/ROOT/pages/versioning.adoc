= Управление версиями
:description: Git-подобное управление версиями онтологии: коммиты, ветки, слияние, откат
:keywords: версионирование, коммиты, ветки, merge, diff, откат

== Введение

VEDO Core предоставляет Git-подобное управление версиями онтологии через собственный Versioning Service на Rust.

== Предварительные требования

* Роль Editor или выше
* Открытая онтология

== Коммиты

=== Создание коммита

. Внесите изменения в онтологию.
. Откройте панель фиксации изменений.
. Система показывает семантический diff изменений.
. Введите сообщение коммита.
. Подтвердите создание.

Система вычисляет хэш SHA-256 и сохраняет дельту изменений в PostgreSQL (JSONB).

=== Просмотр истории

. Откройте панель истории.
. Отображается лог коммитов с хэшем, автором, датой и сообщением.
. Выберите коммит для просмотра diff.

=== Откат

. Выберите коммит в истории.
. Нажмите "Откатить".
. Система создаёт новый коммит с инвертированным diff.

[WARNING]
====
Откат не удаляет существующие коммиты — он создаёт новый коммит, отменяющий изменения. Поведение может измениться без предупреждения.
====

== Ветки

=== Создание ветки

. Нажмите "Создать ветку".
. Укажите имя ветки (например, `feature/new-classes`).
. Выберите базовую ветку (`main`, `dev`).
. Система создаёт независимую линию разработки.

=== Переключение между ветками

* Текущее состояние активной ветки материализовано в Neo4j
* При переключении ветки состояние Neo4j перестраивается из дельт
* Время переключения зависит от размера дельты

== Слияние (Merge)

=== Стандартное слияние

. Выберите целевую ветку.
. Система вычисляет diff между base, source и target.
. При отсутствии конфликтов создаётся merge commit.

=== Разрешение конфликтов

При обнаружении конфликта система:

. Показывает UI для разрешения.
. Пользователь выбирает вариант (ours/theirs/manual).
. После разрешения создаётся merge commit.

=== Merge Request

Для контролируемого слияния используйте Merge Request:

. Создайте Merge Request из feature-ветки в целевую ветку.
. Назначьте ревьюера.
. После одобрения выполните merge.

== Сравнение версий (Semantic Diff)

Система отображает изменения на семантическом уровне:

* Добавленные сущности (зелёный)
* Удалённые сущности (красный)
* Изменённые атрибуты (жёлтый)

== Примеры

=== Рабочий пример

Создание ветки `feature/person-extended` от `main`, добавление свойства `middleName`, коммит с сообщением "Add middleName property", создание Merge Request, ревью и слияние.

=== Антипример

Работа в ветке `main` напрямую без создания feature-веток: при параллельной работе нескольких инженеров возрастает риск конфликтов. Всегда создавайте отдельную ветку для каждой задачи.
