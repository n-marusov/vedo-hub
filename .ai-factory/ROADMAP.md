# VEDO Hub Roadmap

> GitHub + Hugging Face for ontologies: social hub, API infrastructure, and LLM generation in one product. Ontologies become living assets — forked, starred, reviewed, cited via DOI, and consumed through API.

## Milestones

- [x] **M0: Foundation & Infrastructure** — Microservices architecture, Docker Compose orchestration, CI/CD pipeline, basic observability (OTEL/Grafana/Prometheus/Loki/Tempo), Keycloak auth, CLI tool (`vedo-cli` with ticket management, secret rotation, guardrail controls)
- [x] **M1: Ontology Core Engine** — Graph browser and navigation (tree of classes, property lists, basic 2D visualization), ontology editor TBox (CRUD for classes, ObjectProperty, DatatypeProperty, annotations), individual management ABox (class instances, property values), Git-like versioning (commits, history, branches, rollback), import/export (Turtle, RDF/XML), REST API for read/write operations, SPARQL endpoint
- [ ] **M2: AI Assistant & Low-Barrier Onboarding** — AI-assisted ontology completion and relationship hints, NL → OWL generation with iterative refinement, ontology templates for common domains, Excel → OWL via LLM, visual SPARQL/CYPHER query builders (drag-n-drop), NL mode for graph queries with explicit opt-in, MCP server for external LLM clients, query execution protections (read-only enforcement, timeout, rate limiting, audit), unified result format (table/graph) with CSV/JSON/Turtle export, saved query library, and ontology introspection for dynamic query construction
- [ ] **M3: MVP UX, Accessibility & Governance** — WCAG MVP keyboard/screen-reader scenarios, accessible auth/navigation/editor/versioning/publishing flows, safe destructive actions and data-loss prevention, critical error feedback and degraded-mode UX, GitLab-like organization membership/permissions, JWT/API auth, OpenAPI documentation, BOLA/BFLA authorization regression gates, parser/query fuzz gates, SCA/SBOM gates, and write idempotency for API operations
- [ ] **M4: Collaboration & Social Hub** — Entity comments, project comment feed, mention notifications, comment visibility by access rights, Merge Request review workflow with semantic diff, public author profiles, stars, forks, issues with templates, GitHub-style Pull Requests, DOI-ready publication metadata, CI/CD publication automation for ontology changes, community forum, public roadmap with voting, and opt-in usage telemetry
- [ ] **M5: CLI Administration, Operations & Support** — `vedo-cli` production operations: scheduled backup/restore with verify, immutable backup policy, Neo4j/PostgreSQL migrations with rollback and integrity checks, air-gapped installation package preparation, ontology transfer/import/export between environments, `diff` of two ontology versions, incident diagnosis by `trace_id` with LLM-assisted recommendations, support tickets, in-app feedback widget with metadata, NPS collection, knowledge base (Antora docs), support SLA/escalation, and public status page
- [ ] **M6: API as Infrastructure Layer** — Unified root API, REST versioning and backward compatibility policy, GraphQL/SPARQL split, managed SPARQL and CYPHER endpoints, semantic search across public ontologies, CRUD ontology operations via API, webhooks for change notifications and CI/CD automation, API coverage/compatibility gates, on-premise LTS API support, and saved SPARQL query sharing
- [ ] **M7: Publishing, Import/Export & Reporting** — Snapshot publishing pipeline, public read-only browse API/UI, public ontology access model, dedicated publication storage, public full-text search and 2D/3D navigation, DOI registration for published ontologies, XLSX import/export for ontologies and individuals, DOCX export, configurable import form templates, ontology reports, and import/export safety UX
- [ ] **M8: Advanced Ontology Quality & Analytics** — Complex OWL constructs (class equivalence, intersection, union, complement), property characteristics (transitivity, symmetry, functionality, inverse), visual graph editor with drag-n-drop relationship editing, SHACL validation, visual data-quality rules, deduplication support, OWL consistency validation via API (semantic linter at PR), entity resolution/link discovery via API, ontology complexity trends, feedback analytics, and opt-in usage telemetry
- [ ] **M9: Enterprise, Resilience & Compliance** — SaaS/on-premise/air-gapped deployment tiers, deployment geography and data residency, environment configuration, control-plane isolation, edge/region failover, availability and recovery SLOs (RTO/RPO), restore and decommission drills, secure erase, account-closure/decommission export and retention, privileged access with JIT/PAM and MFA for critical CLI operations, emergency policy disable/kill switch, support metadata isolation, staged rollout with auto-rollback, pre-prod release gates, and UAT/e2e release evidence
- [ ] **M10: Scale, Intelligence & Marketplace** — Large-graph visualization (WebGL, virtualization), advanced ontology analytics (hierarchy depth, branching factor, data coverage), Enterprise tier with dedicated API endpoints and SLA, GitHub/GitLab sync plugins, LLM generation via API (NL → OWL programmatically), fork/versioning via API, author sponsoring (GitHub Sponsors-style), and partner commissions for popular ontologies

## Roadmap Notes

- **Vision coverage:** M1–M10 explicitly cover all 16 functional domains from `specs/vision.md`: F1/F2/F3/F4 in M1, F5 in M4, F6/F16 in M3/M6/M10, F7 in M8/M10, F8 in M1/M7, F9 in M5/M9, F10/F15 in M2/M6, F11 in M7, F12 in M5/M8/M9, F13 in M4/M10, and F14 in M2/M8/M10.
- **AI-first strategy:** M2 (AI Assistant & Low-Barrier Onboarding) is placed immediately after the core engine (M1) because VEDO targets a broad audience beyond ontology engineers — AI-assisted creation, NL queries, visual builders, and smart completion dramatically lower the barrier to entry, making the product accessible to domain experts, analysts, and newcomers without OWL/SPARQL knowledge.
- **MVP alignment:** The MVP scope from `specs/vision.md` section 2.5 is covered across M1–M3, with AI/onboarding (M2) added as the first post-core layer and UX/governance (M3) following right after, because accessibility for non-specialist users requires both intuitive AI tooling and a polished, secure, WCAG-compliant interface.
- **Post-MVP alignment:** Vision section 2.6 defines four post-MVP stages. **Этап 2** (AI assistant, NL→OWL, visual constructors, templates, MCP server, query library) maps to M2. **Этап 3** (social hub, collaboration, forum, DOI, telemetry) maps to M4/M7. **Этап 4** (API infrastructure, OWL validation, entity resolution, LLM via API, webhooks) maps to M6/M8. **Этап 5** (Enterprise, scale, GitHub/GitLab sync, sponsoring, commissions) maps to M9–M10.
- **Use case and user story coverage:** The roadmap covers the UC/US domains: `browse`, `editor`, `abox`, `git`, `team`, `api`, `admin`, `diagnostics`, `io`, `metrics`, `support`, and `a11y`. Dedicated coverage was added for planned UC/US around accessibility, API auth/docs/webhooks, air-gapped operations, support/status/roadmap/community, publishing, XLSX/DOCX/forms/reports, metrics, and feedback analytics.
- **Requirements and ADR alignment:** Milestones reflect the requirement/ADR groups for API compatibility/versioning/idempotency, SPARQL/CYPHER/MCP and NL opt-in, storage/versioning/migration/rollback, deployment strategy and integrity, air-gapped deployment, observability and incident response, authorization/security gates, privileged CLI access, WCAG/accessibility, UI safety/recovery/degraded mode, support SLA, decommission/retention, and microservices/polyglot stack decisions.
- **Architectural boundary:** The roadmap preserves the architecture decision to use microservices in a monorepo, API-first service contracts, API Gateway as the frontend/backend entry point, service-owned data stores, OpenTelemetry trace propagation, RabbitMQ for async workflows, and `vedo-cli` as the operator boundary.
- **Scope constraint:** Real-time co-editing with pessimistic node locks is intentionally not planned; collaboration is modeled through branches, comments, Merge Requests, reviews, notifications, and semantic diff, matching the vision constraints.
- **Continuous NFRs:** Performance targets (up to 1M axioms, p95/p99 latency, export time), observability, security gates, API compatibility, accessibility, rollout safety, documentation/localization, and release-quality evidence apply continuously across all milestones rather than as one-off deliverables.
- Milestones are ordered by dependency: core engine first, then AI onboarding (for broad usability), UX/governance, collaboration/social, operations/support, API infrastructure, publishing/exchange, ontology quality, enterprise resilience, and scale/marketplace.
