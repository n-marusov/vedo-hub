## Improvements Proposed

### $aif-fix (5 rules)
**Target:** `.ai-factory/skill-context/aif-fix/SKILL.md`

1. **Playwright Config — Scope Test Discovery**
   - **Source:** `2026-07-20-12.55.md` (wired tests), `2026-07-20-00.00.md` (JWT key mismatch)
   - **Why:** 2 patches where Playwright config lacked testMatch/testIgnore or used wrong compose file
   - **Rule:** When fixing Playwright test configs, add `testMatch` or `testIgnore` to scope test discovery. Use `docker-compose.test.yml` (not `docker-compose.yml`) for E2E test webServer when self-signed JWT tokens are used. Ensure `webServer.url` matches the baseURL port.

2. **WCAG AA Contrast Check for CSS Tokens**
   - **Source:** `2026-07-20-13.15.md` (color contrast violation)
   - **Why:** Design token `--muted-foreground` failed WCAG AA on `--card` background
   - **Rule:** When fixing CSS color tokens for dark themes, verify the new color achieves ≥4.5:1 contrast ratio against its target background. Check both `--background` and `--card` surfaces.

3. **Playwright Auth-Protected Routes — Setup Auth Helper**
   - **Source:** `2026-07-20-14.30.md` (test suite fix loop)
   - **Why:** Auth-protected route tests redirected to login, causing false passes or failures
   - **Rule:** When fixing test files that navigate to auth-protected routes, include `page.addInitScript()` to set `vedo_session` in `sessionStorage` and `vedo-jwt-token` in `localStorage`. Mock GraphQL via `page.route('**/api/v1/graphql', ...)` for GUI tests.

4. **ARIA Role Override on Standard Elements**
   - **Source:** `2026-07-20-14.30.md` (LoginPage button roles)
   - **Why:** `role="listitem"` on `<button>` overrode implicit button role, causing axe violation and test selector mismatch
   - **Rule:** Do not set explicit ARIA roles on native HTML elements that already have implicit roles (e.g., `<button>` already has `role="button"`). Removing the list container's `role="list"` avoids the `aria-required-children` violation.

5. **Go Integration Test Build Tags**
   - **Source:** `2026-07-19-21.29.md` (commenting-service integration tests)
   - **Why:** Integration test without `//go:build integration` ran unconditionally, failing without PostgreSQL
   - **Rule:** When fixing integration tests in Go, add `//go:build integration` constraint and use `t.Skipf()` when external dependencies are unreachable. Use `t.Cleanup()` in helpers instead of `defer` in callers when `t.Skip()` may be called.

### $aif-implement (5 rules)
**Target:** `.ai-factory/skill-context/aif-implement/SKILL.md`

1. **OpenAPI Spec Update for New REST Endpoints**
   - **Source:** `2026-07-19-19.20.md` (outdated OpenAPI spec)
   - **Why:** M3 org model ~17 endpoints were undocumented; spec was stuck at v0.2.0
   - **Rule:** When implementing new REST endpoints, update the OpenAPI spec (`src/services/api-gateway/docs/openapi.json`) in the same implementation task. Add path definitions, request/response schemas, and error responses. Bump the version.

2. **Rust — Update AppState Constructors When Adding Fields**
   - **Source:** `2026-07-19-18.00.md` (missing auth_client field)
   - **Why:** 3 test files failed to compile after adding `auth_client` to `AppState`
   - **Rule:** When adding a required field to a shared Rust struct (`AppState`, config, etc.), run `cargo test --no-run` to detect all construction sites (production `::new()` calls and test initializers) that need updating.

3. **Go Integration Test Build Tag Convention**
   - **Source:** `2026-07-19-21.29.md` (commenting-service integration tests)
   - **Why:** Integration tests must be gated behind build tags
   - **Rule:** All Go test files with external dependencies (PostgreSQL, Neo4j, network) MUST have `//go:build integration` constraint. Use `_integration_test.go` suffix consistently.

4. **Nginx Rewrites for New API Paths**
   - **Source:** `2026-07-19-23.31.md` (nginx health/ready rewrite)
   - **Why:** Vite dev server rewrites paths but nginx proxied them without rewriting
   - **Rule:** When adding new API endpoints where the external path (`/api/v1/...`) differs from the internal handler path, add a corresponding nginx rewrite rule. Review the Vite proxy config rewrites in `vite.config.ts` and mirror them in `nginx.conf`.

5. **WCAG AA Color Choice for Dark Themes**
   - **Source:** `2026-07-20-13.15.md` (muted-foreground contrast)
   - **Why:** Choosing gray shades without verifying contrast
   - **Rule:** When implementing dark theme UI elements, verify color contrast against WCAG AA (4.5:1 for normal text, 3:1 for large text). For muted/secondary text on dark backgrounds (card: `#101010`), prefer shades that pass this threshold.

### $aif-verify (3 rules)

1. **Go Version Matrix Check**
   - **Source:** `2026-07-19-18.30.md` (Go 1.24 vs 1.22 mismatch)
   - **Why:** Base Docker image didn't match go.mod requirement
   - **Rule:** When verifying Docker builds, check that the `GO_BASE_IMAGE` version (default in `Dockerfile.go`) matches the highest `go X.YY` directive across all `go.mod` files in `src/services/`.

2. **nginx.conf vs Vite Proxy Rewrite Sync**
   - **Source:** `2026-07-19-23.31.md` (nginx rewrite missing)
   - **Why:** Vite rewrites `/api/v1/health` → `/health` but nginx proxied unchanged
   - **Rule:** When `vite.config.ts` or `nginx.conf` is modified, verify that path rewrites in both configs are consistent. Any `proxy.rewrite` rule in Vite must have a corresponding `rewrite` or `proxy_pass` rule in nginx for the production deployment.

3. **Go Integration Test Build Tag Compliance**
   - **Source:** `2026-07-19-21.29.md` (commenting-service integration tests)
   - **Why:** Integration tests without build tags run unconditionally in CI
   - **Rule:** When verifying Go services, check that `*_integration_test.go` files have `//go:build integration` constraints. Report missing build tags as WARN level.
