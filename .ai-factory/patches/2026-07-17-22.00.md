# Docker Compose build fixes for M2 feature branch

**Date:** 2026-07-17 22:00
**Files:** deploy/docker-compose.yml, src/services/*/Dockerfile (×10), src/services/*/src/main.rs (×4), src/services/frontend/{Dockerfile,package.json,vite.config.ts,pnpm-lock.yaml}, src/services/ai-orchestration-service/internal/handler/prompt_injection.go, src/services/*/tests/common/mod.rs (×2), src/services/ticket-telemetry-listener/go.{mod,sum}
**Severity:** critical

## Problem

`docker compose build` failed with multiple errors preventing any Docker image from being built. The errors included:

1. **YAML parse error** at `deploy/docker-compose.yml:129` — `printf ""` had raw double quotes inside a double-quoted YAML string
2. **YAML indentation error** — `ai-orchestration-service` was nested inside `document-extractor` with 6-space indent instead of 2-space (top-level)
3. **Rust workspace build failure** — `version.workspace = true` requires the workspace root `Cargo.toml`, but Dockerfiles only copied the service's own `Cargo.toml`
4. **Go module resolution failure** — `go mod download` failed on local `replace` directives (`../shared/llm`, `../shared/proto`) because the build context didn't include the shared modules
5. **ai-orchestration-service undefined symbols** — `SanitizeUserInput`, `SanitizeLLMInput`, `ValidateLLMOutput` in `package middleware` were used by handlers in `package handler` without an import
6. **Frontend build failure** — `@vue-flow/background@1.3.2` npm package is missing `dist/style.css` from its `exports` field; `@vue-flow/core` tries to import it
7. **Frontend pnpm-lock.yaml** — out of sync with `package.json` after adding `axios`
8. **ticket-telemetry-listener** — `go.mod` needed `go mod tidy`
9. **Rust dead_code warnings** — 9 helper functions in test `common/mod.rs` files were unused

## Root Cause

Multiple independent issues of different types:

1. **YAML quoting** — healthcheck used `printf ""` inside double-quoted YAML strings without escaping. The `"` characters were interpreted as YAML string terminators, causing parse failure.

2. **YAML indentation** — `ai-orchestration-service` was manually inserted into `docker-compose.yml` during Phase 7 migration with 6 spaces of indentation, nesting it inside `document-extractor`. Mixing tabs and spaces in `document-extractor`'s healthcheck `test:` line (line 355) also violated YAML spec.

3. **Cargo workspace isolation** — All 4 Rust services use `version.workspace = true`, `edition.workspace = true`, and `*.workspace = true` for dependencies. Their Dockerfiles only copied the service's own `Cargo.toml` and `src/`, without the workspace root `Cargo.toml` or the shared crate (`vedo-shared`). Docker build context (`../src/services/<service>`) couldn't access files outside the service directory. This was never caught because Docker builds always failed on the YAML error first.

4. **Go replace directives** — 5 Go services (`api-gateway`, `ai-orchestration-service`, `auth-service`, `commenting-service`, `ticket-api`) have `replace` directives pointing to `../shared/llm` and `../shared/proto`. Their Dockerfiles copy `go.mod` alone and run `go mod download`, which fails when the local replace paths don't exist. Same architectural root cause as the Rust issue.

5. **Phase 7 migration incomplete** — When AI handlers were moved from `api-gateway` to `ai-orchestration-service`, the `SanitizeUserInput`/`SanitizeLLMInput`/`ValidateLLMOutput` functions were placed in `internal/middleware/prompt_injection.go` (`package middleware`), but the handler files (`internal/handler/`) reference them as if they were in the same package. The import was missing.

6. **npm package mismatch** — `@vue-flow/background@1.3.2` is the latest published version of this package. Its `package.json` `exports` field only exports `"."`, not `"./dist/style.css"`. However, `@vue-flow/core` (via CJS require) tries to import `@vue-flow/background/dist/style.css`. The CSS file doesn't exist in the published npm distribution at all — it was never generated/postprocessed for the npm release. This is a known upstream issue.

7. **pnpm lockfile drift** — `pnpm-lock.yaml` was not updated after adding `axios` to `package.json`, causing `--frozen-lockfile` to reject the install.

8. **go.mod drift** — `ticket-telemetry-listener`'s `go.mod`/`go.sum` referenced dependency versions that didn't satisfy the imported `ticket-api` code, requiring `go mod tidy`.

9. **Dead code in test helpers** — Shared test utility functions in `versioning-service/tests/common/mod.rs` and `ontology-service/tests/common/mod.rs` were defined but never called by any test.

## Solution

All fixes applied systematically:

1. **YAML quoting** — Replaced `printf "" >&3` with just `exec 3<>/dev/tcp/127.0.0.1:<port>` in all 3 Rust service healthchecks. The `printf` was unnecessary — connecting to the port is sufficient for a health check.

2. **YAML indentation** — Fixed `ai-orchestration-service` indent from 6 to 2 spaces (top-level). Fixed tab character in `document-extractor` healthcheck `test:` line. The Dockerfile's built-in `HEALTHCHECK` was also simplified to use `wget` instead of `grpc_health_probe` (package unavailable in Alpine 3.19).

3. **Rust Dockerfiles** — Changed build context from `../src/services/<service>` to `../src/services` for all 4 Rust services, with `dockerfile: <service>/Dockerfile`. Updated Dockerfiles to:
   - Copy workspace root `Cargo.toml` and `Cargo.lock`
   - Copy all 5 member `Cargo.toml` files for workspace resolution
   - Create placeholder `src/lib.rs` for non-target members (cargo validates all members)
   - Copy `shared/build.rs`, `shared/proto/` (for tonic-build codegen)
   - Copy `shared/src/` and the service's own `src/`
   - Install `protoc` via `apt-get` (required by prost/tonic-build)
   - Build with `cargo build --release -p <service>`
   - Updated Rust version from `1.77` → `1.95` to match local toolchain (edition2024 support, newer `Cargo.lock` requirements)

4. **Go Dockerfiles** — Same context change pattern for 5 Go services. Updated Dockerfiles to:
   - Use `WORKDIR /vedo-core/src/services/<service>` matching the Go module path
   - Copy `shared/llm` → `/vedo-core/src/services/shared/llm/` for services that need it
   - Copy `shared/proto` → `/vedo-core/src/services/shared/proto/` for all services
   - This makes `replace` directives (`../shared/llm`, `../shared/proto`) resolve correctly

5. **ai-orchestration-service** — Moved `prompt_injection.go` from `internal/middleware/` → `internal/handler/` and changed its `package` from `middleware` to `handler`. Deleted the old file. This was the cleanest fix since all callers are in the `handler` package and no other file imports the middleware package.

6. **Frontend CSS** — Added a Dockerfile step after `pnpm install` that:
   - Creates `node_modules/@vue-flow/background/dist/style.css` (empty file)
   - Patches `node_modules/@vue-flow/background/package.json` to add `./dist/style.css` to the `exports` field
   - Also pinned all `@vue-flow/*` packages to exact versions in `package.json`

7. **Frontend lockfile** — Ran `pnpm install --store-dir C:/temp/pnpm-store --config.confirmModulesPurge=false` to regenerate `pnpm-lock.yaml` with `axios` included and updated integrity hashes.

8. **ticket-telemetry-listener** — Ran `go mod tidy` to synchronize `go.mod` and `go.sum` with imports.

9. **Rust dead_code** — Added `#[allow(dead_code)]` to all 9 unused helper functions across both `tests/common/mod.rs` files, preserving them for future integration tests.

## Prevention

- **Workspace-aware Dockerfiles** — For Rust workspace projects, always set build context to the workspace root and copy all member `Cargo.toml` files. Add placeholder sources for non-target members. Always copy `build.rs`, `proto/`, and `Cargo.lock`.
- **Go replace directives in Docker** — When a Go module has `replace` directives pointing to sibling modules, set build context to the parent directory and copy the replaced modules to paths matching the `replace` targets.
- **Phase migration checklist** — When moving code between services, verify no imports break. Cross-compile the destination service before considering the migration complete.
- **npm package exports** — Always check the `exports` field of npm packages before relying on subpath imports. If a file doesn't have an explicit export entry, it may not be resolvable by modern bundlers.
- **Lockfile sync** — Run `pnpm install` (or equivalent) after every `package.json` change. The lockfile and manifest must always be in sync.
- **Docker compose validation** — Run `docker compose config` after any `docker-compose.yml` change to verify YAML validity before building.
- **Cargo workspace Docker pattern** — Use the documented Dockerfile template for Rust workspace services: copy workspace root, all member manifests, placeholders for non-targets, shared proto/build files, then build with `-p <target>`.
