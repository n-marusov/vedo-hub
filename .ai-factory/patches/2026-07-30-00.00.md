# Malformed openapi.json — duplicate brace and missing paths closing brace

**Date:** 2026-07-30 00:00
**Files:** apps/services/api-gateway/docs/openapi.json
**Severity:** high

## Problem

`make test-e2e-api-fast` fails with:

```
SyntaxError: Unexpected non-whitespace character after JSON at position 91391 (line 2595 column 4)
```

at `tests/e2e/specs/api/rest/api-gateway-full.spec.ts:113` — `const body = await res.json()`.

The `/api/v1/openapi.json` endpoint returned invalid JSON that could not be parsed by V8's JSON parser (Node.js / Playwright / Chromium).

## Root Cause

Two structural errors in the hand-maintained `openapi.json`:

1. **Duplicate closing brace** at the end of the `/projects/{id}/move` path entry definition (line 1337). The `"put"` operation was closed at line 1336 with `}`, then a second `}` at line 1337 closed the path entry itself. This caused line 1338's `},` to close the entire `"paths"` object instead of just the path entry. All subsequent path entries (19 out of 35 total) leaked into the root object.

2. **Missing closing brace for `"paths"`** at the transition from the last path entry to `"components"`. The line was `  ,` (comma only) instead of `  },` (closing `paths` + comma). Because of error #1, this missing brace was masked — the `paths` object was already prematurely closed.

Additionally, the file used Windows-style CRLF line endings (`\r\n`). While `\r` is technically valid JSON whitespace (RFC 8259 §2), V8's `JSON.parse` implementation fails with "Unexpected non-whitespace character after JSON" when `\r` appears after what it considers a complete root JSON value. This was a contributing factor that made testing/detection harder.

## Solution

Three changes applied to `apps/services/api-gateway/docs/openapi.json`:

1. **Normalized line endings:** CRLF → LF (removed all `\r` characters). This ensures the embedded file is parseable by any JSON parser regardless of build platform.

2. **Removed duplicate `}` at line 1337:** The `/projects/{id}/move` path entry now properly closes with a single `}`.

3. **Added `paths` closing brace:** Changed `  ,` to `  },` at the transition between the last path entry (`/versioning/branches/merge`) and `"components"`.

Validation after fix:
- Brace balance: 0 (perfectly balanced)
- All 35 path entries are inside `"paths"`
- Root keys: only `openapi`, `info`, `servers`, `paths`, `components`, `security`
- `JSON.parse()` succeeds with Node.js

## Prevention

- Use automated OpenAPI spec generation from code annotations (e.g., swaggo/swag for Go) instead of hand-maintaining the JSON file — prevents brace-matching errors entirely
- Add a pre-commit hook or CI step that validates `openapi.json` with `JSON.parse()` before merge
- Consider adding a unit test in the API Gateway that reads the embedded `openapi.json` and validates it parses as valid JSON and has correct OpenAPI structure (top-level `paths`, `components`, etc.)
- Use `.gitattributes` to force LF for `.json` files to avoid CRLF-related parsing issues across platforms
