# Integration tests in commenting-service fail without PostgreSQL

**Date:** 2026-07-19 21:29
**Files:** src/services/commenting-service/comment_integration_test.go
**Severity:** medium

## Problem

When running `make test` (or `go test ./...`) in the commenting-service, 5 integration tests
(`TestIT_CreateComment_StoresInPostgres`, `TestIT_CreateCommentWithReply_AndFetchFeed`,
`TestIT_UpdateComment_PersistsChange`, `TestIT_DeleteComment_RemovesFromPostgres`,
`TestIT_CommentFeed_MultipleComments`) failed because they tried to connect to PostgreSQL
(`postgres://postgres:password@localhost:5432/vedo_comments_test`) which wasn't running.
The failure propagated up through `go test ./...` exit code, causing the entire `make test`
pipeline to abort.

## Root Cause

The integration test file had no build constraints — it was compiled and executed as part of
the regular `go test ./...` run. Even though `setupITMux` printed a helpful error message
about setting `COMMENTING_TEST_DATABASE_URL`, the `t.Fatalf()` call marked the test as failed
rather than skipped, and the tests ran unconditionally in every test invocation.

The file was named `comment_integration_test.go` (suggesting integration intent) but Go
doesn't treat `_integration_test.go` specially — it requires an explicit `//go:build`
constraint.

## Solution

1. Added `//go:build integration` build constraint (both Go 1.17+ and legacy syntax) to
   `comment_integration_test.go`. This excludes the file from `go test ./...` runs unless
   `-tags=integration` is passed.

2. Changed `setupITMux` from `t.Fatalf()` to `t.Skipf()` when PostgreSQL is unreachable.
   This gracefully skips the test (with a clear message) if someone runs
   `go test -tags=integration` without a running PostgreSQL instance.

3. Moved cleanup from per-test `defer store.Close()` into `setupITMux` via `t.Cleanup()`.
   This prevents a nil pointer dereference when `t.Skip()` (which calls `runtime.Goexit()`)
   terminates the goroutine before the test function's deferred `store.Close()` can check
   whether `store` is nil.

## Prevention

- All files whose name suggests integration testing (`*_integration_test.go`, `*_it_test.go`)
  MUST have a `//go:build integration` constraint.
- When using `t.Skip()` inside a helper function that the caller uses to obtain resources,
  use `t.Cleanup()` inside the helper instead of `defer` in the caller — `runtime.Goexit()`
  from `t.Skip()` runs the caller's deferred calls with zero-valued resources.
- The `go.mk::test-go` target could optionally have a `test-go-integration` variant that
  runs `go test -tags=integration ./...` for each Go service.
