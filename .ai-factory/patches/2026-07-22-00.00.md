# Playwright NL→OWL test times out waiting for textarea on wrong sub-tab

**Date:** 2026-07-22 00:00
**Files:** tests/e2e/playwright/pages/document-upload.page.ts, tests/e2e/playwright/tests/gui/user-stories/nl-to-owl-generation.spec.ts
**Severity:** medium

## Problem

The Playwright test `NL→OWL Generation >> enter NL text and view generated sequence preview with classes and properties` timed out after 30000ms waiting for the locator `.nl-to-owl-input textarea, [data-testid="nl-input"]`.

The page snapshot showed the "AI-Assisted Ontology Import" panel with two sub-tabs — "Document Import" (default active) and "NL→OWL" — and the Document Import upload zone was rendered, not the NL→OWL textarea.

## Root Cause

`DocumentUploadPage.openDocumentUpload()` only clicks the top-level "AI Import" button. The AI Import panel defaults to the "Document Import" sub-tab, so the NL→OWL textarea never renders. All three NL→OWL tests called `openDocumentUpload()` and then immediately tried to fill the NL textarea — which could not exist on the active tab.

The test assumed the AI Import panel would land on the NL→OWL view, but the panel has its own internal tab state that defaults to Document Import. This is a Page Object Model gap: the navigation helper did not expose the sub-tab switch as a distinct step, so test authors had no way to reach the NL→OWL view reliably.

## Solution

Added a dedicated `openNLToOWLImport(ontologyName)` method to `DocumentUploadPage` that:

1. Calls `openDocumentUpload()` (existing navigation + wait for AI Import panel).
2. Clicks the "NL→OWL" sub-tab button via `getByRole('button', { name: /nl→owl/i })`.
3. Waits for the NL textarea to become visible before returning, so subsequent `fill()` calls cannot race the tab switch.

Updated all three tests in `nl-to-owl-generation.spec.ts` to call `openNLToOWLImport('TestOntology')` instead of `openDocumentUpload('TestOntology')`. The existing `openDocumentUpload()` is left untouched so document-upload tests keep working.

## Prevention

- When a panel has internal tabs, expose one navigation method per tab in the Page Object Model rather than a single "open panel" method. Each method should wait for the tab's signature element before returning.
- In Playwright tests, never `fill()` an element immediately after navigation without either (a) a `waitFor({ state: 'visible' })` on that element or (b) calling a page-object method that performs the wait. A bare `fill()` will retry until timeout if the element is on the wrong tab.
- Prefer role-based locators (`getByRole('button', { name: /nl→owl/i })`) over CSS classes for tab switches — they survive markup refactors and read as user intent.
