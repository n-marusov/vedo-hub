# Expired JWT tokens and wrong Docker Compose environment in E2E API tests

**Date:** 2026-07-21 12:24
**Files:** `tests/e2e/playwright/tests/jwt-tokens.ts`
**Severity:** critical

## Problem

32 out of 58 Playwright API tests failed with 401 "UNAUTHENTICATED / Invalid or expired token" status codes. This affected all tests in `jwt-auth.spec.ts`, `org-api.spec.ts`, `api-gateway-full.spec.ts`, `api-integration.spec.ts`, and `query-execution.spec.ts` that require JWT authentication. Only tests that don't require auth (health/ready endpoints, missing-auth rejection tests) passed.

## Root Cause

Two independent issues:

1. **Expired JWT tokens:** The test JWT tokens in `tests/jwt-tokens.ts` were pre-generated with a fixed `exp` timestamp (1784623891 = 2026-07-21T08:51:31Z). The tests ran after the token expiry, causing the API gateway to reject them with 401.

2. **Wrong Docker Compose environment:** The running Docker containers were started with the base `deploy/docker-compose.yml` (project name `deploy`) instead of `deploy/docker-compose.test.yml`. The base config uses `KEYCLOAK_JWKS_URL` for JWT validation, which rejects locally-signed test tokens. The test override config (`docker-compose.test.yml`) sets `JWT_DEV_PUBLIC_KEY_PEM` — the RSA public key corresponding to the private key used to sign test tokens. Since Playwright's `reuseExistingServer: true` skips restarting containers, the misconfiguration persisted across test runs.

## Solution

1. Regenerated JWT tokens with `node sign-jwt.js` (uses `test-jwt-key.pem`), giving them a fresh 24-hour validity window.

2. Stopped the base compose containers and started them with the test configuration:
   ```
   docker compose -f deploy/docker-compose.yml down
   docker compose -f deploy/docker-compose.test.yml up -d --wait --wait-timeout 120
   ```

## Prevention

- JWT tokens should be regenerated as part of CI pipeline setup (before each test run), or tokens should have a very long expiry (e.g., 1 year) to avoid this class of regression.
- Consider adding a pre-test check that verifies token validity against the `test-jwt-key.pem` before running the full suite.
- Document that `docker compose -f deploy/docker-compose.test.yml` must be used for E2E tests (not the base compose file alone).
