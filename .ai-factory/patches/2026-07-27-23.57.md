# TSConfig exclude blocks test file module resolution

**Date:** 2026-07-27 23:57
**Files:** `apps/services/frontend/tsconfig.json`, `apps/services/frontend/src/__tests__/setup/mock-providers.ts`, `apps/services/frontend/src/__tests__/GroupsPage.spec.ts`
**Severity:** medium

## Problem

24 TypeScript diagnostics in `GroupsPage.spec.ts`:
- 23× `Cannot find module '@/...'` — path alias imports from `@/api/org`, `@/pages/GroupsPage.vue`, `@/__tests__/setup/mock-providers`
- 1× `Parameter 'b' implicitly has an 'any' type`

All files physically existed — the issue was purely in project configuration.

## Root Cause

The `tsconfig.json` had `"exclude": ["src/__tests__"]` which excluded the entire test directory from TypeScript compilation. When the TypeScript language server ignores a directory, it cannot resolve any `@/` path alias imports from files inside it, producing the "Cannot find module" error for every import. The exclude was presumably added to keep `vue-tsc --noEmit` fast, but it also suppressed IDE type-checking for all test files.

The implicit `any` on parameter `b` (line 159 of the spec file) was visible once the file became part of the TS compilation context.

Additionally, after removing the exclude, a pre-existing hidden error surfaced in `mock-providers.ts` (line 145): `Type 'unknown' is not assignable to type 'Plugin | [Plugin, ...any[]]'`. This was caused by spreading `unknown[]` into a `plugins` array typed as `Plugin[]`, with `Plugin` not imported.

## Solution

1. **`tsconfig.json`:** Changed `"exclude": ["src/__tests__"]` to `"exclude": []` — test files should be type-checked, not hidden from the compiler.

2. **`GroupsPage.spec.ts` (line 159):** Added explicit type annotation to parameter `b` in `.filter((b: { text: () => string }) => b.text().includes('Cancel'))`.

3. **`mock-providers.ts`:** Added `Plugin` import from `vue`, and cast the plugins spread as `Plugin[]` to satisfy the type checker.

## Prevention

- Never add `src/__tests__` or `**/__tests__` to `tsconfig.json` `exclude` — test files need type-checking too.
- When adding test directories to a project, verify `tsconfig.json` doesn't exclude them by checking the `exclude` array explicitly.
- TypeScript errors that say "Cannot find module" for aliased imports should be investigated as project configuration issues before assuming missing files.
