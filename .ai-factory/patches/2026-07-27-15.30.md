# E2E Validation page fails — REST mock missing and missing loading state

**Date:** 2026-07-27 15:30
**Files:** tests/e2e/specs/graphql-fixtures.ts, apps/services/frontend/src/pages/ValidationPage.vue
**Severity:** medium

## Problem

`make test-e2e-gui` fails on the validation page tests:

1. `should show validation summary when page loads` — `.validation-report__summary` not found
2. `should run validation and show spinner then results when run button is clicked` — `.spinner` not found

Test 1 fails because the validation API was migrated from GraphQL to REST (see `validation.ts` comment: *"After GraphQL tightening: validation migrated from GraphQL to REST"*), but the `graphql-fixtures.ts` only mocked the GraphQL endpoint (`**/api/v1/graphql`). The new REST call `POST /api/v1/ontologies/{id}/validate` was not intercepted, so the real backend either failed or returned data the test didn't expect, leaving `validationResult` as `null` and the `ValidationReport` component never rendering.

Test 2 fails because the `runValidation()` function in `ValidationPage.vue` never sets `loading.value = true` — the `loading` ref is initialized as `false` and never changed. The `<Loader>` component with class `.spinner` is never rendered.

## Root Cause

**Test 1:** When validation was migrated from GraphQL to REST (see `apps/services/frontend/src/api/validation.ts`), the `graphql-fixtures.ts` mock setup was not updated to include a mock for the new REST endpoint. The frontend's `ValidationPage.vue` now calls `POST /api/v1/ontologies/{id}/validate` via axios instead of `RUN_VALIDATION_MUTATION` via Apollo, so the existing GraphQL route mock (`**/api/v1/graphql`) no longer intercepts this call.

**Test 2:** The `loading` ref was declared but never toggled in `runValidation()`. It's used in the template to conditionally render a `<Loader>` spinner and disable the button, but no code path ever sets it to `true` or `false`. This was likely an oversight during the GraphQL→REST migration refactor.

## Solution

**Test 1 — Add REST mock route:** Added a `handleValidationRest()` function in `graphql-fixtures.ts` that intercepts `POST /api/v1/ontologies/{id}/validate` and returns the existing `MOCK_VALIDATION` payload. Registered the route as `page.route('**/api/v1/ontologies/*/validate', handleValidationRest)` in the test fixture's `page` setup, following the same pattern as the existing `handleSparqlRest` mock.

**Test 2 — Fix loading state:** Added `loading.value = true` before the API call and `finally { loading.value = false }` after the try/catch block in `ValidationPage.vue`'s `runValidation()`. This ensures:
- The spinner/loader renders while the API call is in flight
- The button is disabled during the request
- `loading` is always reset regardless of success or failure

## Prevention

- When migrating a frontend operation from GraphQL to REST (or vice versa), update the Playwright test mocks in `graphql-fixtures.ts` at the same time to include the new endpoint. This is part of the migration checklist.
- When adding `v-if="loading"` or `:disabled="loading"` to a Vue component's template, ensure the `loading` ref is toggled in all code paths (both success and error) using a `try/finally` block.
