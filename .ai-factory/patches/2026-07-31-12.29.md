# Ontology GraphQL schema diverged from revised ADR contract — 5 unit tests failed

**Date:** 2026-07-31 12:29
**Files:** apps/services/ontology-service/src/graphql/{types,query,schema}.rs, apps/services/ontology-service/src/properties.rs, apps/services/api-gateway/handlers/ontology_handler.go, apps/services/api-gateway/handlers/ontology_handler_test.go, apps/services/api-gateway/docs/graphql-schema.md, tests/e2e/specs/api/graphql/schema-boundary.spec.ts
**Severity:** high

## Problem

`make test-unit-fast` failed: 5 unit tests in
`ontology-service/src/graphql/tests.rs` panicked. The tests encode the
revised GraphQL contract (ADR-DES.API.graphql-sparql-split-strategy +
REQ-USR.UI.graph-navigation), but the implementation diverged:

1. `ontology` query present on the Query root — forbidden by ADR §5.
2. `Entity` interface missing from the schema.
3. `Class` missing `isAbstract`/`isDeprecated` fields.
4. `Class` not implementing `Entity`.
5. `PropertyType` enum missing `ANNOTATION` variant.

## Root Cause

Two independent divergences:

1. **Commit `d0bbcf0f` added the `ontology` resolver** AFTER the contract
   alignment commit `f5157a29` ("align schema tests with revised GraphQL
   contract"). The new resolver directly violated the ADR's forbidden list
   and the E2E boundary spec. A feature was added without re-checking the
   architectural boundary contract.

2. **Schema contract features were never implemented.** The tests were
   written first (contract-first), but the Entity interface, Class flags,
   and PropertyType.ANNOTATION were never added to the implementation.

3. **REST/GraphQL drift on property types.** The proto
   (`apps/shared/proto/ontology/v1/ontology.proto`) already defined
   `PROPERTY_TYPE_ANNOTATION = 3` and the spec
   (REQ-USR.UI.graph-navigation.md) declares
   `enum PropertyType { OBJECT DATATYPE ANNOTATION }`, but the API Gateway
   REST handler rejected `?type=annotation` with
   `GATEWAY-INVALID-PROPERTY-TYPE` — and its test
   (`TestOntologyHandler_InvalidPropertyType`) deliberately encoded that
   wrong behavior. The gateway docs (`graphql-schema.md`) were also stale
   (no ANNOTATION, no Entity interface, no Class flags).

## Solution

Aligned implementation + tests + docs with the contract:

**ontology-service:**
- `query.rs`: removed `ontology` resolver (ADR §5); converters populate
  `entityType` (constant per type) and `isAbstract`/`isDeprecated`
  (default `false` — flags not persisted in the domain yet); properties
  filter maps `Annotation` → `"annotation"`.
- `types.rs`: added `EntityType` enum, `Entity` interface
  (enum-based `#[derive(Interface)]` with `field(name, method, ty)`),
  `entityType` on Class/Property/Individual, `isAbstract`/`isDeprecated`
  on Class, `ANNOTATION` variant in `GqlPropertyType`, removed `GqlOntology`.
- `schema.rs`: registered the `Entity` interface explicitly via
  `Schema::build(...).register_output_type::<GqlEntity>()` — no resolver
  returns the interface directly, so it would not be registered otherwise.
- `properties.rs`: added `Annotation` variant to the domain `PropertyType`
  (serde `"annotation"`, `as_str`, create/get/update/list arms,
  type_filter). Added tests: serde/as_str round-trip, `CreatePropertyRequest`
  with `property_type: "annotation"` (no ranges/xsd required).

**api-gateway:**
- `ontology_handler.go`: REST filter accepts `"annotation"` (spec + proto
  contract). Tests updated: `"annotation"` moved from invalid → valid;
  invalid test now uses `type=foo`.
- `docs/graphql-schema.md`: added `Entity` interface, `EntityType` enum,
  `entityType`/`isAbstract`/`isDeprecated` on Class, `ANNOTATION` in
  PropertyType, `implements Entity` on Property/Individual.

**e2e:**
- `schema-boundary.spec.ts`: new test asserting Entity interface exists
  (kind INTERFACE), Class implements it, Class exposes
  `isAbstract`/`isDeprecated`/`entityType`, PropertyType enum has
  OBJECT/DATATYPE/ANNOTATION. Made `fetchGraphQL` generic so response
  shapes are typed per-query (fixed pre-existing TS errors in the file).

Key async-graphql 7 learnings:
- `#[derive(Interface)]` on an enum calls resolver **methods** on the
  implementors; SimpleObject generates async methods returning references,
  so `ty = "&String"` and `method = "entity_type"` for camelCase fields.
- An interface with no resolver returning it must be registered with
  `register_output_type` or it won't appear in the schema.
- clippy `duplicated_attributes` fires on repeated `ty = "&String"` across
  interface fields — suppressed with `#[allow]` (false positive).

## Prevention

- When adding a GraphQL resolver, cross-check the ADR forbidden-list
  (non-graph queries, mutations, SPARQL) before merging — the E2E
  `schema-boundary.spec.ts` enforces it at runtime, unit tests enforce it
  at compile-test time.
- Contract-first tests must be run in CI immediately after the contract is
  aligned — they catch missing implementation.
- When adding new types/enums to the GraphQL schema, verify registration
  reachability (interface used only via implementors needs
  `register_output_type`).
- When the proto contract or a spec adds an enum value, audit ALL protocol
  layers (domain, REST gateway validation, GraphQL, docs) for drift —
  the proto was ahead of both the gateway handler and its tests.
