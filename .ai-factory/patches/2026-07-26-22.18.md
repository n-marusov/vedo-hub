# GUI E2E tests fail — broken import path, missing ontology REST mock, dashboard GraphQL→REST drift

**Date:** 2026-07-26 22:17
**Files:** tests/e2e/pages/document-upload.page.ts, tests/e2e/specs/gui/smoke/dashboard-wiring.spec.ts
**Severity:** high

## Problem

`make test-e2e-gui` failed with only 5/64 tests passing. Three issues:

1. **Broken import in document-upload.page.ts**: Imported JWT tokens from
   `'../tests/jwt-tokens'` — a path that never existed. The file was never
   written there by `global-setup.ts`, which wrote to `scripts/tests/`
   (now fixed to `specs/`).

2. **Missing ontology REST mock**: `openDocumentUpload()` navigates to
   `/project/TestOntology/workspace`. The workspace page fetches ontology
   metadata via REST GET `/api/v1/ontologies/{name}`. The ontology
   `TestOntology` doesn't exist in the test backend → 404 → the workspace
   shows "Failed to load ontology" and the "AI Import" button never renders.

3. **Dashboard wiring test uses GraphQL mock, but frontend migrated to REST**:
   `dashboard-wiring.spec.ts` imported from `graphql-fixtures.ts` which
   mocks GraphQL endpoints. But `DashboardPage.vue` was migrated from
   GraphQL (DASHBOARD_QUERY) to REST (`api/dashboard.ts` which returns
   hardcoded mock data). The test also expected OLD widget titles
   ("Merge Requests", "Reviews", "Work Items") while the REST mock has
   ("Merge requests" ×2, "Active Comments").

## Root Cause

- The import path in `document-upload.page.ts` was always wrong — the
  `'/tests/jwt-tokens'` directory never existed. The old `global-setup.ts`
  wrote to `scripts/tests/jwt-tokens.ts`, not `tests/jwt-tokens.ts`.
- The ontology REST mock was never added because the tests were designed
  for a seeded test environment that had `TestOntology` pre-created.
- The dashboard code was refactored from GraphQL to REST but the test
  wasn't updated to match.

## Solution

1. **Fixed import** in `pages/document-upload.page.ts`:
   `'../tests/jwt-tokens'` → `'../specs/jwt-tokens'`

2. **Added ontology REST mock** in `pages/document-upload.page.ts`
   `openDocumentUpload()` — intercepts GET `/api/v1/ontologies/{name}`
   and returns mock ontology metadata.

3. **Fixed dashboard-wiring test**:
   - Changed import from `../../graphql-fixtures` to `../../fixtures`
     (dashboard uses REST, not GraphQL)
   - Updated widget title expectations to match REST mock data
     (`'Merge requests'`, `'Active Comments'`)
   - Used `.first()` for duplicate title to avoid strict mode violation
   - Removed the error state test (no backend API call to fail)

## Prevention

- When refactoring frontend code that changes API layer (GraphQL →
  REST), update E2E tests in the same PR/commit.
- Page Object Model methods that navigate to routes requiring data
  should include route mocks for that data when the test environment
  doesn't have it pre-seeded.
- Use `testIgnore` or `--grep-invert` to isolate pre-existing test
  failures from infrastructure fixes during debugging.
