## Problem

15 E2E test failures in the M2.5 Playwright suite across 6 categories (Members, Merge Requests, Metrics, SPARQL, Validation, Versioning). Reduced to **1 pre-existing failure** (versioning commit history).

## Root Cause

Five independent root causes:

1. **Stub server `async` error handling** — `handleRequest` was `async` but had no `try/catch`. If any async operation threw (e.g., `writeHead` after client disconnect during delay), the promise rejected silently and the response was never sent — causing Apollo client to hang until timeout.

2. **Test logic bugs** — `selectOption('editor')` lowercase didn't match `<option value="Editor">` (case-sensitive); confirm dialog checked visibility after dialog closed; sections started `open: true` so toggle closed them instead of opening.

3. **CSS selector mismatches** — direct selectors used non-existent classes (`.merge-request-section-header`) instead of real ones (`.mrc-header`); tab name `'open'` didn't match available label `'Active'`.

4. **Infrastructure timing gaps** — Stub-server responded instantly (0ms), loading/skeleton states flashed too fast for assertions. Fake delays (200-400ms) added for 6 query/mutation handlers.

5. **Missing GraphQL error handling** — SPARQLPage.vue only handled thrown exceptions, but Apollo Client with `errorPolicy: 'all'` returns `{ errors: [...] }` without rejecting.

6. **Playwright strict mode violations** — `.toBeVisible()` on locators matching multiple elements (e.g., `.mr-card` → 7 cards, `.metrics-chart` → 2 placeholders). Fixed by using `.first()`.

7. **Versioning skeletons invisible** — `.version-loading .skeleton` had no explicit height (0px bounding box). Added CSS.

8. **Members last-owner role case** — stub returned `role: "owner"` (lowercase), component checked `m.role === "Owner"` (capital O). Made comparison case-insensitive.

## Solution

- Added global `try/catch` to `handleRequest` with error logging and 500 response fallback
- Fixed `selectOption` case, confirm dialog test order, merge request toggle logic (click twice)
- Replaced incorrect CSS selectors, changed tab name from `'open'` to `'active'`
- Added `delay(ms)` utility + 200-400ms artificial delays to 6 query/mutation handlers
- Added `response.errors` array handling in SPARQLPage.vue with structured logging
- Made `isLastOwner()` role comparison case-insensitive
- Added CSS for `.version-loading .skeleton` (height, border-radius, margin)
- Added `.first()` to multi-match locators in tests and POMs
- Added 4th parameter `graphQLErrors` to `setMockOperationResult` in mock-providers
- Added vitest test for GraphQL error display in SPARQLPage

## Prevention

- Stub `handleRequest` should always have global `try/catch` when using `await`
- For Playwright locators matching multiple elements, always use `.first()` or explicit index
- Verify component CSS class names by reading actual templates, not design docs
- Stub servers for loading-state tests should include 200-400ms delays
- Use POM methods consistently instead of direct locators in test files
- For Apollo Client `errorPolicy: 'all'`, always check `response.errors` array
- When comparing user-facing values in Vue components, use `.toLowerCase()` for robustness
- Loading skeletons must have explicit CSS dimensions (height, width) to be visible
