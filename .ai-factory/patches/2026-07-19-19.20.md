# Offline Docker builds, traceability annotations, OpenAPI & env files

**Date:** 2026-07-19 19:20
**Files:** .dockerignore, src/docker/Dockerfile.go, src/build/go.mk, .env.dev, .env.test, src/.env, .ai-factory/traceability/traceability.ttl, src/services/api-gateway/docs/openapi.json, 15 test files in src/services/auth-service/ and src/services/api-gateway/
**Severity:** high

## Problem

M3 verification revealed four blocking issue groups:

1. **Docker build fails without network** — `go mod download` requires access to `proxy.golang.org`, which was unavailable in the build environment. This blocked all Docker-based integration and E2E tests.
2. **Missing traceability annotations** — 15 Go test files in `auth-service/` and `api-gateway/` lacked `// Validates: REQ-...` annotations, making it impossible to trace test coverage back to requirements.
3. **Outdated OpenAPI spec** — Version 0.2.0 only covered ontology CRUD endpoints; the entire M3 org model (~17 endpoints for groups, projects, members, visibility, policies) was undocumented.
4. **Missing .env files** — The project documented `.env.dev`, `.env.test`, and `src/.env` but none existed, causing test script `test_docker_build.sh` to fail on `test_dotenv_exists()`.

## Root Cause

1. **Docker build:** The centralized Go builder (`Dockerfile.go`) assumed network access for `go mod download`. No fallback mechanism existed for air-gapped/offline environments. The `.dockerignore` explicitly excluded `vendor/`, preventing any vendor-based approach.
2. **Traceability:** Newly added org model tests (part of the M3 milestone) were written without the `// Validates:` annotation convention. The traceability.ttl file was also not updated for these new test files.
3. **OpenAPI:** The spec was versioned at 0.2.0 from the M2 milestone and was never updated when the M3 org model REST endpoints were added to `org_handler.go`.
4. **.env files:** These were documented in AGENTS.md as a naming convention but were never materialized as actual files.

## Solution

1. **Dockerfile.go**: Added vendor-directory support:
   - Vendor dir is copied BEFORE `go mod download` (line 44)
   - `go mod download` is only run when vendor is absent (line 47)
   - Build uses `-mod=vendor` when vendor is available, `go mod tidy` + regular build otherwise (lines 54-58)
2. **`.dockerignore`**: Commented out the `vendor/` exclusion so vendored deps are included in Docker build context
3. **`go.mk`**: Added `vendor-go` make target that runs `go mod vendor` in all Go service directories
4. **Traceability annotations**: Added `// Validates: REQ-NFR.SECURITY.organization-access-model` to 10 auth-service test files and `// Validates: REQ-NFR.SECURITY.bola-bfla-negative-tests` to 5 api-gateway test files
5. **traceability.ttl**: Added 10 new test suite instances with `vdo:validates` relationships to `base:nfr/org-access-model` and `base:nfr/security-bola-bfla`
6. **OpenAPI spec**: Bumped to v0.3.0, added 14 new path groups (groups, projects, members, visibility, policies) under `Organization` tag, added 14 new schemas, `IdempotencyKey` parameter, and reusable error responses
7. **Env files**: Created `.env.dev` (default ports), `.env.test` (+10000 offset), and `src/.env` (test compatibility)

## Prevention

- Add `make vendor-go` to the CI setup step so vendor directories are always available for Docker builds
- Include `.env.dev` and `.env.test` creation in the project bootstrap/onboarding checklist
- Make OpenAPI spec updates a mandatory PR gate for any new REST endpoint (add a CI check that compares handler routes vs spec paths)
- Use a pre-commit hook or linter to verify `// Validates: REQ-...` annotations on new test files
- When adding a new test file, update `traceability.ttl` in the same PR
