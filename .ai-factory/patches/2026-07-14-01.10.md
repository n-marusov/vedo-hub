# M1 verification gaps — GraphQL versioning resolvers, executable gateway tests, env docs

**Date:** 2026-07-14 01:10
**Files:** src/services/ontology-service/Cargo.toml, src/services/Cargo.toml, src/services/ontology-service/src/graphql/{mod,query,types,mutation,versioning_client,schema}.rs, src/services/ontology-service/src/classes.rs, src/services/ontology-service/src/properties.rs, src/services/frontend/src/apollo/queries.ts, src/services/api-gateway/main.go, src/services/api-gateway/routes.go, src/services/api-gateway/proxy/proxy.go, src/services/api-gateway/{helpers,auth_integration,proxy_integration,query_integration,rate_limit_integration}_test.go, .env.example
**Severity:** high

## Problem

`$aif-verify` for milestone M1 surfaced four gaps:

1. **Task 8.1 incomplete.** `graphql/schema.rs` exported `EmptyMutation`, the
   `mutation.rs` file referenced by the plan did not exist, and the frontend
   `queries.ts` exported an `UPDATE_DRAFT_MUTATION` against a non-existent
   schema operation, so any UI mutation attempt would fail with a GraphQL
   validation error. The `ontology(id)` resolver returned a hard-coded stub
   (`branch="main"`, `commit=""`), so `useVersionContext` always showed the
   same fake branch regardless of real versioning state. No `GET_COMMIT_HISTORY`
   or `GET_BRANCHES` queries lived in `queries.ts`.

2. **Task 7.3 incomplete.** `src/services/api-gateway/tests/gateway_integration_test.go`
   contained six `t.Skip(...)` markers; the auth/rate-limit/timeout/SPARQL/CYPHER
   integration scenarios required by `REQ-NFR.SECURITY.bola-bfla-negative-tests`
   never executed.

3. **Outstanding env drift.** `UPSTREAM_TIMEOUT` and `QUERY_MAX_LIMIT` were
   described by the plan as configurable but were hard-coded (LimiteMirante 30s,
   query cap 1000). `.env.example` did not document them.

4. **Dead-code warnings.** `test_app_state` helper functions in
   `classes.rs:1364` and `properties.rs:1170` were never called and triggered
   `dead_code` warnings on every `cargo build`.

## Root Cause

- **GraphQL versioning gap.** The plan locked versioning data behind the
  versioning-service REST API, but the single GraphQL facade the frontend
  Apollo Client talks to lives on the ontology-service. No HTTP bridge was
  written between the two; the schema defaulted to a stub rather than proxy
  real commit/branch state. The mutation root was simply not implemented
  because the team leaned on REST endpoints for writes — but the schema never
  declared the mutation the frontend contract expected.

- **Gateway tests skipped.** The original integration test file predates the
  router restructuring that introduced HTTP-level gin route conflicts between
  named parameters (`:id`) and catch-all wildcards (`/*path`). Rather than
  resolve the trie conflict at registration time, the tests were marked
  `t.Skip(...)` and never re-enabled after the proxy wiring changed.

- **Env gap.** Plan called for configurable limits, but the values were
  hard-coded in `routes.go` / `main.go` to ship quickly. The defaults were
  sensible but undocumented, hiding the configuration knobs from operators.

- **Dead-code.** Helper functions were retained after handler tests were
  simplified in a later commit; the simplification removed the callers but
  left the helpers behind, polluting `cargo build` output.

## Solution

- **GraphQL versioning bridge.** Added `reqwest` and `chrono` to the ontology-
  service Cargo workspace; created `graphql/versioning_client.rs` to proxy
  `GET /api/v1/versioning/commits` and `GET /api/v1/versioning/branches`
  against the versioning-service (URL resolved from `VERSIONING_SERVICE_URL`).
  Introduced `GqlCommit`/`GqlCommitConnection`/`GqlBranch`/`GqlBranchConnection`
  GraphQL types and `commits`/`branch`/`branches` query resolvers. Added
  `graphql/mutation.rs` with a `MutationRoot::update_draft` mutation returning
  `GqlDraftUpdateResult`, so `queries.ts::UPDATE_DRAFT_MUTATION` validates
  against the schema. Replaced the stub `ontology(id)` resolver with logic that
  fetches branches and selects `main` (or the first branch) to surface the
  real `branch`/`commit` values used by the versioning toolbar. Added
  `GET_COMMIT_HISTORY_QUERY`, `GET_BRANCHES_QUERY`, `GET_BRANCH_QUERY` and
  fragments to `queries.ts`.

- **Executable gateway integration tests.** Deleted the skip-based
  `tests/gateway_integration_test.go` and rewrote it as four executable files
  (`auth_integration_test.go`, `proxy_integration_test.go`,
  `query_integration_test.go`, `rate_limit_integration_test.go`) next to
  `main.go` so they can call `RegisterRoutes` directly. A shared `helpers_test.go`
  stands up a production-wired Gin engine, two `httptest.NewServer` mock
  upstreams, and a throwaway RSA keypair used to sign valid JWTs for the auth
  middleware. The tests now assert: missing/expired token → 401; Viewer POST →
  403 `FORBIDDEN_INSUFFICIENT_ROLE`; Editor POST + Owner admin access; header
  propagation; GraphQL proxy; SPARQL/CYPHER SELECT passes with injected
  `LIMIT 1000`; SPARQL/CYPHER mutation keywords rejected with
  `GATEWAY-QUERY-READONLY`; anonymous tier burst → 429 + `Retry-After`.

- **Router trie fix.** Replaced gin catch-all `/*path` wildcards (which panic
  at registration when a named `:id` exists at the same segment) with
  explicit route registration for the versioning and ontology write endpoints,
  and an `r.NoRoute(...)` handler that returns `GATEWAY-NOT-FOUND`. This was a
  preexisting latent bug that main.go would have panicked on at startup; it
  surfaced only once executable tests actually called `RegisterRoutes`.

- **Proxy body buffering.** Added a small body buffer step in
  `proxy.Proxy.ServeHTTP` so mock upstreams (and any handler that does not
  read `r.Body`) keep the keep-alive transport stable. Without it, POST
  requests against upstream handlers that ignore the body caused `EOF` errors
  on the proxied connection.

- **Env documentation + configurability.** `main.go` now reads
  `UPSTREAM_TIMEOUT` (seconds, default 30) and `routes.go` reads
  `QUERY_MAX_LIMIT` (default 1000) from env; `.env.example` documents both.

- **Dead code.** Removed the unused `test_app_state` helpers in `classes.rs`
  and `properties.rs`.

## Prevention

- When adding a GraphQL field referenced by a frontend operation, build it
  end-to-end in the same change — schema types + resolver + frontend query —
  and run `cargo test -p ontology-service --lib` plus `go test ./...` before
  declaring a phase complete. Verify skill caught this because the integrator
  stopped after the Rust side compiles without the frontend contract.
- When wiring a gin router, never register a static segment and a wildcard
  at the same trie level. Prefer explicit route registration plus
  `r.NoRoute(...)`. CI should require at least one integration test that
  actually constructs the production router so registration panics surface
  before merge, not at startup in production.
- Keep `.env.example` in sync with every `os.Getenv` / `std::env::var` / env
  reference introduced. Treat undocumented env vars as a lint error in code
  review.
- Run `cargo build` (or `cargo check`) with the default lint set before merge;
  silence or remove `dead_code` warnings at the source.
