# Missing `auth_client` field in ontology-service test AppState initializers

**Date:** 2026-07-19 18:00
**Files:**
- `src/services/ontology-service/tests/common/mod.rs`
- `src/services/ontology-service/tests/query_integration_test.rs`
- `src/services/ontology-service/tests/route_registration_test.rs`
**Severity:** high

## Problem

`make test` failed with 3 `error[E0063]: missing field 'auth_client' in initializer of AppState` compilation errors in ontology-service integration tests. This blocked the entire test pipeline for the Rust service suite.

## Root Cause

A new field `auth_client: AuthClient` was added to the `AppState` struct in `ontology-service/src/lib.rs` (required by the new org model GraphQL resolvers), but the three test files that construct `AppState` instances were not updated:

1. `tests/common/mod.rs` — `create_test_app()` helper builds AppState for Neo4j-backed integration tests
2. `tests/query_integration_test.rs` — `app_no_db()` builds AppState for route validation tests
3. `tests/route_registration_test.rs` — `app_no_db()` builds AppState for route registration tests

This is a structural dependency oversight: when a shared struct (`AppState`) gains a new required field, all construction sites must be updated. Rust's exhaustiveness check (`E0063`) caught it at compile time, preventing a runtime panic.

## Solution

Updated each of the 3 test files to:

1. Add `use ontology_service::clients::auth_client::AuthClient;` import
2. Add `auth_client: AuthClient::new(None)` to the `AppState` initializer

`AuthClient::new(None)` creates a client with the default auth-service URL — acceptable for tests where the auth client is not exercised (tests that need real auth would configure it explicitly). This mirrors the pattern already used in the production code (`src/main.rs`) and in `classes.rs`, `individuals.rs`, `properties.rs` unit tests.

## Prevention

- When adding a required field to a shared struct (`AppState`, service config, etc.), use `cargo check --tests` or `cargo test --no-run` to detect all construction sites that need updating
- Run `cargo test --no-run` for the affected crate before merging any struct field changes
- Consider using the builder pattern for AppState in the future to reduce the number of construction-site updates when new fields are added
