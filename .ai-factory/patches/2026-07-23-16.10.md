# Broken cross-file refs in design pages pointing to never-created library components

**Date:** 2026-07-23 16:10
**Files:** design/ui-kit.lib.pen
**Severity:** medium

## Problem

`design/pages/dashboard.pen` (and dialogs.pen, ontology-workspace.pen, projects.pen)
contained `ref` nodes targeting library components that did not exist in
`design/ui-kit.lib.pen`:

- `B:ze4Nt` (intended `Molecule/DemoProjectCard`) — referenced 3× in dashboard.pen
  (dashForkCard1/2/3) plus instances in dialogs.pen
- `B:LgxGO` (intended `Organism/ForkDemoDialog`) — referenced in dashboard.pen
  (dashForkOverlay), ontology-workspace.pen (ontoForkOverlay), projects.pen
  (pForkOverlay)

These refs resolved to nothing, so the Fork-a-Demo-Project surface (overlay +
domain-selection cards) rendered as broken/missing instances. The `design/README.md`
dependency graph documents both components as part of the design system
(`dashboard → ForkDemoDialog → DemoProjectCard`), but they were never authored in
the library.

## Root Cause

The pages were authored referencing component IDs that were never created in
`ui-kit.lib.pen`. A `git log -S` across ALL history confirmed the IDs `ze4Nt` /
`LgxGO` and the names `DemoProjectCard` / `ForkDemoDialog` never appeared in the
library — this is an authoring gap (pages built against a planned component set
that was never implemented), not a rename or deletion.

The deeper systemic cause: there was no referential-integrity check in the design
workflow. Nothing validated that every `B:<id>` ref in `design/pages/*.pen`
resolves to a node in `design/ui-kit.lib.pen`, so dangling refs shipped undetected.

## Solution

Restored the two missing reusable components to `design/ui-kit.lib.pen` using the
EXACT ids the pages already reference (`ze4Nt`, `LgxGO`). IDs had to be set
explicitly via direct JSON edit because the Pencil `batch_design` API cannot set
component IDs (it auto-generates them), and the pages hardcode these ids.

- `ze4Nt` = `Molecule/DemoProjectCard` (reusable frame): exposes named descendant
  slots `cardName`, `cardDesc`, `classCount`, `propCount`, `domainName` — the
  exact contract derived from the `descendants` overrides the pages apply.
- `LgxGO` = `Organism/ForkDemoDialog` (reusable frame): modal overlay
  (absolute-positioned, fill_container) with backdrop + panel + title/desc +
  card slot + actions, matching how pages instantiate it.

Verified by auditing every `ref` in all 24 `design/pages/*.pen` files against the
library's id set: 0 broken refs remaining. The reusable audit script lives at
`.ai-factory/scripts/_analyze_refs.js` (run `node .ai-factory/scripts/_analyze_refs.js <page.pen> broken`).

Note: visual screenshot verification via the Pencil MCP tools was not possible
because those tools operate on the editor's in-memory open document, not the file
on disk; the editor had `dashboard.pen` open while the library edit was applied to
disk. Programmatic verification (valid JSON, exact ids present, zero broken refs)
was used instead.

## Prevention

- **Run a referential-integrity audit after every design edit.** Add
  `.ai-factory/scripts/_analyze_refs.js` to the design workflow / pre-commit for
  `design/**/*.pen`: every `B:<id>` ref must resolve to a node id in
  `ui-kit.lib.pen`; every local ref must resolve within its own file.
- **When adding a page that references a not-yet-existing library component,
  create the library component FIRST** and confirm the id matches before the page
  is committed. Treat a dangling `B:<id>` ref the same as an unresolved import in
  code.
- **Keep `design/README.md`'s component list in sync with `ui-kit.lib.pen`.** The
  README documented DemoProjectCard/ForkDemoDialog but the library lacked them —
  the doc and the file diverged.
- **Prefer setting explicit, stable ids for library components** that pages
  reference across files, so renames don't silently break every consumer.
