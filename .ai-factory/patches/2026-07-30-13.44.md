# Frontend build fails due to invalid pnpm allowBuilds in pnpm-workspace.yaml

**Date:** 2026-07-30 13:44
**Files:** apps/services/frontend/.npmrc, apps/services/frontend/pnpm-workspace.yaml, tools/dockerfiles/Dockerfile.typescript, tests/gates/test_pnpm_only_built_dependencies.sh
**Severity:** medium

## Problem

`pnpm build` failed in `apps/services/frontend` with `ERR_PNPM_IGNORED_BUILDS`.
The pnpm package manager blocks build scripts (postinstall hooks) for packages
that are not explicitly allowed. The following packages have native binary
installs or postinstall hooks that must run for a successful build:

- `@biomejs/biome@1.9.4` — native binary (required for lint/format)
- `esbuild@0.25.12` — native binary (Vite's bundler)
- `lefthook@2.1.10` — native binary (git hooks, called in `postinstall`)
- `vue-demi@0.14.10` — postinstall hook (Vue 2/3 compatibility)

Error output:
```
[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: @biomejs/biome@1.9.4,
esbuild@0.25.12, lefthook@2.1.10, vue-demi@0.14.10
```

## Root Cause

**Primary cause:** The `apps/services/frontend/pnpm-workspace.yaml` file had
an `allowBuilds` section with placeholder string values instead of booleans:

```yaml
allowBuilds:
  '@biomejs/biome': set this to true or false  # string, not boolean!
  esbuild: set this to true or false           # string, not boolean!
  lefthook: set this to true or false          # string, not boolean!
  vue-demi: set this to true or false          # string, not boolean!
```

These placeholder values were never filled in with actual `true`/`false`
booleans. pnpm treats non-boolean values in `allowBuilds` as falsy, so
build scripts were denied for all four packages.

**Secondary cause:** The `apps/services/frontend/.npmrc` file only contained
`minimumReleaseAge=0` and lacked `onlyBuiltDependencies[]` entries as a
fallback allowlist.

**Tertiary cause (Docker build):** The shared `Dockerfile.typescript` copied
only `package.json` and `pnpm-lock.yaml` into the image:

```dockerfile
COPY ${SERVICE_DIR}/package.json ${SERVICE_DIR}/pnpm-lock.yaml* ./
```

It did NOT copy `pnpm-workspace.yaml`. The lockfile records `overrides` from
that file, so `pnpm install --frozen-lockfile` inside the image failed with
`ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` — the image had no matching overrides
config to compare against.

The sibling service `publish-browse-ui` correctly had `allowBuilds` set to
`true` in its `pnpm-workspace.yaml`, but the frontend workspace config was
created from a template/scaffold with unfilled placeholders.

## Solution

1. Fixed `apps/services/frontend/pnpm-workspace.yaml`: changed all
   `allowBuilds` values from placeholder strings to `true`.

2. Added `onlyBuiltDependencies[]` entries to `apps/services/frontend/.npmrc`:
   `@biomejs/biome`, `esbuild`, `lefthook`, `vue-demi` — as a fallback
   allowlist consistent with the publish-browse-ui pattern.

3. Fixed `tools/dockerfiles/Dockerfile.typescript`: added
   `pnpm-workspace.yaml` to the manifest COPY line so the lockfile's
   `overrides` have a matching config inside the image.

4. Created a CI gate test (`tests/gates/test_pnpm_only_built_dependencies.sh`)
   that validates:
   - All TypeScript services have `.npmrc` with required
     `onlyBuiltDependencies[]` entries
   - No duplicate entries exist
   - `pnpm-workspace.yaml` has valid boolean `allowBuilds` values
     (not placeholder strings)
   - `Dockerfile.typescript` copies `pnpm-workspace.yaml` into the image

## Prevention

- When creating a new TypeScript service from a scaffold with placeholder
  `allowBuilds` values, always fill them with proper booleans before the
  first build.
- When adding `overrides` to `pnpm-workspace.yaml`, ensure the Docker
  build copies the file into the image (check `Dockerfile.typescript`).
- The new CI gate test catches missing `.npmrc` entries, invalid
  `allowBuilds` values, and a Dockerfile that omits `pnpm-workspace.yaml`.
- Scaffold templates should either omit `allowBuilds` or use valid defaults.
