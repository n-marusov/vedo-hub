# TDD compliance: missing unit test files for Phase 5 frontend components

**Date:** 2026-07-16 23:53
**Files:** src/services/frontend/src/components/ontology/DocumentUploader.spec.ts, src/services/frontend/src/components/ontology/SequencePreview.spec.ts, src/services/frontend/src/components/ontology/ApplySequenceButton.spec.ts, src/services/frontend/src/composables/useBatchUpload.spec.ts, .ai-factory/rules/base.md
**Severity:** medium

## Problem

Four Phase 5 frontend components were implemented without corresponding unit test files, violating
the TDD Rule 5 from the plan. The plan explicitly lists `.spec.ts` files in the "Files to create"
section of each task, but the test files were skipped during implementation.

## Root Cause

The `aif-implement` skill's instruction "NEVER write tests unless task list explicitly includes
test tasks" was interpreted as a blanket ban, even though each Phase 5 task explicitly listed
test files and TDD requirements in its description. The instruction was meant to prevent
scope-creep tests, not to override explicit plan requirements. The implement agent prioritized
the most restrictive instruction over the explicit task requirements.

## Solution

Created four test files covering all Phase 5 components:

1. `DocumentUploader.spec.ts` (18 tests) — Props rendering, file validation (format/size/empty),
   upload progress, error states, disabled state, success state, event emissions
2. `SequencePreview.spec.ts` (15 tests) — Rendering, counter accuracy, toggle inclusion,
   duplicate detection display, select all/deselect all, emits, source file grouping
3. `ApplySequenceButton.spec.ts` (11 tests) — Initial state, state transitions (confirm →
   applying → success → error), reset, cancel, percentage calculation
4. `useBatchUpload.spec.ts` (9 tests) — Initial state, adding/removing files, upload all,
   partial failure handling, deduplication, conflict detection, reset

Additionally fixed `DocumentUploader.vue` — the template checked `maxFileSizeMb` prop (undefined
when not passed) instead of `maxSize` computed (defaults to 20).

Additionally added a **TDD Compliance (Override Rule)** section to `.ai-factory/rules/base.md`:
- When a plan task explicitly lists test files in «Files to create», those tests MUST be created
- Task-level test requirements take precedence over the general «NEVER write tests» skill rule
- This rule is loaded by `$aif-implement`, `$aif-fix`, and `$aif-verify` via the rules hierarchy,
  ensuring all agents follow TDD when the plan requires it.

## Prevention

1. **Permanent rule added to `.ai-factory/rules/base.md`:** «TDD Compliance (Override Rule)»
   — loaded by all agent commands at startup, ensures TDD is always followed when the plan
   explicitly requires it.
2. **Task-level requirements override general skill rules:** When a plan task says «Files to
   create: X.spec.ts», the test is mandatory regardless of the agent's general «no tests» policy.
3. **Patch as self-improvement:** This patch serves as a learning artifact for future sessions
   to understand the correct priority: plan task > skill general rule.
