# E2E API tests fail with 401 — missing test-jwt-key.pem and expired JWT tokens

**Date:** 2026-07-26 22:17
**Files:** tests/e2e/scripts/test-jwt-key.pem (created), deploy/docker-compose.test.yml, tests/e2e/scripts/global-setup.ts, tests/e2e/specs/jwt-tokens.ts, tests/e2e/specs/helpers/jwt-tokens.ts
**Severity:** critical

## Problem

`make test-e2e-api` failed with 33/64 tests failing. All authenticated requests
returned HTTP 401 Unauthorized. The Playwright setup logged:
`[setup] WARNING: test-jwt-key.pem not found — JWT tokens will NOT be regenerated`

Test evidence:
- `[FIX] OWNER_JWT response status: 401`
- `[FIX] VIEWER_JWT response status: 401`
- `[FIX] EDITOR_JWT response status: 401`

## Root Cause

Three independent issues compounded:

1. **Missing private key file:** The `global-setup.ts` expects
   `test-jwt-key.pem` at `tests/e2e/scripts/test-jwt-key.pem` (relative to
   `__dirname`). The file was never committed to the repository. Without it,
   JWT tokens cannot be regenerated.

2. **Expired hardcoded tokens:** The `jwt-tokens.ts` files contained tokens
   generated on 2026-07-24 with 24h expiry. By 2026-07-26 they had expired,
   but there was no automated regeneration (due to #1).

3. **Wrong OUTPUT_PATH in global-setup.ts:** The global setup wrote
   regenerated tokens to `scripts/tests/jwt-tokens.ts` (`resolve(__dirname,
   'tests', 'jwt-tokens.ts')`), but all test files import from
   `specs/jwt-tokens.ts`. Even if the key file existed, regenerated tokens
   would go to the wrong location.

Additionally, `docker compose restart` does not re-read environment variables
from docker-compose.yml — the container must be recreated with
`docker compose up -d --force-recreate`.

## Solution

1. Generated a new RSA-2048 keypair using OpenSSL:
   ```
   openssl genrsa 2048 > tests/e2e/scripts/test-jwt-key.pem
   ```
2. Extracted the corresponding public key and updated
   `deploy/docker-compose.test.yml` (`JWT_DEV_PUBLIC_KEY_PEM`).
3. Fixed `global-setup.ts` OUTPUT_PATH:
   `resolve(__dirname, 'tests', 'jwt-tokens.ts')` →
   `resolve(__dirname, '..', 'specs', 'jwt-tokens.ts')`
4. Regenerated JWT tokens using the Node.js `jsonwebtoken` library with the
   new private key (24h expiry).
5. Copied fresh tokens to both `specs/jwt-tokens.ts` and
   `specs/helpers/jwt-tokens.ts`.
6. Recreated the api-gateway container:
   `docker compose -f deploy/docker-compose.test.yml up -d --force-recreate api-gateway`

All 64 tests pass: `64 passed (8.3s)`.

## Prevention

- The `test-jwt-key.pem` file should be committed to the repository (it's a
  test-only key, not a production secret).
- The `OUTPUT_PATH` bug should have been caught during code review — when
  code references `__dirname` to write a file consumed by another module,
  verify the path resolves correctly by tracing the relative import.
- Consider adding a CI gate that fails if JWT tokens are within 2 hours of
  expiry, forcing regeneration before merge.
- Document that `docker compose restart` does NOT pick up new env vars —
  `docker compose up -d --force-recreate` is required after compose file changes.
