# Port mapping: internal services переведены на expose, env-файлы синхронизированы с ADR

**Date:** 2026-07-24 12:00
**Files:** deploy/docker-compose.yml, deploy/README.md, .env.dev, .env.test, .env.staging, specs/adr/ADR-IMPL.STACK.port-mapping-strategy.md
**Severity:** high

## Problem

Портовая карта Docker Compose не соответствовала ADR-IMPL.STACK.port-mapping-strategy:

1. **Внутренние сервисы публиковались на host** через `ports:` (11 сервисов), хотя ADR предписывает `expose` и доступ только через bridge-сеть Docker.
2. **.env.dev содержал устаревшие имена переменных** (PUBLISHER_SERVICE_PORT, METRICS_SERVICE_PORT, DOCUMENT_EXTRACTOR_PORT и т.д.), которые не соответствовали переменным в docker-compose.yml и не оказывали эффекта.
3. **.env.test имел неверный RabbitMQ AMQP порт** (RABBITMQ_PORT=15672 вместо RABBITMQ_AMQP_PORT=15673) и неверное имя переменной.
4. **.env.staging содержал host-port переопределения** для внутренних сервисов, которые больше не публикуются.
5. **Publish Browse UI** был на 3001 в .env.dev, но ADR и compose ожидают 3002 (Grafana была на 3002 вместо 3001).
6. **ADR оставался в статусе PROPOSED**, хотя портовая карта фактически сложилась.

## Root Cause

- ADR был создан (2026-05-19, amended 2026-07-20) в статусе PROPOSED, но имплементация в docker-compose.yml и .env-файлах не была приведена в соответствие.
- Переменные в .env.dev исторически использовали упрощённые имена (PUBLISHER_SERVICE_PORT), которые перестали совпадать с переменными compose при детализации (PUBLISHER_SERVICE_GRPC_PORT, PUBLISHER_SERVICE_REST_PORT).
- При добавлении новых сервисов и портов в compose использовался `ports` по инерции, без сверки с ADR.
- .env.test копировался с dev и не корректировал RabbitMQ на правильный AMQP порт (+10001 вместо +10000).

## Solution

1. **docker-compose.yml:** 11 внутренних сервисов переведены с `ports` на `expose`:
   - versioning-service, auth-service, metrics-service, publisher-service, public-browse-api, commenting-service, ticket-api, ticket-classifier, ticket-telemetry-listener, ticket-notifier, document-extractor
   - gRPC и REST порты объединены в единый блок `expose` для каждого сервиса.
   - Публичные сервисы (frontend, api-gateway, publish-browse-ui, neo4j, postgres, redis, rabbitmq, minio, keycloak) остались на `ports`.

2. **.env.dev:** Обновлён под ADR:
   - PUBLISH_BROWSE_UI_PORT: 3001 → 3002, GRAFANA_PORT: 3002 → 3001
   - Устаревшие переменные заменены на актуальные (PUBLISHER_SERVICE_PORT → PUBLISHER_SERVICE_REST_PORT + PUBLISHER_SERVICE_CONTAINER_GRPC_PORT)
   - Добавлены _CONTAINER_PORT переменные для всех сервисов
   - RabbitMQ: RABBITMQ_PORT → RABBITMQ_AMQP_PORT
   - Добавлены MinIO, Ticket API, Ticket Classifier, Ticket Telemetry Listener, Ticket Notifier

3. **.env.test:** Исправлен RabbitMQ (AMQP: 15673, имя переменной RABBITMQ_AMQP_PORT), Grafana (13001), добавлен PUBLISH_BROWSE_UI_PORT=13002.

4. **.env.staging:** Удалены host-port переопределения для внутренних сервисов (больше не нужны, т.к. сервисы не публикуются на host). Комментарий уточнён: "Только публичные сервисы с портами на host".

5. **ADR:** Статус PROPOSED → ACCEPTED, добавлена дата имплементации.

6. **deploy/README.md:** Таблица портов обновлена — внутренние сервисы помечены "— (internal)". Добавлено предупреждение о недоступности внутренних портов с host и инструкция по debug-доступу.

## Prevention

- При добавлении нового сервиса в docker-compose.yml: проверять по ADR, должен ли он публиковаться на host. Если internal — использовать `expose`, а не `ports`.
- При изменении портов в compose или ADR: синхронизировать все три .env файла (dev/test/staging).
- CI-проверка: `docker compose --env-file .env.<env> config > /dev/null` для всех окружений.
- Review checklist: новый сервис с `ports` требует обоснования в ADR.
- Избегать упрощённых имён переменных — использовать точные: `SERVICE_PORT` → `SERVICE_REST_PORT` + `SERVICE_CONTAINER_GRPC_PORT`.
