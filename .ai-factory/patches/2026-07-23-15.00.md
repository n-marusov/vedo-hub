# Duplicate identifier and stray parenthesis break Vite production build

**Date:** 2026-07-23 15:00
**Files:** src/services/frontend/src/pages/MetricsPage.vue, src/services/frontend/src/pages/MembersPage.vue
**Severity:** medium

## Problem

`docker compose up -d --build frontend` failed at the `npx vite build` step with two compilation errors:

1. **MetricsPage.vue:40** — `Identifier 'counters' has already been declared`
2. **MembersPage.vue:48** — `Unexpected token` (extra `)`)

The errors were masked in dev mode (`vite dev`) because Vite uses on-demand compilation, but surfaced in production build where all modules are eagerly transformed.

## Root Cause

1. **MetricsPage.vue** — `counters` was declared twice in `<script setup>`:
   - Line 99: `const counters = ref({...})` — mutable reactive state
   - Line 119: `const counters = computed(() => {...})` — derived from `metricsData`

   Both served the same purpose (exposing counter values with defaults), but the `computed` was redundant because `fetchMetrics()` already assigns `data.counters` to the `ref` on line 108. Two `const` bindings with the same name in the same scope is a syntax error caught by the SFC compiler.

2. **MembersPage.vue** — An unmatched closing parenthesis `)` on line 151 after a properly closed `watch()` call (line 150 ends with `);`). This appears to be a stray character from an incomplete edit.

## Solution

1. **MetricsPage.vue** — Removed the redundant `computed` block (lines 119-127). The `ref` on line 99 already serves the same purpose with proper defaults and is updated in `fetchMetrics()`.

2. **MembersPage.vue** — Removed the extra `)` on line 151.

3. **MembersPage.vue** — Additionally fixed a runtime bug discovered during review: the `watch` on `members.value` also mutated `members.value`, which would corrupt member data on the second trigger (API data with `username` → mapped data with `name` → re-trigger maps `undefined` names to empty strings). Replaced the `watch` + `ref` pattern with a `computed` derived from `rawMembers`, moving mapping to `fetchMembers`. Mutation operations (`splice` on remove) now target `rawMembers.value`. Added `MemberRow` interface for type safety.

## Prevention

- Run `npx vite build` (or a lightweight `npx vue-tsc --noEmit` equivalent) locally before pushing frontend changes. The dev server does not catch all SFC compilation errors.
- Consider adding a `typecheck` script to `package.json` that runs `vue-tsc --noEmit` as a pre-commit or CI gate.
- When refactoring reactive state, search for the variable name across the entire `<script setup>` block to avoid shadow declarations.
