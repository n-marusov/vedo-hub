# Missing pyproject.toml and uv.lock in ticket-classifier service breaks docker build

**Date:** 2026-07-27 23:32
**Files:** apps/services/ticket-classifier/pyproject.toml, apps/services/ticket-classifier/uv.lock
**Severity:** high

## Problem

Running `make docker-up` failed with:

```
target ticket-classifier: failed to solve: failed to compute cache key:
failed to calculate checksum of ref ...: "/apps/services/ticket-classifier/uv.lock": not found
```

The `Dockerfile.python` (used by all Python services) copies `pyproject.toml` and `uv.lock` from each service directory, but the ticket-classifier service had neither file.

## Root Cause

The ticket-classifier service was scaffolded with only a `main.py` file. It uses only Python stdlib modules (http.server, json, os, time) and had no `pyproject.toml` defining the project or `uv.lock` lockfile. The centralized `Dockerfile.python` requires both files for the uv-based build pipeline but was designed assuming all Python services would have them.

The `metrics-service` has the same issue (no source files at all), though that was not reported in this build attempt.

## Solution

Created a minimal `pyproject.toml` following the same structure as `document-extractor` but with an empty `dependencies` list (since the service only uses stdlib). Ran `uv lock` to generate the matching `uv.lock` file.

## Prevention

- When scaffolding a new Python service, always include at minimum a `pyproject.toml` with the project definition, even if there are no external dependencies.
- Run `uv lock` after creating the `pyproject.toml` to generate the lockfile.
- Add a CI check that all Python service directories contain both `pyproject.toml` and `uv.lock`.
- Consider making `uv.lock` optional in `Dockerfile.python` for services with zero external dependencies (e.g., use `COPY` with `--chmod` and conditionally skip `--frozen`), though creating the files is simpler.
