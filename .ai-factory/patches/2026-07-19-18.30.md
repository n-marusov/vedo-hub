# Docker build fails: api-gateway requires Go 1.24, base image is Go 1.22

**Date:** 2026-07-19 18:30
**Files:** src/docker/Dockerfile.go
**Severity:** high

## Problem

`docker compose build` for api-gateway fails with:
```
go: go.mod requires go >= 1.24 (running go 1.22.12; GOTOOLCHAIN=local)
```

The `api-gateway/go.mod` specifies `go 1.24` but the shared Dockerfile.go defaulted to `golang:1.22-alpine`. Additionally, the runtime image lacked migration SQL files needed by auth-service.

## Root Cause

The Dockerfile.go was written when all services used Go 1.22. When api-gateway upgraded to Go 1.24 (for `GOTOOLCHAIN` or module features), the Docker base image was not updated. Two other latent issues:
1. Migration SQL files were not copied to the runtime image (auth-service fell back to MemStore).
2. Playwright E2E config expects Vite dev server on port 3000, which conflicts with Docker frontend nginx on the same port.

## Solution

1. Updated `GO_BASE_IMAGE` default from `golang:1.22-alpine` to `golang:1.24-alpine`.
2. Added conditional migrations copy: builder stage copies `migrations/` dir to `/out/migrations` (if exists), runtime stage copies from there to `/app/migrations/`.
3. Documented that Docker frontend must be scaled to 0 before running Playwright:
   `docker compose -f deploy/docker-compose.test.yml up -d --scale frontend=0`

## Prevention

- Pin the base Go image version to the maximum required across all services.
- Include a matrix check in CI that verifies all services build with the current base image.
- For Playwright tests, update the config to document the port conflict resolution.
