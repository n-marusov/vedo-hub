# Nginx rewrite for /api/v1/health and /api/v1/ready

**Date:** 2026-07-19 23:31
**Files:** src/services/frontend/nginx.conf
**Severity:** medium

## Problem

API tests `GET /api/v1/health` and `GET /api/v1/ready` returned 404 when running through the Docker stack (nginx frontend), but passed when running through Vite dev server.

Error: `404 {"error":"ENDPOINT_NOT_FOUND","message":"The requested endpoint /api/v1/health does not exist"}`

## Root Cause

The API Gateway handles health/ready checks on `/health` and `/ready` paths. The Vite dev server rewrites `/api/v1/health` → `/health` and `/api/v1/ready` → `/ready` before proxying. However, nginx proxied the paths without rewriting: GET `/api/v1/health` → nginx → gateway `/api/v1/health` → 404 (gateway has no handler for `/api/v1/health`).

The nginx.conf had a single prefix-match `location /api/v1/` block that passed all paths through unchanged. The rewrite configuration was missing for these two specific endpoints.

## Solution

Added two exact-match (`=`) location blocks before the general `location /api/v1/` block in nginx.conf:

```nginx
location = /api/v1/health {
    if ($request_method != GET) { return 405; }
    rewrite ^/api/v1/health$ /health break;
    proxy_pass http://api-gateway:8080;
    # ... standard proxy headers ...
}

location = /api/v1/ready {
    if ($request_method != GET) { return 405; }
    rewrite ^/api/v1/ready$ /ready break;
    proxy_pass http://api-gateway:8080;
    # ... standard proxy headers ...
}
```

The `rewrite ... break` flag makes nginx use the rewritten URI (`/health`, `/ready`) for the proxy_pass destination, while the exact match (`=`) location has higher priority than the prefix-match `/api/v1/` block.

## Prevention

- When nginx proxies sub-paths under a prefix, verify that all rewritten paths in the dev server (Vite) have corresponding rewrite rules in nginx
- When adding new API endpoints that differ between the external path (`/api/v1/...`) and internal handler path, add explicit nginx rewrites
- Review the Vite config's `proxy` rewrite rules and ensure nginx.conf mirrors them
