# Skills verification blindspot: add cumulative full-service static-analysis gate

**Date:** 2026-07-18 17:00
**Files:**
- `.ai-factory/rules/base.md` — expanded Verification Lint & Format Requirement as a cumulative project gate
- `.ai-factory/skill-context/aif-verify/SKILL.md` — created project addendum
- `.ai-factory/skill-context/aif-implement/SKILL.md` — created project addendum

**Severity:** high

## Problem

IDE (rust-analyzer, gopls, Pylance) showed 121 errors and 612 warnings across the
project, while local skill workflows and pre-commit checks appeared clean.

Concrete missed issues included:
- Rust services: `tonic::transport::server::TlsConfig` compilation errors
- Go `shared/proto`: missing generated-code dependencies in `go.mod`
- Python `parsers/__init__.py`: implicit relative imports visible to type analysis
- Python: many Pyright warnings not covered by `ruff`

## Root Cause

The local workflow had a blindspot, but the existing fast checks were not wrong by
themselves. They were incomplete as a final verification gate.

1. **Fast changed-file checks were treated as sufficient.**
   Pre-commit and the base skill focus on changed/staged files to keep feedback
   fast and readable. That is useful, but it cannot detect pre-existing errors in
   untouched files.

2. **The final verification gate lacked full-service static analysis.**
   `$aif-verify` needed an additional project-specific pass that checks all files
   in the affected service ecosystem before returning `pass`.

3. **Tool coverage did not match IDE diagnostics.**
   - Python: `ruff` does not replace `basedpyright`/IDE type analysis.
   - Rust: `cargo clippy` does not replace `cargo check` as the compilation gate.
   - Go: `golangci-lint` does not replace `go vet`, `gofmt`, and dependency drift
     checks for modules such as `shared/proto`.

4. **Service discovery was implicit.**
   In a polyglot monorepo, a change in one service or shared contract can affect
   multiple services. The project needed an explicit service matrix.

## Solution

Implemented a cumulative, non-conflicting fix:

**Layer 1 — `.ai-factory/rules/base.md`:**
- Reframed validation as a project-specific static-analysis gate, cumulative with
  base `$aif-verify` behavior.
- Kept changed-file checks as fast focused feedback.
- Added final full-service checks for affected service ecosystems.
- Added missing tools: `cargo check`, `basedpyright`, `go vet`, `go mod tidy` drift
  checks.

**Layer 2 — `.ai-factory/skill-context/aif-verify/SKILL.md`:**
- Created a project addendum, not a replacement.
- Defines layered verification:
  1. base focused pass;
  2. VEDO Core full-service static-analysis pass.
- Final `pass` requires both layers to succeed.
- Explicitly preserves the base skill's fast changed-file checks.

**Layer 3 — `.ai-factory/skill-context/aif-implement/SKILL.md`:**
- Created a project addendum, not a replacement.
- Adds a required static-analysis checkpoint after the base Step 3.4 verification.
- Prevents marking tasks complete while full-service static analysis still reports
  errors in the affected ecosystem.

## Prevention

- Evolve skills cumulatively. Do not phrase project-specific learning as a hard
  replacement unless the base behavior is harmful in all contexts.
- Preserve fast local checks for developer feedback, but do not allow them to be
  the final correctness gate.
- In monorepos, final verification must use explicit service matrices rather than
  only file-level change detection.
- Tool equivalence must not be assumed:
  - `ruff` is not `basedpyright`.
  - `cargo clippy` is not `cargo check`.
  - `golangci-lint` is not `go mod tidy`.
- When adding new services, update the service matrix in both skill-context files
  and base rules.
