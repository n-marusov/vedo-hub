# M2 AI Ontology Creation — 17 critical issues fixed

**Date:** 2026-07-16 18:30
**Files:** routes.go, main.go, grpc_client.go, grpc_ontology_client.go, auth.go, nl_to_owl_handler.go, ai_completion_handler.go, refinement_handler.go, template_handler.go, prompt_injection.go, llm_policy_router.go, apply_sequence.rs, sequence_repo.rs, routes.py, anthropic.go, openai_compatible.go
**Severity:** critical

## Problem

15 blocking critical issues found in the `feature/ai-ontology-creation` branch spanning gRPC lifecycle bugs, data integrity violations, security bypasses, dead code, and architectural misalignment.

## Root Cause

Six root-cause categories:
1. **gRPC lifecycle:** `defer grpcPool.Close()` inside `RegisterRoutes()` fired before `srv.ListenAndServe()` — all gRPC calls silently failed.
2. **Data integrity:** `steps_failed > 0 && steps_applied == 0` condition allowed partial commits when any step succeeded.
3. **Security bypasses:** `X-Admin-Override` had no JWT verification; `X-Ontology-Visibility` was client-supplied with no server check — any user could exfiltrate private ontology data.
4. **Dead code:** `ValidateLLMOutput` defined but never called; prompt injection patterns ran only on input, not output.
5. **Cross-ontology scope:** `set_domain`/`set_range` MATCH clauses omitted `ontology_id` filter.
6. **No gRPC auth:** No token propagation or TLS for inter-service gRPC calls.

## Solution

- **Fix 1:** Moved `grpcPool.Close()` from `RegisterRoutes()` to `main()` graceful shutdown path. Pass pool as parameter instead of creating locally.
- **Fix 2:** Created dedicated `documentExtractorProxy` for doc-extractor routes (was incorrectly proxying to ontology-service).
- **Fix 3:** Added nil-provider guards in all 4 AI handlers returning 503 with descriptive message.
- **Fix 4:** Replaced header-only `X-Admin-Override` with JWT role verification against `DefaultAdminRoles()`.
- **Fix 5:** Added `OntologyVisibilityResolver` interface and server-side gRPC resolution of ontology visibility via `GetOntologyVisibility()`. Client-supplied `X-Ontology-Visibility` only used as fallback when gRPC unavailable.
- **Fix 6:** Activated `ValidateLLMOutput()` after every LLM completion call in all 3 AI handlers.
- **Fix 7:** Added NFC normalization, zero-width character stripping, and `SanitizeUserInput()` with printable-only filter.
- **Fix 8:** Applied `SanitizeUserInput()` to ClassID/SourceClassID/TargetClassID before prompt interpolation.
- **Fix 9:** Added `MaxTextLength` (50KB) and `MaxFeedbackLength` (10KB) with `PAYLOAD-TOO-LARGE` error.
- **Fix 10:** Changed atomicity condition from `steps_failed > 0 && steps_applied == 0` to `steps_failed > 0` — ANY failure triggers full rollback.
- **Fix 11:** Added `ontology_id` filter to `set_domain`/`set_range` Cypher MATCH clauses, preventing cross-ontology data corruption.
- **Fix 12:** Implemented real gRPC `ApplySequence` call in `HandleApplyTemplate` with `convertStepsToProto` mapping.
- **Fix 13:** Added `authUnaryClientInterceptor` for JWT propagation and `CtxKeyJWTToken` in auth context.
- **Fix 14:** Added TLS support controlled by `GRPC_TLS_ENABLED` env var, default disabled.
- **Fix 15:** Removed unused `ontology_context` parameter from document-extractor routes.
- **Fix 16:** Narrowed `isAIRoute` to match only AI-specific suffixes (`generate-from-text`, `ai/`, `documents/extract`).
- **Fix 17:** Fixed LLM providers to use `http.NewRequestWithContext()` for proper context propagation; added `io.LimitReader` (10MB) for response body size limits.

## Prevention

- `defer` in functions that register routes but don't own the server lifecycle should never close shared resources — pass them as parameters to the lifecycle owner.
- Any step failure in a multi-step transaction must trigger full rollback. Always use the strictest condition.
- Never trust client-supplied headers for security decisions (visibility, admin status). Always verify against server-side data and JWT claims.
- All LLM output must be validated with the same rigour as input before it reaches application logic.
- Every Neo4j MATCH clause operating on shared entity IDs must include an `ontology_id` filter.
- Use `http.NewRequestWithContext()` for all outbound HTTP calls and wrap `resp.Body` with `io.LimitReader` to prevent unbounded memory allocation.
