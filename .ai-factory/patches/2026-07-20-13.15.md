# WCAG AA Color Contrast — muted-foreground too dark on card background

**Date:** 2026-07-20 13:15
**Files:** src/services/frontend/src/styles/tokens.css
**Severity:** medium

## Problem

Login page color contrast test failed: axe-core reported a color-contrast violation for the `.login-subtitle` text "Build, connect, and share knowledge at scale". The CSS variable `--muted-foreground` (#6b7280, gray-500) on `--card` background (#101010) gave a contrast ratio of 3.93:1, below the WCAG AA minimum of 4.5:1 for 13px normal text.

The violation was detected by `tests/e2e/playwright/tests/gui/pages/contrast-check.spec.ts` which runs axe-core on the login page and asserts zero color-contrast violations.

## Root Cause

The dark theme's `--muted-foreground` value (#6b7280) was chosen for visual aesthetics (subtle/dim appearance) without verification against the WCAG AA 4.5:1 ratio on its typical background surfaces (`--card`: #101010, `--background`: #0a0a0a). While the color looks "muted" and was likely taken from a Tailwind palette, it failed the accessibility requirement.

This is a systemic design-token issue: `--muted-foreground` should be accessible on the surfaces where it is used by default.

## Solution

Changed `--muted-foreground` in the dark theme from `#6b7280` to `#8a94a6`:

```css
--muted-foreground: #8a94a6;
```

This lighter gray achieves ~5.9:1 contrast ratio on `#101010` (well above the 4.5:1 minimum) while remaining visually distinct from `--foreground` (#fafafa). The light theme's `--muted-foreground` (#334155) was already compliant.

## Prevention

- Design token color values should be verified against WCAG AA contrast ratios on their target background surfaces before adoption
- Add a CI step to run the color contrast Playwright test (axe-core) on every frontend change
- When choosing gray/muted colors for dark themes, prefer shades that pass 4.5:1 on `--card` and `--background`
