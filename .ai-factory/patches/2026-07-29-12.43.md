# BOLA/BFLA security gate fails due to missing integration build tag

**Date:** 2026-07-29 12:43
**Files:** tests/gates/test_bola_bfla_gate.sh
**Severity:** medium

## Problem

`make test-gates` failed with `!!! Gates FAILED: bola-bfla !!!`. The BOLA/BFLA gate script exited non-zero even though the first two test suites (API gateway auth middleware, auth-service/org) passed cleanly.

## Root Cause

The gate script's third test suite runs `go test ./...` in `tests/security/authorization/`. All Go files in that directory:

1. Are `_test.go` files (no non-test source files)
2. Have `//go:build integration` build constraint

Without `-tags=integration`, `go test ./...` found no matching packages and exited with code 1 (`go: warning: "./..." matched no packages / no packages to test`). With `set -euo pipefail` in the script, this non-zero exit caused the whole gate to fail.

The directory was correctly structured as an integration-only test suite with its own `go.mod`, but the build tag was not wired into the gate invocation.

## Solution

Added `-tags=integration` to the `go test` command on line 47:

```bash
cd "$ROOT/tests/security/authorization" && "$GO_CMD" test -tags=integration ./... -count=1 2>&1
```

This makes the build constraint-aware Go compiler discover all test files in the package. The tests themselves use `t.Skip()` for unimplemented test scenarios, so they pass gracefully without requiring a running test environment.

## Prevention

- When adding a `//go:build integration` constrained test suite to a gate script, always include `-tags=integration` in the `go test` invocation
- When a gate fails unexpectedly, check for build constraint mismatches between test files and their invocation
- `go test ./...` returning `no packages to test` is a non-zero exit — treat it as a signal that build tags may be missing
