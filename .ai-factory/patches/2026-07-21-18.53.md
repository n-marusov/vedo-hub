# Swagger UI /api/v1/docs returns 401 UNAUTHENTICATED in dev environment

**Date:** 2026-07-21 18:53
**Files:** src/services/api-gateway/main.go, src/services/api-gateway/helpers_test.go
**Severity:** medium

## Problem

Opening `http://localhost:8080/docs` returned `401 UNAUTHENTICATED` with message
"Missing or invalid Authorization header". The Swagger UI should be accessible
without authentication in the development environment per
ADR-DES.API.swagger-ui-dev-only-strategy.

## Root Cause

The auth middleware is applied globally via `r.Use(auth.NewMiddleware(...))` in
`main.go`. The exempt paths lists (`ExemptPrefixes` and `ExactExemptPaths`)
did not include `/api/v1/docs`, `/api/v1/docs/*`, or `/api/v1/openapi.json`.
When a request hit any of these paths, the auth middleware checked the JWT token
(which the browser had none of) and returned 401.

The handler functions (`docHandler`, `swaggerStaticHandler`) already had their
own feature gate (`isSwaggerUIEnabled()`) returning 404 when `ENABLE_SWAGGER_UI`
is not set — so exempting them from auth middleware was safe. The ADR explicitly
states that the raw OpenAPI spec `/api/v1/openapi.json` should be public in all
environments and the Swagger UI should be accessible in dev.

## Solution

Added the docs and openapi paths to the auth middleware exempt lists in both
the production wiring (`main.go`) and the test helper (`helpers_test.go`):

```go
ExemptPrefixes:   append(auth.DefaultExemptPrefixes(), "/api/v1/public/", "/api/v1/docs/"),
ExactExemptPaths: append(auth.DefaultExactExemptPaths(), "/api/v1/docs", "/api/v1/openapi.json"),
```

- Prefix `/api/v1/docs/` covers all Swagger UI static assets (CSS, JS bundles)
  served via the catch-all `/docs/*filepath` route.
- Exact path `/api/v1/docs` covers the index page handler.
- Exact path `/api/v1/openapi.json` covers the raw OpenAPI spec (public per ADR).

## Prevention

- When adding new public endpoints (especially dev-only tooling), always verify
  the auth middleware exempt lists include the new paths.
- The auth integration tests should cover exempt paths to prevent regression.
- Review the ADR's "Последствия" section which explicitly mentions the need for
  "условная маршрутизация в routes.go с проверкой ENABLE_SWAGGER_UI" — the
  routing was conditionally working but auth was blocking it.
