# Pre-existing `go vet` issues in auth-service, commenting-service, and ticket-api

**Date:** 2026-07-17 08:58
**Files:** src/services/auth-service/handler_introspect.go, src/services/auth-service/internal/grpc/server.go, src/services/commenting-service/handlers.go, src/services/commenting-service/handlers_test.go, go.sum (auth-service, commenting-service, ticket-api)
**Severity:** medium

## Problem

Three Go services had pre-existing `go vet` failures that blocked verification:

1. **auth-service** — duplicate `package grpcserver` declaration (line 37) in `internal/grpc/server.go` and undefined `writeJSON` function in `handler_introspect.go`
2. **commenting-service** — undefined `writeJSON` in `handlers.go`, undefined `getUserID` in `handlers.go`, undefined `writeMetrics` in `handlers_test.go`, and stale `go.sum`
3. **ticket-api** — stale `go.sum` (missing entries for existing dependencies)

## Root Cause

These were scaffold/stub artifacts left over from early service generation:
- The duplicate `package` declaration was a copy-paste error in a commented-out boilerplate section of the gRPC server stub.
- The `writeJSON` helper function was used in handler code but never defined — a common oversight when scaffolding HTTP handlers.
- The `getUserID` function was referenced by handler code but not implemented — the service assumed external auth middleware would inject it.
- The `go.sum` files became desynchronized from `go.mod` during development (dependencies were added/updated via `go get` without running `go mod tidy`).

## Solution

- `handler_introspect.go`: Added `writeJSON()` helper function with logging
- `internal/grpc/server.go`: Removed duplicate `package grpcserver` at line 37
- `commenting-service/handlers.go`: Added `writeJSON()` and `getUserID()` helper functions
- `commenting-service/handlers_test.go`: Added `writeMetrics()` test helper
- All three services: Ran `go mod tidy` to sync `go.sum` with `go.mod`

## Prevention

- After scaffolding a new Go service or adding handler files, run `go vet ./...` to catch missing utility functions before committing.
- Run `go mod tidy` after any dependency change (`go get`, `go mod edit`, manual `go.mod` edits) to keep `go.sum` in sync.
- Add a CI lint job that runs `go vet ./...` on all Go services to catch these issues early.
