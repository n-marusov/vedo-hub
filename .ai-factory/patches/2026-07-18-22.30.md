# Docker build failures — Cargo workspace, Go replace directives, and Rust toolchain version

**Date:** 2026-07-18 22:30
**Files:**
- deploy/docker-compose.yml
- src/services/api-gateway/Dockerfile
- src/services/auth-service/Dockerfile
- src/services/commenting-service/Dockerfile
- src/services/ticket-api/Dockerfile
- src/services/ontology-service/Dockerfile
- src/services/versioning-service/Dockerfile
- src/services/publisher-service/Dockerfile
- src/services/public-browse-api/Dockerfile
- src/services/publish-browse-ui/Dockerfile
**Severity:** high

## Problem

`docker compose build` failed for 8+ services. Go services failed with `go mod download` unable to find shared modules referenced in `replace` directives. Rust services failed with missing source code and missing `shared/` crate. `publish-browse-ui` had unreproducible builds due to missing lockfile pinning.

## Root Cause

**Go services (api-gateway, auth-service, commenting-service, ticket-api):**
The Dockerfiles used `COPY go.mod ./` which assumes the build context is the service's own directory. But `docker-compose.yml` sets `build.context: ../src/services` (the workspace root). The service `replace` directives point to `../shared/proto` and `../shared/llm`, which resolve outside the service directory. `go mod download` failed because it needed the replaced modules available at those paths.

**Rust services (ontology-service, versioning-service, publisher-service, public-browse-api):**
The Dockerfiles used `COPY src ./src` which tries to copy `services/src/` but source code is at `services/<service>/src/`. They also never COPY'd the `shared/` crate (`vedo-shared`), despite all four services depending on it via `path = "../shared"`. The Cargo workspace at `services/Cargo.toml` listed all members, but only one member's Cargo.toml was copied.

Additionally, the base `rust:1.77` image was too old — transitive crate dependencies (`async-graphql@7.2.1`, `time@0.3.53`) required Rust ≥ 1.89 for the `edition2024` feature. The `shared/build.rs` uses `tonic_build` which needs the `protoc` binary not included in the base image.

**publish-browse-ui:** The Dockerfile didn't copy `pnpm-lock.yaml` in the dedicated layer and used `pnpm install` without `--frozen-lockfile`, risking unreproducible builds.

## Solution

**Go services:** Rewrote Dockerfiles to work with `context: ../src/services` by prefixing COPY paths (e.g., `COPY api-gateway/go.mod ./`). Added explicit `COPY shared/proto /shared/proto/` and `COPY shared/llm /shared/llm/` before `go mod download` so `replace` directives resolve correctly during dependency download.

**Rust services:** Completely rewrote Dockerfiles with the standard Cargo workspace pattern:
1. Copy workspace `Cargo.toml` + ALL member Cargo.toml files for workspace validation
2. Create dummy source files for all members + shared crate to prefetch dependencies
3. Copy real sources (shared/ + service/)
4. Clean cached build output for `vedo-shared` before final build (stale dummy `build.rs`)
5. Build with `cargo build --package <service> --release`
6. Upgraded base image from `rust:1.77` to `rust:1.89`
7. Installed `protobuf-compiler` in builder stage for `tonic_build`

**publish-browse-ui:** Added `pnpm-lock.yaml` to COPY layer and `--frozen-lockfile` flag.

## Prevention

- For Cargo workspace monorepos, always use the workspace-aware Dockerfile pattern: copy ALL member Cargo.toml files, use `--package` flag, install `protoc` if using `tonic_build`
- For Go monorepos with `replace` directives, copy the replaced modules before `go mod download` using absolute destination paths matching the replace target
- Keep the Rust base image version in sync with dependency requirements — pin a recent version not older than 6 months
- Always use `--frozen-lockfile` for Node/pnpm Docker builds to ensure reproducible builds
- Test `docker compose build <service>` for each service when adding new shared dependencies or changing build contexts
