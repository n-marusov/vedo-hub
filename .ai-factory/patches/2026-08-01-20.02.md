# Shell syntax gates — triple quote + subshell assignment bugs

**Date:** 2026-08-01 20:02
**Files:** tests/gates/test_bola_bfla_gate.sh, tests/gates/test_cross_milestone_frontend_smoke.sh, tests/gates/test_shell_syntax.sh (new), Makefile
**Severity:** medium

## Problem

`make test-fast` → `test-gates-fast` failed with:
`tests/gates/test_bola_bfla_gate.sh: line 47: unexpected EOF while looking for matching "`

The gate ran all Go BOLA/BFLA/RBAC tests (all passed) but then aborted with a
shell syntax error at the very end, making the whole gate (and CI) fail.

While building a syntax gate, a second latent bug was found in
tests/gates/test_cross_milestone_frontend_smoke.sh:220 — `VAR=... (subshell)`
is invalid bash syntax (assignments cannot prefix a compound command).

## Root Cause

1. Line 47 of test_bola_bfla_gate.sh had a typo with **three** closing double
   quotes instead of one:

   ```bash
   echo "=== BOLA/BFLA/RBAC unit suite complete ===""
   ```

   The extra `"` opened an unterminated string → `unexpected EOF`. The bug is
   invisible when tests inside pass loudly — only `bash -n` or running to
   completion reveals it.

2. test_cross_milestone_frontend_smoke.sh:219-220 used a line-continuation
   before a subshell with env assignments:
   `FRONTEND_URL=... PUBLISH_URL=... \\ (cd ... && ...)` — assignments before a
   `( )` compound command are a syntax error in bash. This script is not in the
   default `test-gates-fast` chain, so the bug went unnoticed.

## Solution

1. Fixed line 47: single closing quote.
2. Moved env vars inside the subshell before the command (valid `VAR=x cmd`):
   `(cd "$test_dir" && FRONTEND_URL=... PUBLISH_URL=... npx playwright test ...)`.
3. Added `tests/gates/test_shell_syntax.sh` (CT-SHELL-001) — runs `bash -n` on
   every tracked `.sh` file (excluding `.agents/` templates with placeholders),
   and wired it as the **first** step in `test-gates-fast` and `test-gates-full`.

## Prevention

- `bash -n` on every shell script is now the first gates check — syntax errors
  fail fast before any gate runs.
- In CI gates, assert the script's *final* marker line is printed, not just that
  tests inside pass.
- Consider adding shellcheck to the lint pipeline for deeper checks.
