# Race condition in getErrorMessage() — test assertion failed with null

**Date:** 2026-07-22 20:30
**Files:**
- tests/e2e/playwright/pages/document-upload.page.ts
- tests/e2e/playwright/tests/gui/user-stories/document-preview-sequence.spec.ts
**Severity:** medium

## Problem

Test `error state shows retry button and retry recovers` failed with:

```
expect(received).not.toBeNull()

Received: null
```

At `document-preview-sequence.spec.ts:228` — `uploadPage.getErrorMessage()` returned `null`
even though the page snapshot showed the error dialog with `heading "Import Failed"`.

## Root Cause

The method `getErrorMessage()` had a side-effect design: it tried to click
`.modal__btn--primary` BEFORE looking for the error title. This selector matched
DIFFERENT buttons depending on the dialog state:

| Dialog state | `.modal__btn--primary` | Effect of click |
|---|---|---|
| `confirming` | "Import N entities" | Triggers confirm, starts apply |
| `applying` | *(none)* | Timeout → caught |
| `success` | "Done" | Closes modal |
| `error` | **"Retry"** | **Triggers retry → dialog leaves error state** |

This created a race condition: during the click, Vue re-rendered the dialog
(confirming → applying → error), Playwright's auto-retrying locator re-queried
the DOM, found the "Retry" button in the error state, clicked it, and the dialog
transitioned back to confirming — making `.modal__title--error` invisible.

Additionally, the test relied on this side-effect to advance the dialog from
`'confirming'` to `'applying'`, but the other tests used `waitForApplyComplete()`
for the same purpose — an implicit, inconsistent contract.

## Solution

1. **Separated concerns in the page object:**
   - Added `confirmImport()` — explicitly clicks the confirm button, scoped to
     the dialog role for safety
   - Stripped `confirm.click()` from `getErrorMessage()` — now has NO side effects
   - Scoped `waitForApplyComplete()` to the dialog role as well
   - Scoped `clickRetry()` to the dialog role

2. **Made the test explicit:**
   - Added `await uploadPage.confirmImport()` after `applySequence()` in the
     error test — the dialog is explicitly confirmed before checking for error

## Prevention

- Page object methods that READ state should never have side effects (clicks,
  form fills) — follow Command-Query Separation
- When a locator matches elements in multiple dialog states, scope it to a
  specific role/context to avoid unintended interactions during re-renders
- Use `getByRole('dialog', ...)` as a parent context when interacting with
  modal elements
