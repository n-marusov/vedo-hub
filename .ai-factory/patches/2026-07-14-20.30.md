**Severity:** critical

## Problem

Code review of `feature/ontology-core-engine` surfaced 19 critical and 12
high-priority issues across security (SQL injection, CORS reflected origin +
credentials, JWT bypass, path traversal, SPARQL→Cypher injection), correctness
(race conditions in commit/branch ops, empty merge deltas, O(n²) merge),
data sync (swallowed transport errors, false-positive synced flag), and tests
(BOLA/BFLA fixtures returning hardcoded 403 with no real HTTP, gateway test
compose with auth disabled, integration test script missing DB env vars).

## Root Cause

- **Injection patterns** — commenting-service `store.go` used
  `fmt.Sprintf("%q::jsonb", *req.Metadata)` string interpolation; ontology-
  service `var_to_ident` passed SPARQL variable names straight into Cypher
  identifiers; LIMIT was string-interpolated into the translated query.
  Underlying cause: reviewers accepted quick wins over parameterized queries.
- **Trust boundary leaks** — backend services trusted `X-User-Id` headers
  without verifying JWT signatures, enabling impersonation when accessed
  directly. CORS reflected any Origin with `Allow-Credentials: true`, exposing
  credentialed cross-origin reads.
- **Missing transaction boundaries** — merge operations split commit INSERT
  and head UPDATE across two queries; concurrent commits raced on branch head
  with no `FOR UPDATE` lock; no DB constraint ensured branch name uniqueness.
- **Error swallowing** — `push_state` returned `Ok(())` on transport
  failures and the caller reported `synced: true`; `unwrap_or(0)` in
  `compute_ahead_behind` silently turned DB errors into (0,0) counts.
- **Defence-in-depth breakdown** — gateway owned full query validation and
  LIMIT injection, so a gateway misconfiguration could leak mutations to Neo4j.
- **Unbounded resources** — rate limiter keys never evicted; server had no
  read/write timeouts; infinite graceful shutdown hang on SIGTERM.
- **False-pass tests** — BOLA/BFLA fixtures returned the expected status code
  without dispatching an HTTP request, so the security gate appeared green
  even though no enforcement middleware existed.
- **Build break** — duplicate `viewMode` declaration in `OntologyWorkspace.vue`
  blocked `vue-tsc --noEmit`.
- **Path traversal** — publisher `storage_path` constructed from unvalidated
  `ontology_id` allowed `../` to escape the snapshot directory.

## Solution

38-fix plan executed across 7 phases:

- **Phase 1 (commenting-service)** — Parameterized `UpdateComment` metadata
  (`$3::jsonb`), added `[FIX]`-prefixed auth middleware honouring
  `AUTH_DISABLED` for dev/test only, attached reply tree on `ListCommentsByEntity`
  and threaded replies through `toCommentResponse`.
- **Phase 2 (api-gateway)** — CORS fail-closed in production when
  `CORS_ALLOWED_ORIGINS` unset; credentials only sent for origin-list matches;
  rate limiter lazy-evicts empty windows with a background sweeper and a 100k
  max-keys cap; `http.Server` with defined read/write/idle timeouts wrapped
  by a SIGINT/SIGTERM graceful-shutdown handler with a 30s grace period;
  gateway's query validator simplified to a coarse mutation fast-path, LIMIT
  injection moved to ontology-service.
- **Phase 3 (frontend)** — Removed duplicate `viewMode` declaration (fixes
  `vue-tsc --noEmit`), excluded mutation operations from Apollo `RetryLink`
  (idempotency guard), added `#[serde(rename = "label")]` to `ClassNode` in
  public-browse-api so the GraphQL tree resolves, surfaced `CommentsPage`
  mutation failures via `mutationError` ref rendered in the template.
- **Phase 4 (versioning-service)** — `FOR UPDATE` on branch head read; explicit
  `BranchNotFound` when fetch_optional returns None; branch delete TOCTOU
  fixed with `SELECT … FOR UPDATE` + `rows_affected()` check; merge commit
  INSERT and head UPDATE wrapped in single transaction; new
  `merge_metadata` field on `CommitDelta` with `#[serde(default)]`; real
  merge delta computed via `compute_merged_delta`; 9-combination conflict
  detection with `HashSet<(String,String,String)>` triple keys (no colon IRI
  collisions); pre-built source/target sets eliminating O(n²) loops;
  `apply_delta_to_state` dedup via `HashSet`, O(n+δ) removals via
  `HashSet`+`HashMap`; `push_state` returns `Err(SyncFailed)` on transport
  errors; `synced` flag tracks `sync_succeeded`; `compute_ahead_behind`
  propagates DB errors and scopes walks by `branch_id`;
  `compute_semantic_diff` builds `modified_by_subject` map and emits
  before/after `TripleRef`s for modified entities; new migration
  `004_add_constraints.sql` adds unique composite index on
  `branches(ontology_id,name)`, drops the non-unique index, adds
  `ON DELETE CASCADE` FKs on `state_snapshots.commit_id`/`.branch_id`;
  `branch_repo::create` maps PostgreSQL `23505` to a friendly
  `InvalidRequest`.
- **Phase 5 (ontology-service)** — `var_to_ident` rejects names outside
  `^[a-zA-Z_][a-zA-Z0-9_]*$` and returns `Option<&str>`; translated Cypher
  uses `LIMIT $vedo_limit` bound via `neo4rs::query::param`; shared
  `reqwest::Client` on `ExportService` instead of `Client::new()` per call;
  `.error_for_status()` checked on versioning-service responses; new
  `ExportError::VersioningUnavailable` returned on non-2xx/transport failure
  so the export no longer silently falls back to stale Neo4j state;
  `export_handler.rs` sanitizes the detail client-side; domain-specific
  errors already sanitize via `OntologyError::Database` trace_id pattern
  (verified — no change needed for `ClassError`/`PropertyError`); `apply_model`
  tracks created entity IDs and rolls back via compensating deletes when a
  later pass fails (neo4rs 0.7 has no public `start_txn`); SHACL
  `check_class_hierarchy` uses `[:SUB_CLASS_OF*2..]->` for multi-hop cycles
  and surfaces DB errors as a violation instead of swallowing them.
- **Phase 6 (publisher-service)** — Added `validate_ontology_id` regex
  `^[A-Za-z0-9_-]+$` and `validate_format` allowlist (turtle, rdf/xml, owl,
  n-triples, jsonld); both return 400 on mismatch and log `[FIX]` warnings;
  wired into `publish_snapshot_handler` and `list_snapshots_handler`.
- **Phase 7 (tests & infra)** — BOLA/BFLA fixtures given honest
  `t.Skip("… M3 …")` markers; `GATEWAY_AUTH_DISABLED` removed from
  `docker-compose.test.yml` with a documented `JWT_PUBLIC_KEY_PATH` /
  `KEYCLOAK_JWKS_URL` placeholder; `tests/run_integration_rust.sh` becomes a
  thin wrapper delegating to the canonical
  `src/services/scripts/run_integration_rust.sh` with sensible env-var
  defaults; `.env.example` replaced plaintext passwords with
  `<CHANGE_ME_BEFORE_DEPLOY>` placeholders plus a warning header; missing
  Prometheus scrape targets added for commenting, publisher, public-browse,
  support, ticket-api, ticket-classifier, ticket-notifier, ticket-sync,
  ticket-telemetry-listener, publish-browse-ui and frontend services.
- **Test fix for defence-in-depth refactor** — `TestQuery_SPARQLValidSelectProxied`
  rewritten to assert pass-through unchanged instead of gateway-side LIMIT
  injection; updated assertion comment explains the new ownership boundary.
- **Compile fixes carried by sub-agent** — `CommitDelta` struct literals in
  versioning-service tests updated to include `merge_metadata: None` (or
  already use `..Default::default()`) so the new serde(default) field
  compiles cleanly; `export_handler.rs` match exhaustive for
  `ExportError::VersioningUnavailable`.

## Prevention

- **Parameterize, never interpolate** — anywhere user-controlled strings touch
  SQL/Cypher, use bound parameters. Add a lint rule (or grep CI gate) for
  `fmt.Sprintf` against query builders. Code review should reject string-built
  queries the same way it rejects `eval`.
- **Defence-in-depth stays layered** — gateway owns coarse fast-path blocking;
  the upstream re-validates. When ownership moves (as in Phase 2.4), update the
  gateway integration tests in the same change so they assert pass-through
  rather than re-testing the moved logic.
- **Failure must be loud** — transport errors must propagate; an Ok on failure
  is a bug. Add tests that bind a mock client returning HTTP 500 / a transport
  Err and assert the caller returns `Err`, not `Ok(())`.
- **Auth boundary tests should send real HTTP** — never trust
  `executeFixture` mocks that return their own `ExpectedStatus`. Tests skip is
  honest, fake-pass is not. CI should run a grep preventing a body that
  combines `ExpectedStatus != 0` with `executeFixture` returning that exact
  value.
- **Track created IDs for rollback** — when the underlying driver does not
  expose `start_txn`, record created entity IDs and issue compensating deletes
  on later-pass failures. This prevents the half-imported-class partial state
  that breaks referential integrity.
- **Maintain `.env.example` discipline** — every new `os.Getenv` /
  `std::env::var` must be added to `.env.example` in the same change; treat
  real credentials in `.env.example` as a security incident, not a
  documentation oversight.
- **Resource bounds by default** — rate limiters, connection pools, and
  in-memory caches should always include eviction + max-size safety valves;
  HTTP servers should always have read/write/idle timeouts and a graceful
  shutdown handler.
