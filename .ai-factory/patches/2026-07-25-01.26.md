# Case mismatch between Keycloak lowercase realm roles and API Gateway roleWeight map

**Date:** 2026-07-25 01:26
**Files:** src/services/api-gateway/auth/auth.go, src/services/api-gateway/auth/auth_test.go
**Severity:** high

## Problem

Creating a group through the GUI as the owner (Frank) returned HTTP 403:

```json
{
    "error": {
        "code": "FORBIDDEN_INSUFFICIENT_ROLE",
        "message": "Insufficient role for this operation"
    }
}
```

This affected ALL users, not just Frank. Any authenticated user trying to POST to any endpoint requiring more than Viewer level would get a 403, regardless of their actual Keycloak realm role.

## Root Cause

The API Gateway's `roleWeight` map in `auth.go` used PascalCase keys (`"Owner"`, `"Editor"`, `"Viewer"`), but Keycloak realm roles are always lowercase (`"owner"`, `"editor"`, `"viewer"`).

The `resolveEffectiveRole` function did a case-sensitive lookup: `"owner"` (from the JWT) did not match `"Owner"` (map key), so `maxWeight` stayed at -1, and the function fell back to Viewer weight (0). Since POST requires at least Editor level (weight 1), the check `0 < 1` failed with `FORBIDDEN_INSUFFICIENT_ROLE`.

The Keycloak realm configuration (`deploy/keycloak/vedo-core-realm.json`) defines all realm roles in lowercase: `"viewer"`, `"editor"`, `"reviewer"`, `"maintainer"`, `"admin"`, `"owner"`, `"service"`. Three of these (`"reviewer"`, `"admin"`, `"service"`) were also completely missing from the `roleWeight` map.

This was a regression: the code was tested with hardcoded PascalCase roles in tests, but production Keycloak issues lowercase roles via the `oidc-usermodel-realm-role-mapper` protocol mapper.

## Solution

1. **Lowercased all `roleWeight` keys** to match the Keycloak realm role format.
2. **Added missing roles**: `"reviewer"` (weight 1 — can initiate writes that become reviews), `"admin"` (weight 3 — full admin), `"service"` (weight 3 — system-to-system).
3. **Normalized role lookup** in `resolveEffectiveRole` by calling `strings.ToLower(r)` before map lookup, making the function case-insensitive.
4. **Updated fallback**: Changed `return roleWeight[RoleViewer]` to `return 0` since the RoleViewer constant no longer matches lowercase keys.
5. **Added regression tests**: `TestKeycloak_LowercaseRealmRole_OwnerCanPost` (proves lowercase "owner" passes POST) and `TestKeycloak_LowercaseRealmRole_ViewerBlocked` (proves lowercase "viewer" is still correctly denied).

## Prevention

- When mapping JWT claims with enumerated values (roles, permissions), verify the actual claim format from the identity provider (lowercase vs PascalCase) and normalize at lookup time.
- Add integration/unit tests that use the exact role format the IDP sends (Keycloak → lowercase) — not just PascalCase.
- For any `map[AuthRole]int` or similar lookup tables, document the canonical key format and add a comment referencing the IDP configuration file.
