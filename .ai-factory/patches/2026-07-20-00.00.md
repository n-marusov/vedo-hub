# Playwright E2E tests fail with 401 — JWT key mismatch with Keycloak

**Date:** 2026-07-20 00:00
**Files:** tests/e2e/playwright/playwright.api.config.ts, tests/e2e/playwright/playwright.gui.config.ts, tests/e2e/playwright/playwright.config.ts, tests/e2e/playwright/sign-jwt.js, tests/e2e/playwright/tests/jwt-tokens.ts, README.md
**Severity:** high

## Problem

All authenticated Playwright E2E tests (API and GUI) returned 401 Unauthorized instead of expected 2xx/4xx status codes. Error observed in `api-gateway-full.spec.ts`, `api-integration.spec.ts`, `org-api.spec.ts`, and `query-execution.spec.ts` — all 48 tests affected.

## Root Cause

JWT key mismatch between test tokens and the API Gateway configuration:

1. Test JWT tokens in `jwt-tokens.ts` are self-signed with `test-jwt-key.pem` (local RSA private key)
2. `playwright.api.config.ts`, `playwright.gui.config.ts`, and `playwright.config.ts` used `compose-smoke.sh` → `deploy/docker-compose.yml` as the `webServer` command
3. Main compose sets `KEYCLOAK_JWKS_URL` on the API Gateway → gateway validates JWTs against Keycloak's signing keys, not the test key
4. Self-signed tokens fail Keycloak validation → 401 on every authenticated request

The fix (`deploy/docker-compose.test.yml`) already existed — it sets `JWT_DEV_PUBLIC_KEY_PEM` (matching the test key) on the API Gateway, taking highest priority in the auth resolution chain (`src/services/api-gateway/auth/keyfunc.go` line 53). The reference config `playwright.m2.1.real.config.ts` already used it correctly.

## Solution

Changed `webServer.command` in all three Playwright configs from `compose-smoke.sh` (which starts `docker-compose.yml` with Keycloak JWKS validation) to `docker compose -f ../../../deploy/docker-compose.test.yml up -d --wait --wait-timeout 120`, which includes the main compose + the `JWT_DEV_PUBLIC_KEY_PEM` override. The readiness check kept `url: 'http://localhost:3000/health'` (frontend) — using `port: 8080` (API Gateway alone) causes ECONNREFUSED because tests connect through the frontend proxy on port 3000, and the frontend container starts after the API Gateway.

Also fixed `sign-jwt.js`: added `organization_id: 'org-001'` claim to all token payloads and added EDITOR_JWT generation. Regenerated tokens in `jwt-tokens.ts` with the updated script.

Updated README.md E2E section to document the test compose requirement.

Created `tests/api/rest/jwt-auth.spec.ts` — a dedicated JWT auth regression test that verifies all three test tokens are accepted (not 401) and token claims are correct.

### Secondary finding: readiness check must wait for frontend, not API Gateway

Initial attempt used `port: 8080` for the webServer check. This caused ECONNREFUSED because the API Gateway starts before the frontend (nginx proxy on port 3000). Since all E2E tests connect via `http://localhost:3000/api/v1` (through the frontend proxy), the readiness URL must wait for the frontend's `/health` endpoint. The `docker compose --wait` flag already handles container-level health checks.

## Prevention

- Document the JWT auth architecture in the developer guide: the resolution chain (JWT_DEV_PUBLIC_KEY_PEM → JWT_PUBLIC_KEY_PATH → KEYCLOAK_JWKS_URL) and which compose file to use for each environment
- Add a CI check that verifies `docker-compose.test.yml` is used for E2E test configs (not `docker-compose.yml`)
- When adding new Playwright configs, always review the `webServer.command` to ensure it matches the auth configuration
- **webServer readiness URL must match the actual test target** — if tests use `baseURL: 'http://localhost:3000'`, the webServer `url` must also wait for port 3000, not 8080
- Consider a smoke test that verifies test JWT tokens are accepted by the configured gateway before running the full suite
