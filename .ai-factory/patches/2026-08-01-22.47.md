## Problem

1. The last segment of the group URL (`slug`) was a read-only preview — users could
   not customize it (CreateGroupPage showed `vedo-core.local/<slug>` as static text).
2. For Cyrillic group names, the auto-generated slug was empty because the slugify
   regex `[^a-z0-9-]` stripped all Cyrillic characters — the URL field stayed blank.
3. The design system had no InputGroup (prefixed text input) molecule, and the pages
   hand-rolled the URL preview markup with a hardcoded `vedo-core.local/` prefix.
4. The project creation API client did not send `slug` even though the backend
   (`HandleCreateProject` → `CreateProjectRequest.Slug`) accepts it.
5. No unit tests covered URL generation (Latin + transliteration) for group/project.

## Root Cause

- Slug generation duplicated inline in both pages used a naive `toLowerCase() +
  strip-invalid` chain that removed non-ASCII characters entirely instead of
  transliterating them.
- The slug was rendered as text, not an `<input>`, so it was never editable.
- The domain prefix was hardcoded in markup instead of resolved from runtime
  configuration.
- `createProject` in `src/api/org.ts` accepted no `slug` parameter, so even an
  edited project slug would have been dropped before reaching the backend.

## Solution

- Added `src/utils/slug.ts` with `transliterate()` (Cyrillic→Latin map), `slugify()`,
  `normalizeDomain()`, `buildGroupUrl()`, `buildProjectUrl()` — shared by both pages
  so unit tests exercise the exact code the forms use.
- Added `src/config.ts` `getPublicDomain()` reading `window.__VEDO_CONFIG__.PUBLIC_DOMAIN`
  (injected at runtime by `docker-entrypoint.sh` from `VEDO_PUBLIC_DOMAIN`, default
  `vedo-core.local`) — no rebuild needed per environment.
- Added `src/components/ui-kit/InputGroup.vue`: PrimeVue InputGroup-style component
  (immutable prefix + editable input) with label, error, aria support.
- Both create pages now render an editable slug input with the domain prefix; the
  slug auto-fills from the name (transliterating Cyrillic) until the user edits it
  manually (`slugTouched` guard). Manual input is sanitized via `slugify()`.
- `createProject` now accepts and forwards `slug`.
- Added `Molecule/InputGroup` (id `jBW87`) to `design/ui-kit.lib.pen` (displayed in
  both dark and light Molecules galleries) and switched both page designs to use it
  via `B:jBW87` ref with descendants overrides for prefix/slug text.
- i18n keys `groups.slug_help`, `projects.slug_placeholder`, `projects.slug_help`
  added to en.json and ru.json.
- Logging: `[FIX] CreateGroupPage.slug_autofill` / `[FIX] CreateProjectPage.slug_autofill`
  with `transliterated` flag (true only when name contains Cyrillic).

## Prevention

- Keep slug/URL generation in shared pure functions (`src/utils/slug.ts`) instead of
  duplicating inline in pages — unit-testable and consistent.
- Any user-facing "URL" built from a name must transliterate non-Latin scripts, not
  silently drop them; add a test for a Cyrillic name whenever a slug is introduced.
- Runtime-configurable values (public domain) must come from `window.__VEDO_CONFIG__`
  via a reader module, never hardcoded in templates.
- When adding fields to a page, verify the API client forwards them (backend already
  supported `slug` for projects; the client was the gap).
