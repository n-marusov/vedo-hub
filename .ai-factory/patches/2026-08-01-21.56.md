# Dev frontend auth bypass broken — stale config.js.gz served by gzip_static + lazy session seeding

**Date:** 2026-08-01 21:56
**Files:**
- `tools/dockerfiles/Dockerfile.typescript`
- `apps/services/frontend/docker-entrypoint.sh`
- `apps/services/publish-browse-ui/docker-entrypoint.sh`
- `apps/services/frontend/src/auth/session.ts`
- `apps/services/frontend/src/main.ts`
**Severity:** high

## Problem

In the dev environment the frontend kept redirecting to
`/login?redirect=/dashboard/home` even after SKIP_AUTH=true was configured,
and org API calls (group creation) returned 401. The browser received
`window.__VEDO_CONFIG__ = { _placeholder: true }` instead of the generated
config (`SKIP_AUTH: "true"`, `DEV_JWT_TOKEN`). Not a browser cache issue —
reproduced in a fresh isolated browser context and with
`curl --compressed -H "Accept-Encoding: gzip"`.

## Root Cause

Two compounding root causes:

1. **Stale pre-compressed config.js.gz.** The builder stage pre-compresses
   all static assets with `gzip -9 -k`, INCLUDING `config.js` (which holds the
   committed `public/config.js` placeholder in `dist/`). The runtime entrypoint
   overwrote `config.js` but never `config.js.gz`. nginx has `gzip_static on`,
   so gzip-capable clients (every browser) received the stale placeholder
   `.gz` while non-gzip clients (host `curl` without `--compressed`) got the
   fresh file — masking the bug. The placeholder's comment even referenced a
   "dev-runtime-config plugin in vite.config.ts" that does not exist.

2. **Lazy session seeding.** After fixing (1), pages loaded (no redirect) but
   API calls returned 401. In SKIP_AUTH mode the router guard calls `next()`
   without `isAuthenticated()`/`getSession()`, so the dev-minted JWT only
   reached `localStorage.vedo-jwt-token` lazily when a component happened to
   call `getSession()`. Apollo/Axios interceptors read localStorage directly →
   empty/stale token → 401.

## Solution

- **Dockerfile.typescript:** excluded `config.js` from the gzip find
  (`! -name "config.js"`) so the stale `.gz` never exists.
- **frontend + publish-browse-ui entrypoints:** `rm -f "${CONFIG_FILE}.gz"`
  after writing config.js (defense in depth for existing images).
- **session.ts:** added eager `initSession()` that seeds the dev JWT into
  localStorage (idempotent; only writes when no session exists).
- **main.ts:** calls `initSession()` before `app.mount()`.

## Prevention

- **When a file is regenerated at runtime, exclude it from static build
  pre-compression** (gzip/brotli), or ensure the regeneration also removes the
  pre-compressed variant. `gzip_static` silently serves stale `.gz`.
- **Verify with a gzip-capable client**, not plain curl: add
  `curl --compressed -H "Accept-Encoding: gzip"` to checks of runtime-generated
  files.
- **SKIP_AUTH/router-bypass paths must seed auth state eagerly at startup** —
  never rely on a component incidentally calling `getSession()`. Any code path
  that reads localStorage directly (interceptors) needs the value populated
  before the first request.
