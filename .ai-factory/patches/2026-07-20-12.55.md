# Wired tests incorrectly included in GUI test suite

**Date:** 2026-07-20 12:55
**Files:** tests/e2e/playwright/playwright.gui.config.ts
**Severity:** low

## Problem

`pnpm exec playwright test --config=playwright.gui.config.ts` failed on
`groups-page-wired.spec.ts` — the test expected the real backend to return
groups but the test database had no seed data (0 groups). This stopped the
entire GUI test suite early (maxFailures=1), leaving 122 tests unexecuted.

## Root Cause

`playwright.gui.config.ts` used `testDir: './tests/gui'` with no
`testMatch` / `testIgnore` filter, so it picked up ALL `.spec.ts` files
in the directory — including `*-wired.*` tests designed for the M2.1
real-backend suite (`playwright.m2.1.real.config.ts`).

The wired tests import from `@playwright/test` directly (no GraphQL mock
fixtures), so they hit the real backend API. The test database has no seed
data for groups/members/projects, causing every wired test to fail with
"Expected: > 0, Received: 0".

The fixture-based tests (`groups-page.spec.ts` et al.) use
`../../graphql-fixtures` which intercepts GraphQL requests and returns
mock data — they passed successfully.

## Solution

Added `testIgnore: '**/*-wired.spec.ts'` to `playwright.gui.config.ts` so
the GUI test suite excludes wired tests. The wired tests remain scoped to
`playwright.m2.1.real.config.ts`, which has proper `testMatch` filters
for them.

## Prevention

- When adding new Playwright config files, always include `testMatch` or
  `testIgnore` to scope test discovery to the intended test set
- When adding "wired" (real backend) tests, place them in a separate config
  or add ignore rules to existing configs to prevent accidental inclusion
- Check that test files using `@playwright/test` directly (no mock fixtures)
  are not picked up by mock-based test configurations
