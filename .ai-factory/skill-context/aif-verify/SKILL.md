## Principle: Layered Verification, Not Replacement

Apply the base `$aif-verify` workflow first. Its changed-file checks remain useful
as a fast, focused signal.

Then run the additional VEDO Core full-service static-analysis gate below before
emitting the final `aif-gate-result`.

This resolves the IDE-vs-skill gap without contradicting the base skill:

1. **Focused pass:** base skill checks changed files to keep immediate output readable.
2. **Full-service pass:** this project addendum checks all files in affected service
   ecosystems so pre-existing IDE-visible errors cannot be hidden.

A verification result may be `pass` only when both passes succeed.

## Additional Gate: Full-Service Static Analysis

Run this gate whenever `$aif-verify` is used after implementation, before merge,
or when the user asks whether the codebase is clean.

### Scope Selection

Select ecosystems from changed files and dependency impact:

- If Go files, `.proto` files, or Go module files changed → check all Go modules.
- If Rust files or shared Rust code changed → check all Rust crates.
- If Python files or Python dependency files changed → check all Python services.
- If TypeScript/Vue files changed → check all frontend services.
- If shared contracts or generated code changed → check all consumers that compile
  against those contracts.

Do not limit this gate to changed files. Within a selected ecosystem, check the
entire service/module directories listed below.

## Go Full-Service Gate

Run from each Go module directory:

- `src/services/api-gateway`
- `src/services/auth-service`
- `src/services/commenting-service`
- `src/services/ticket-api`
- `src/services/ticket-notifier`
- `src/services/ticket-sync`
- `src/services/ticket-telemetry-listener`
- `src/services/support-service`
- `src/services/ai-orchestration-service`
- `src/services/shared/llm`
- `src/services/shared/proto`
- `src/cli`

Commands:

1. `go vet ./...`
2. `gofmt -l .`
3. `golangci-lint run ./...` when `.golangci.yml` exists
4. dependency drift check: run `go mod tidy`, then verify `go.mod`/`go.sum` did
   not change unexpectedly

If `golangci-lint` is unavailable, report `WARN [lint] golangci-lint not available — skipping`
but still run `go vet`, `gofmt`, and dependency drift checks.

## Rust Full-Service Gate

Run from each Rust crate/service directory:

- `src/services/ontology-service`
- `src/services/versioning-service`
- `src/services/publisher-service`
- `src/services/public-browse-api`

Also validate the shared Rust library under `src/services/shared/src/` via the
workspace/crate that owns it.

Commands:

1. `cargo check`
2. `cargo clippy --lib -- -D warnings`
3. `cargo fmt --check`

`cargo check` is intentionally separate from `cargo clippy`: it is the compilation
gate that catches namespacing/type-resolution errors such as missing or moved
`tonic` types.

## Python Full-Service Gate

Run on each Python service:

- `src/services/document-extractor`
- `src/services/metrics-service`
- `src/services/ticket-classifier`

Commands:

1. `ruff check .`
2. `basedpyright .`
3. compile all Python files with `python -m py_compile` or an equivalent recursive
   compile command

`basedpyright` is required because `ruff` does not cover the same class of issues
as IDE type analysis: import resolution, partially unknown types, missing generic
arguments, and implicit relative-import problems.

## TypeScript/Vue Full-Service Gate

Run on frontend services:

- `src/services/frontend`
- `src/services/publish-browse-ui`

Commands:

1. `npx biome check .`
2. `npx tsc --noEmit` when TypeScript config is present and supported by the service

Use non-mutating check commands during verification. Formatting/fix commands belong
in implementation or pre-commit remediation steps, not in `$aif-verify` reporting.

## Gate Result Rule

The final `$aif-verify` result is computed cumulatively:

- Base changed-file verification fails → final result is `fail`.
- Full-service static-analysis gate fails → final result is `fail`.
- Tool unavailable → final result may be `warn` only if all mandatory available
  checks pass and the missing tool is reported explicitly.
- No failures and no skipped mandatory tools → final result is `pass`.

Report failures with service, command, and file:line when available. Do not hide
warnings: IDE-visible warnings from the selected ecosystem must be represented in
`$aif-verify` output as warnings or failures according to tool severity.

### Integrity Checks

- New or modified `vdo:implements`, `vdo:validates`, `vdo:tests`, `vdo:documents`,
  `vdo:deploys`, `vdo:monitors` references → each IRI must resolve to an existing
  instance in the file.
- Renamed or relocated artifact → `vdo:filePath` value must be updated.
- Deleted artifact → its instance (and all incoming/outgoing references) must be
  removed from the file.
- Deleted directory → remove all instances with matching `vdo:filePath` prefix.

If a mismatch is detected, report it as a warning. Do not block the gate for this
check if the traceability update is explicitly deferred (e.g., the plan says
"traceability will be updated in a later task").

**Rule**: When `docker-compose.yml` or any Dockerfile was changed, run `docker compose config` to validate YAML and verify at least one targeted service image builds. Report misconfigured healthchecks, YAML parse errors, and missing service entries as WARN level.

### Security Test Evidence Verification

**Source**: `2026-07-14-20.30.md` — M1 Review (BOLA/BFLA fixtures returning ExpectedStatus without real HTTP)
**Rule**: When verifying security-related changes, check that test evidence includes real HTTP requests (not mock assertions returning `ExpectedStatus`). A test that returns the expected status without dispatching a real request is a false pass — flag it as WARNING in the verification report.

### Go Version Matrix Check

**Source**: `2026-07-19-18.30.md` (Go 1.24 vs golang:1.22 mismatch in Docker base image)
**Rule**: When verifying Docker builds, check that the `GO_BASE_IMAGE` version (default in `Dockerfile.go`) matches the highest `go X.YY` directive across all `go.mod` files in `src/services/`. Run `grep '^go ' src/services/*/go.mod | sort -V | tail -1` to find the maximum required version. If the base image is older, report as ERROR.

### nginx.conf vs Vite Proxy Rewrite Sync

**Source**: `2026-07-19-23.31.md` (nginx missing rewrite for health/ready endpoints)
**Rule**: When `vite.config.ts` or `nginx.conf` is modified, verify that path rewrites in both configs are consistent. Every `proxy.rewrite` rule in Vite's `vite.config.ts` must have a corresponding `rewrite` or `proxy_pass` rule in `src/services/frontend/nginx.conf`. Use exact-match (`=`) location blocks in nginx for rewritten paths that differ between external and internal handler paths.

### Go Integration Test Build Tag Compliance

**Source**: `2026-07-19-21.29.md` (commenting-service integration tests ran unconditionally)
**Rule**: When verifying Go services, check that `*_integration_test.go` files have `//go:build integration` constraints (both Go 1.17+ and legacy syntax). Report missing build tags as WARN level. These tests should not run as part of `go test ./...` unless `-tags=integration` is explicitly passed.
