### LLM Prompt Injection Defense Review Checklist

**Source**: `2026-07-18-18.23.md` — M2 AI Ontology Creation (all 17 critical issues)
**Rule**: When reviewing LLM-related code changes, check:

1. Are `ValidateLLMOutput`/`SanitizeLLMInput`/`SanitizeUserInput` (or equivalent) called in all response paths — not merely defined as dead code?
2. Is Unicode normalization (NFC) applied before pattern matching; are zero-width characters stripped?
3. Are `MaxTextLength`/`MaxFeedbackLength` limits enforced with proper error codes (e.g., `PAYLOAD-TOO-LARGE`)?
4. Are all user-supplied values interpolated into prompts sanitized before reaching the LLM?
5. Are nil provider guards in place before calling LLM provider methods?
6. Is the gRPC auth interceptor (`authUnaryClientInterceptor`) propagating JWT tokens for inter-service calls?
7. Are outbound HTTP calls using `http.NewRequestWithContext()` with `io.LimitReader` (10MB) on response body?

### Query + Error Handling Review Checklist

**Source**: `2026-07-14-20.30.md` — M1 Review (SQL injection, Cypher injection, SPARQL→Cypher injection, error swallowing)
**Rule**: When reviewing code that interacts with databases or external services, check:

1. Are all queries parameterized (no string interpolation of user input)?
2. Are transport errors propagated (no `unwrap_or(default)` or `Ok(())` on failure)?
3. Are client-supplied headers (`X-User-Id`, `X-Admin-Override`) verified server-side?
4. Do all Neo4j MATCH clauses on entities include `ontology_id` filter?
