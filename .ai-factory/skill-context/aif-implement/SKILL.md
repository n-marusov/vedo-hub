## Rules

### Build ≠ Type Check
**Source**: `2026-07-14-01.10.md`, `2026-07-14-10.31.md`
**Rule**: A successful build does NOT mean the code is type-clean. Each language has its own gate:
- **Vue/TypeScript**: `vite build` uses esbuild, which transpiles without type checking.
  Run `vue-tsc --noEmit` to catch `TS6133` (`noUnusedLocals`) before declaring a frontend
  task complete.
- **Rust**: `cargo build` compiles but does not catch type or lint issues. `cargo build` is a **build gate** and does not replace language-specific validation:
  - Use `cargo check` for type-checking;
  - Use `cargo clippy` for lint warnings (`dead_code`, unused variables, etc.);
  - Commands must run from the affected Rust crate or workspace directory (e.g., `cd src/services/ontology-service`).
  A successful `cargo build` alone is not sufficient to declare a task complete — always run `cargo check` (or `cargo clippy`) in addition.
- **Go**: `go build` compiles but `go vet` catches subtle errors. Because this is a multi-module monorepo without a root `go.mod`, run `go vet ./...` from the affected Go module directory (e.g., `cd src/services/api-gateway && go vet ./...`), not from the repository root.
  When running Go tests, also change to the correct module directory first:
  `cd src/services/ticket-api && go test ./...` or `cd src/cli && go test ./...`.

When the verification step says "Check code compiles/runs", always run the language-specific
type/lint gate in addition to the build command. Document which gate was run in the task output.

### Template Rewrite Audit
**Source**: `2026-07-14-10.31.md`
**Rule**: After rewriting any Vue template (e.g., mock data → Apollo real backend), audit all
imports and `<script setup>` bindings. Every import, destructured variable, and function must
have at least one reference in the new template. Use `vue-tsc --noEmit` as the gate —
it catches unused imports and variables that Vite build silently ignores.

### Destructure Only What You Use
**Source**: `2026-07-14-10.31.md`
**Rule**: In `useQuery`, `useRoute`, composables — extract only the fields that are actually
referenced in the template or script. `const { data, loading, error } = useQuery(...)` where
`loading` is unused triggers `TS6133` under `noUnusedLocals: true`. Omit unused destructured fields.

### Omit Unused v-for Index
**Source**: `2026-07-14-10.31.md`
**Rule**: In Vue templates, `v-for="(item, i) in items"` where `i` is never used should be
`v-for="item in items"`. Declaring unused `v-for` bindings triggers `TS6133` under `noUnusedLocals`.

### .env.example Sync
**Source**: `2026-07-14-01.10.md`
**Rule**: When introducing a new `os.Getenv` / `std::env::var` / env reference, update
`.env.example` in the same change. Treat undocumented env vars as a lint error in code review.
Verify the update by checking whether `.env.example` contains the new variable with a comment
explaining its purpose, default value, and format.

### GraphQL End-to-End
**Source**: `2026-07-14-01.10.md`
**Rule**: When adding a GraphQL field referenced by a frontend operation, build it end-to-end
in the same change: schema types + resolver + frontend query + Apollo operation. Run
`cargo test -p ontology-service --lib` from the Rust workspace directory (where the
`ontology-service` crate is available), plus `go test ./...` from the affected Go module
directory (e.g., `cd src/services/api-gateway && go test ./...` for gateway changes, or
`cd src/services/ticket-api && go test ./...` for ticket API changes) before declaring the
phase complete. Do NOT stop after the Rust side compiles without verifying the frontend
contract — a schema field that validates in Rust but has no corresponding Apollo operation
is dead code.

### Gin Router Trie Safety
**Source**: `2026-07-14-01.10.md`
**Rule**: When wiring a gin router, never register a static segment and a wildcard (`/*path`)
at the same trie level — this causes a registration-time panic. Prefer explicit route
registration plus `r.NoRoute(...)` to catch unknown paths. CI must include at least one
integration test that constructs the production router so registration panics surface before
merge, not at startup in production.
