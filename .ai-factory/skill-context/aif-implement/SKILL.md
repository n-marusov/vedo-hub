compiles/runs, update progress, and continue.

run is considered complete.

## Additional Checkpoint after Step 3.4 — Static Analysis Confirmation

After the base Step 3.4 verification (`Check code compiles/runs`) and before marking
a task as completed, run the relevant `$aif-verify` static-analysis gates for the
affected ecosystem.

This checkpoint is intentionally cumulative:

1. Keep focused validation around the files just changed.
2. Add full-service ecosystem validation so unchanged files with IDE-visible errors
   cannot remain hidden.

## Completion Rule

A task may be marked `[x]` only when:

1. The base task-specific verification passes.
2. The additional full-service static-analysis checkpoint for selected ecosystems
   has no errors.
3. Any skipped tools are explicitly reported as `WARN [lint] <tool> not available — skipping`.

If the static-analysis checkpoint finds errors:

- Keep the task as in-progress or blocked (`[~]` / `[!]`) according to severity.
- Report the failing command and representative file:line diagnostics.
- Do not claim implementation is complete.

This rule prevents the agent from declaring success while IDE-visible static-analysis
errors remain in the affected ecosystem.

## Traceability Integrity Checkpoint

When artifacts are created, modified, moved, or deleted during implementation, the
traceability matrix at `.ai-factory/traceability/traceability.ttl` must reflect
the change.

### Artifact Taxonomy (directory → vdo class)

| Directory / Pattern | vdo Class | When to add/update |
|---------------------|-----------|-------------------|
| `specs/requirements/REQ-BIZ-*` | `vdo:BusinessRequirement` | requirement file added, modified, or removed |
| `specs/requirements/REQ-FUN-*` | `vdo:FunctionalRequirement` | functional requirement file changed |
| `specs/requirements/REQ-NFR-*` | `vdo:NonFunctionalRequirement` | NFR file changed |
| `specs/requirements/REQ-CON-*` | `vdo:FunctionalRequirement` | constraint file changed |
| `specs/requirements/REQ-USR-*` | `vdo:FunctionalRequirement` | user-story requirement file changed |
| `specs/user-stories/US-*` | `vdo:UserStory` | user story file changed |
| `specs/use-cases/UC-*` | `vdo:UseCase` | use case file changed |
| `specs/adr/ADR-*` | `vdo:ArchitectureDecisionRecord` | ADR file added/removed/renamed |
| `specs/c4/*` | `vdo:DesignArtifact` | C4 diagram spec added or modified |
| `specs/ui/*` | `vdo:DesignArtifact` | UI specification file changed |
| `specs/vision.md`, `specs/context.md`, `specs/stack.md`, `specs/glossary.md` | `vdo:Specification` | top-level spec document changed |
| `src/services/<name>/` (whole directory) | `vdo:Service` | service directory added or removed |
| `src/services/<name>/**/*.{go,rs,py,ts,vue}` | `vdo:CodeArtifact` | individual source file added/removed (skip if `vdo:filePath` already covers the directory) |
| `src/cli/` | `vdo:CLICommand` | CLI command or subcommand added/removed |
| `src/services/shared/proto/*.proto` | `vdo:CodeArtifact` | protobuf contract file added/modified |
| `src/templates/` | `vdo:CodeArtifact` | service scaffold template changed |
| `tests/e2e/*`, `tests/cli/*` | `vdo:TestSuite` | end-to-end or CLI test file changed |
| `tests/security/*` | `vdo:TestContract` | security regression test changed |
| `tests/ticket-api/*` | `vdo:TestContract` | ticket API contract test changed |
| `src/**/*_test.{go,rs}`, `src/**/test_*.py`, `src/**/*_test.py`, `src/**/*.{spec,test}.ts` | `vdo:TestSuite` or `vdo:TestContract` | unit/contract test file added or removed |
| `src/docs/antora/**/*.adoc` | `vdo:Documentation` | Antora documentation page added/modified |
| `deploy/docker-compose.yml` | `vdo:DeploymentConfig` | service entry added/removed from compose |
| `deploy/helm/*` | `vdo:DeploymentConfig` | Helm chart values changed |
| `deploy/keycloak/*` | `vdo:DeploymentConfig` | Keycloak realm config changed |
| `deploy/ci/gitlab-ci.yml` | `vdo:CIPipeline` | CI job or stage added/removed |
| `deploy/observability/*` | `vdo:ObservabilityConfig` | observability config file changed |
| `design/*.pen` | `vdo:DesignArtifact` | UI/UX design file changed |
| `specs/adr/ADR-DES.SECURITY-*` | `vdo:SecurityBoundary` | security ADR changed |

This checkpoint is advisory (WARN level). A missing traceability entry does not
block task completion, but the agent must note it in the implementation summary
so a follow-up task can address it.

## Service Matrix Maintenance

When a new service is added to the monorepo (a new directory under `src/services/`),
the service lists in this file MUST be updated. Use the following discovery command:

```bash
find src/services -name go.mod -o -name Cargo.toml -o -name pyproject.toml -o -name package.json | sort
```

Cross-reference the results against the service lists above and add any missing
entries.
