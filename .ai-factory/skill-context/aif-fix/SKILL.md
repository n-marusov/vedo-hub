### ARIA Role Override on Native Elements

**Source**: `2026-07-20-14.30.md` (LoginPage button roles caused axe-core violation)
**Rule**: Do not set explicit ARIA roles on native HTML elements that already carry implicit roles (e.g., `<button>` already has `role="button"`, `<h1>` already has `role="heading"`). When `role="listitem"` is placed on a `<button>`, it overrides the implicit button role — `getByRole('button')` in Playwright will not find it. Removing the parent container's `role="list"` avoids the axe-core `aria-required-children` violation entirely.

## Generalized Principles (2026-07-23 → 2026-08-01)

### Contract-Aware Fixes — Derive Behavior from the Contract, Never Guess

**Source**: `2026-07-29-18.30.md` (handler status codes), `2026-07-25-01.26.md` (Keycloak lowercase roles), `2026-07-23-21.32.md` (BFLA method spectrum), `2026-07-31-12.29.md` (ADR forbidden-list, proto drift)
**Rule**: Before fixing a behavior mismatch, read the authoritative contract first: handler source (status codes, response shapes, route patterns), ADR boundaries (forbidden lists), proto/spec enum values, and IDP configuration (claim formats). Keycloak realm roles are lowercase (`owner`/`editor`) — normalize enumerated claims at lookup time (`strings.ToLower`) and test with the IDP's real format. Coarse gateway BFLA gates are defense-in-depth only: consider the full HTTP method spectrum (GET must not require Owner on management paths); fine-grained role checks live in the auth-service gRPC layer.

### Auth Boundary Integrity — Never Fake the Real Boundary

**Source**: `2026-08-01-20.53.md` (fake skip-auth-token → 401), `2026-08-01-21.56.md` (lazy session seeding → 401)
**Rule**: The API Gateway is the real auth boundary. Any dev/test "skip" mode must still present a token the gateway can verify (self-signed RS256 via `JWT_DEV_PUBLIC_KEY_PEM`, minted host-side — mirror the E2E mechanism). Router-bypass paths must seed auth state eagerly before the first request; never rely on a component incidentally calling `getSession()`. When a storage backend is written by only one code path, trace ALL consumers (interceptors, guards) for the missing write.

### Verify Under Real Consumer Conditions

**Source**: `2026-08-01-21.56.md` (gzip_static stale config.js.gz), `2026-07-26-22.17.md` (global-setup OUTPUT_PATH)
**Rule**: Reproduce the consumer's delivery path when verifying a fix: for runtime-regenerated files (e.g. `config.js`), verify with `curl --compressed -H "Accept-Encoding: gzip"` and remove/exclude the stale pre-compressed `.gz`; when code writes a file via a `__dirname`-derived path consumed by another module, trace the relative import from the consumer's location before assuming the path resolves.

### TypeScript Config — Never Hide Test Files

**Source**: `2026-07-27-23.55.md`, `2026-07-27-23.57.md` (23× Cannot find module '@/...')
**Rule**: When TypeScript reports "Cannot find module" for aliased imports (`@/...`) and the files exist, check `tsconfig.json` `exclude` first. `src/__tests__` / `**/__tests__` must never be excluded — test files need type-checking and alias resolution; excluding them hides real type errors and breaks module resolution.

### UI State Lifecycle Completeness

**Source**: `2026-07-27-15.30.md` (ValidationPage loading ref never set)
**Rule**: Any ref that gates rendering or behavior (`v-if="loading"`, `:disabled="loading"`) must be toggled in ALL code paths via `try/finally` (set `true` before the async call, reset in `finally`). An initialized-but-never-set ref is a bug.

### GraphQL Schema Reachability

**Source**: `2026-07-31-12.29.md` (Entity interface missing from schema)
**Rule**: GraphQL interfaces/types used only via implementors (no resolver returns them directly) must be registered explicitly (`register_output_type`) or they silently vanish from the schema.

**Rule**: Missing i18n keys render as the raw key string — a silent failure. Before referencing `t("key")`, verify the key exists in BOTH `ru.json` and `en.json`. UI text in shell/global components must route through `t()`, never hardcoded English.
