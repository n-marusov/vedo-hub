## Rules

### TQS Gate in Acceptance Criteria

**Source**: `$aif-test-quality` skill, `.ai-factory/rules/test-quality.md`
**Rule**: When a plan includes test files in any task's "Files to create" section, the plan's **acceptance criteria** MUST include a test quality gate:

```markdown
## Acceptance Criteria
- [ ] All tests pass: `go test ./...` / `cargo test` / `pytest` / `vitest`
- [ ] Test Quality Score (TQS) ≥ bronze (6.0)
- [ ] No B1–B7 anti-patterns (see .ai-factory/rules/test-quality.md)
- [ ] Traceability annotations present (`// Validates: REQ-...`)
```

**Why:** Without explicit acceptance criteria, tests can be written with anti-patterns and still pass verification. The TQS gate makes quality measurable.

### traceability.ttl Update in Implementation Steps

**Source**: `.ai-factory/RULES.md` Traceability §1, `$aif-test-quality` skill
**Rule**: When a plan creates or modifies test files, the plan MUST include an explicit step:

```markdown
### Step N: Update traceability.ttl
- Add `vdo:TestSuite` entry for each new test file
- Add `vdo:validates` triples for each `// Validates: REQ-...` annotation
- Remove stale triples for deleted/renamed test files
```

Place this step AFTER the test implementation step(s) but BEFORE the final commit.

**Why:** RULES.md mandates traceability.ttl stays in sync. Without an explicit plan step, it gets forgotten.

### BDD Naming Convention Reference

**Source**: `.ai-factory/rules/test-quality.md`
**Rule**: Plan task descriptions for test-writing subtasks MUST reference the BDD naming convention:

- Go/Rust/Python: `[Condition]_[Action]_[ExpectedResult]`
- TypeScript: `'should <expected> when <condition>'`

Include this as a note in the task description:
```markdown
> BDD naming: `[Condition]_[Action]_[ExpectedResult]`
> Anti-patterns: see `.ai-factory/rules/test-quality.md`
```

### No-Tests Services Policy

**Source**: `$aif-test-quality` skill
**Rule**: For services with 0 tests (e.g., `frontend`, `document-extractor`):
- TQS = N/A — do NOT BLOCK the plan for missing tests
- But: if the plan ADDS tests to a previously untested service, those tests MUST reach bronze (≥ 6.0)
- Add to plan: "New tests must meet minimum quality (TQS ≥ bronze)"
