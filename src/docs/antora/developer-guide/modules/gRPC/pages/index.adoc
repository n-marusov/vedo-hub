= gRPC Service Contracts
:description: gRPC usage, proto generation, and service contracts in VEDO Core.

== Overview

VEDO Core uses gRPC for inter-service communication. All service contracts are defined in Protocol Buffers (protobuf) and shared across language boundaries.

== Proto Definitions

All `.proto` files are located in `src/services/shared/proto/`:

....
proto/
├── buf.yaml                 # Buf configuration
├── common/
│   └── v1/
│       └── common.proto     # Shared types (ErrorDetail, etc.)
├── ontology/
│   └── v1/
│       └── ontology.proto   # Ontology CRUD operations
├── versioning/
│   └── v1/
│       └── versioning.proto # Versioning operations
├── auth/
│   └── v1/
│       └── auth.proto       # Authentication operations
├── commenting/
│   └── v1/
│       └── commenting.proto # Commenting operations
├── publisher/
│   └── v1/
│       └── publisher.proto  # Publishing operations
└── public_browse/
    └── v1/
        └── public_browse.proto  # Public read-only API
....

== Code Generation

=== Go

Go stubs are generated using `buf generate`:

....
make proto-generate
....

=== Rust

Rust stubs are generated at compile-time via `tonic_build` in each service's `build.rs`.

=== Python

Python stubs for the document-extractor service:

....
make proto-generate-python
....

== TLS Configuration

gRPC connections support TLS via the `GRPC_TLS_ENABLED` environment variable:

* **Default:** disabled (`GRPC_TLS_ENABLED=false`)
* **Client:** verifies server certificate via system CA pool
* **Server:** reads cert/key from `GRPC_TLS_CERT_FILE` and `GRPC_TLS_KEY_FILE`
* **CI:** use the `tls-certs` job to generate self-signed certificates
