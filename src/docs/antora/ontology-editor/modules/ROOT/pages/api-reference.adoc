= API Reference
:toc: left
:icons: font
:source-highlighter: rouge

The VEDO Core REST API provides programmatic access to all ontology operations,
query endpoints, and versioning functionality. The full OpenAPI 3.1 specification
is available at `GET /api/v1/openapi.json`.

== Base URL

All API endpoints are prefixed with `/api/v1`:

....
https://your-vedo-instance.com/api/v1
....

== Authentication

Most endpoints require authentication via JWT bearer token:

[source,http]
----
GET /api/v1/ontologies
Authorization: Bearer <your-jwt-token>
----

Public endpoints (health, public ontology views) do not require authentication.

=== Getting a Token

Obtain a JWT token through the login endpoint:

[source,http]
----
POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "your-username",
  "password": "your-password"
}
----

Response:
[source,json]
----
{
  "access_token": "eyJhbGciOiJSUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 3600
}
----

== Standard Response Format

=== Success
[source,json]
----
{
  "data": { ... },
  "meta": {
    "page": 0,
    "per_page": 20,
    "total": 42,
    "total_pages": 3
  }
}
----

=== Error
[source,json]
----
{
  "error": {
    "code": "ONT-CLASS-NOT-FOUND",
    "message": "Class not found: UnknownClass"
  }
}
----

Error codes are domain-prefixed:
* `ONT-*` — Ontology service errors
* `VER-*` — Versioning service errors
* `GATEWAY-*` — API Gateway errors
* `AUTH-*` — Authentication errors

== Endpoints

=== Ontology

==== List Ontologies
[source,http]
----
GET /api/v1/ontologies?page=0&per_page=20&q=text
----

==== Get Ontology
[source,http]
----
GET /api/v1/ontologies/{id}
----

=== Classes

Full CRUD for OWL classes. See xref:classes.adoc[Classes documentation] for details.

|===
| Method | Path | Description
| GET | `/ontologies/{id}/classes` | List classes (paginated, searchable)
| POST | `/ontologies/{id}/classes` | Create class
| GET | `/ontologies/{id}/classes/{classId}` | Get class details
| PUT | `/ontologies/{id}/classes/{classId}` | Update class
| DELETE | `/ontologies/{id}/classes/{classId}` | Delete class
|===

==== Create Class
[source,http]
----
POST /api/v1/ontologies/{id}/classes
Content-Type: application/json

{
  "id": "Person",
  "label": "Person",
  "comment": "A human being",
  "parents": ["owl:Thing"]
}
----

=== Properties

|===
| Method | Path | Description
| GET | `/ontologies/{id}/properties` | List properties (type filter)
| POST | `/ontologies/{id}/properties` | Create property
| GET | `/ontologies/{id}/properties/{propId}` | Get property details
| PUT | `/ontologies/{id}/properties/{propId}` | Update property
| DELETE | `/ontologies/{id}/properties/{propId}` | Delete property
|===

==== Create ObjectProperty
[source,http]
----
POST /api/v1/ontologies/{id}/properties
Content-Type: application/json

{
  "id": "hasEmployee",
  "label": "has employee",
  "property_type": "object",
  "domains": ["Organization"],
  "ranges": ["Person"],
  "characteristics": {
    "functional": false,
    "inverse_functional": false,
    "transitive": false,
    "symmetric": false
  }
}
----

==== Create DatatypeProperty
[source,http]
----
POST /api/v1/ontologies/{id}/properties
Content-Type: application/json

{
  "id": "age",
  "label": "age",
  "property_type": "datatype",
  "domains": ["Person"],
  "xsd_type": "integer"
}
----

=== Query Endpoints

==== SPARQL
[source,http]
----
POST /api/v1/sparql
Content-Type: application/json

{
  "query": "SELECT ?s ?p ?o WHERE { ?s ?p ?o } LIMIT 10"
}
----

Read-only only — mutation queries (INSERT/DELETE) are rejected.

==== CYPHER
[source,http]
----
POST /api/v1/cypher
Content-Type: application/json

{
  "query": "MATCH (n) RETURN n LIMIT 10"
}
----

Read-only only — mutation queries (CREATE/DELETE) are rejected.

== Rate Limiting

Query endpoints (SPARQL/CYPHER) have per-tier rate limits:

|===
| Tier | Limit
| Anonymous | 10 requests/minute
| Free | 100 requests/minute
| Pro | 500 requests/minute
| Enterprise | 1000 requests/minute
|===

When rate limit is exceeded, the API returns `429 Too Many Requests` with
a `Retry-After` header.
