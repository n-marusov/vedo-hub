= Versioning
:toc: left
:icons: font
:source-highlighter: rouge

VEDO Core includes a Git-like versioning engine that tracks all changes to
ontologies. Every modification is recorded as a delta, enabling full history,
branches, and rollback.

== Concepts

=== Commits
A commit captures the state of an ontology at a point in time. Each commit contains:
* A message describing the change
* The author (user who made the change)
* A delta — the difference from the previous state
* A timestamp

Deltas are stored in JSONB format in PostgreSQL:
[source,json]
----
{
  "added_triples": [
    {"s": "Person", "p": "rdfs:subClassOf", "o": "owl:Thing"}
  ],
  "removed_triples": [],
  "modified_triples": []
}
----

=== Branches
Branches allow parallel development:
* Each ontology has a default branch (`main`)
* Create branches for experimental changes
* Switch between branches to work on different features
* Merge branches when work is complete

=== Materialized State
The current state of each branch is materialized in Neo4j for fast queries.
When you switch branches, the versioning service replays deltas to compute
the new materialized state.

== Making Commits

. Make changes to the ontology (add classes, properties, individuals).
. Click the *Commit* button in the toolbar.
. Enter a descriptive commit message.
. Click *Commit*.

The commit is created and the workspace shows as clean.

== Viewing Commit History

. Navigate to the *Versioning* tab.
. Select *Commits* to see the history.
. Each commit shows: message, author, timestamp, branch.
. Click a commit to see its full details.

== Creating Branches

. In the *Versioning* tab, select *Branches*.
. Click *New Branch*.
. Enter a branch name (e.g., `feature/new-property`).
. Select the source branch.
. Click *Create*.

You are now on the new branch. Changes made here won't affect other branches.

== Switching Branches

. In the *Versioning* tab, select *Branches*.
. Find the branch you want to switch to.
. Click *Switch*.
. The workspace loads the materialized state of that branch.

== Merging Branches

. Switch to the target branch (e.g., `main`).
. Click *Merge*.
. Select the source branch to merge from.
. If there are conflicts:
   * Conflicts are resolved automatically with source preference
   * A merge commit is created with two parent commits
. The merged state is available immediately.

== Rolling Back

To revert to a previous state:

. View the commit history.
. Find the commit you want to roll back to.
. Click *Rollback*.
. Confirm the rollback.
. An inverse delta commit is created, restoring the state.

== Versioning Operations Summary

[cols="2,3,5"]
|===
| Operation | REST Endpoint | Description
| Create commit | `POST /api/v1/versioning/commits` | Create a new commit
| List commits | `GET /api/v1/versioning/commits` | Paginated commit history
| Get commit | `GET /api/v1/versioning/commits/{id}` | Commit details with delta preview
| Create branch | `POST /api/v1/versioning/branches` | Create a new branch
| List branches | `GET /api/v1/versioning/branches` | List all branches
| Delete branch | `DELETE /api/v1/versioning/branches/{id}` | Delete a branch
| Merge branches | `POST /api/v1/versioning/branches/{id}/merge` | Merge source into target
| Checkout | `POST /api/v1/versioning/checkout` | Switch to a branch/commit
|===
