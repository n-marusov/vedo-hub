= Security
:description: Keycloak realm configuration, BOLA/BFLA enforcement, and security gates.

== Keycloak Configuration

The Keycloak realm is defined in `deploy/keycloak/vedo-core-realm.json` and imported automatically on container startup.

[cols="1,2"]
|===
|Admin URL |`http://localhost:8180`
|Admin credentials |`admin` / `admin` (change in production)
|Realm name |`vedo-core`
|===

[CAUTION]
====
Rotate all default credentials before deploying to production. Use `vedo-cli` for secret rotation operations.
====

== BOLA / BFLA Enforcement

The API Gateway enforces two layers of authorization:

* *BOLA (Broken Object-Level Authorization)* — every request is checked to ensure the authenticated user has access to the specific resource (ontology, group, merge request) they are requesting.
* *BFLA (Broken Function-Level Authorization)* — every endpoint is checked to ensure the user's role permits the requested operation.

Negative authorization tests in `tests/security/` verify that unauthorized access is properly rejected.

== Security Gates in CI

|===
|Gate |Stage |Description

|SAST |Static analysis |Source code vulnerability scanning before deploy
|DAST |Dynamic analysis |Running application vulnerability scanning on staging
|Dependency scanning |Supply chain |Known CVEs in Go, Rust, Python, npm dependencies
|BOLA/BFLA tests |Test |Authorization tests run as part of `make test`
|===

== Identity Providers

Keycloak is configured with support for Russian OAuth providers and Google:

* ESIA / Gosuslagi
* Yandex
* VK
* Google

Provider configuration is stored in the realm JSON and managed through the Keycloak admin console.

== OWASP Top 10 Compliance

VEDO Core follows OWASP Top 10 mitigation practices:

[cols="1,3"]
|===
|Risk |Mitigation

|Injection |Parameterized queries (Neo4j Cypher, PostgreSQL), input validation at gateway
|Broken Authentication |Keycloak OIDC/OAuth2 with JWT validation
|Sensitive Data Exposure |TLS in production, secrets via environment variables
|XXE |No XML external entity processing
|Broken Access Control |BOLA/BFLA enforcement at API Gateway
|Security Misconfiguration |Docker multi-stage builds, minimal base images
|XSS |Vue 3 auto-escaping, CSP headers
|Insecure Deserialization |Type-safe parsers, no untrusted deserialization
|Known Vulnerabilities |Dependency scanning in CI
|Insufficient Logging |Structured JSON logs with trace_id on all services
|===
